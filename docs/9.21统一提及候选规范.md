# 统一提及候选规范（@ 人）

本规范约束 Eva 内所有「输入 `@` 选人」的候选范围、排序、外观与筛选交互。所有入口必须复用同一个 `MentionPicker` 组件与同一套身份外观、分类语义和筛选规则；候选数据按入口范围从公共提供者或会话成员取得，禁止各自维护第二套渲染、样式或分类。

## 1. 适用入口

- 团队 IM 输入框：群聊、子区、私聊。
- 个人「我的 AI」及相关子区输入区（沿用公共输入区组件）。
- 项目任务评论 / 描述输入框（`@` 触发）。
- 后续任何新增的 `@` 选人入口默认遵循本规范。

## 2. 唯一组件与公共候选提供者

- 渲染唯一组件：`MentionPicker`（`prototype/009-2-members-ui.js`）。所有入口复用该组件，不复制 DOM / CSS 或事件。
- 公共候选提供者：`window.EvaMentionCandidates`（`prototype/009-2-mention-candidates.js`），任务评论使用它按全局规则取数：

```js
window.EvaMentionCandidates.flat({ store, actorId, projectId, scopeId, agents, squads, query })
```

返回统一结构 `{ id, name, kind, tokenId, tokenType, appearance? }`，由组件决定分组、图标与写入的提及 token。

- IM 输入区按会话范围传入成员集合（见 §3.2），仍由同一个 `MentionPicker` 渲染，分类与外观规则一致。
- 匹配规则：名称经 `NFKC` + `toLocaleLowerCase()` 归一后做 `includes` 模糊匹配；空查询返回全部。
- 禁止在业务入口硬编码候选名单、按名称猜身份、或复制 DOM / CSS。

## 3. 候选范围与顺序

`EvaMentionCandidates.ORDER` 固定为：

| 顺序 | 分类 | kind | 数据来源 |
| --- | --- | --- | --- |
| 1 | 个人助理 | `assistant` | `EvaAITeam` 个人助理 |
| 2 | 联系人 | `human` | 项目 / 群成员中的真人 |
| 3 | AI 分身 | `clone` | 项目 / 群成员的分身，**本人分身排最前** |
| 4 | 数字员工 | `employee` | 已加入项目 / 群的数字员工（项目管家不进入提及体系） |
| 5 | 专家 | `agent` | 项目范围内的专家 |
| 6 | 专家团 | `squad` | 项目范围内的专家团 |

### 3.1 项目任务评论：全局规则（6 类全选）

项目任务评论按全局规则取数，**6 个分类全部可选**：个人助理、联系人、AI 分身、数字员工、专家、专家团。范围由当前项目（`projectId`）解析，顺序遵循上表。

### 3.2 IM：会话成员子集

IM 输入区候选是**当前会话成员**：联系人、AI 分身、数字员工；**个人助理、专家、专家团不属于会话成员，在 IM 中 @ 不出来**。本人分身置顶。

「我的 AI」AI 小队 / 自定义 AI 小队是例外入口：其候选是该 AI 小队的全部 AI 成员（云端分身、个人助理、数字员工），并按「云端分身 / 个人助理 / 数字员工」分组展示，与「我的 AI」中栏的身份分组一致。

这是数据范围差异，不是第二套名单或第二套样式：组件、行外观、分类语义、筛选与展开规则与任务评论完全一致。

顺序固定，不因来源、身份数量或输入内容改变。

### 3.3 不进入候选的身份

- **本人真人**：任何入口的 `@` 候选都不出现当前登录人的真人身份；本人 AI 分身仍保留并置顶。
- **项目管家**：`@` 提及体系任何地方都不出现项目管家（候选、广播文案、写入的提及 token 均不含）。
- 广播 `@所有人` 仍然包含本人，只是不提供手动 `@` 到本人真人的候选行。

## 4. 外观

- 每行 = 头像 + 名称 +（AI）标，统一走 `EvaAIIdentity.avatar` 与 `EvaAIIdentity.badge`，头像尺寸在选择器内为 32。
- AI 身份（个人助理、AI 分身、数字员工、专家）显示公共 AI 标；联系人不显示；专家团不显示 AI 标。
- 业务入口不得自行拼接头像、颜色或标签，不得新增 AI 标的尺寸 / 颜色变体。
- 分组视图使用分类名作为分组标题。

## 5. 顶部类型筛选（chips）

- 仅在**未开始检索**且当前出现 **≥2 个分类** 时显示；每组显示动态数量。
- 一旦在 `@` 后输入检索词，**隐藏全部分组与 chips**，切换为统一的相关度排序结果（见 §5.1）。
- 「全部」恒在最前；其余只列出当前仍有结果的分类，无结果的分类不出现。
- 数量随候选实时变化。
- 点击 chip 不抢输入焦点（`mousedown` 阻止默认），可继续打字。

### 5.1 检索态：单列相关度排序

- 触发条件：`@` 之后的检索词去空白后非空（有“开始检索”的输入）。
- 检索态**跨全部分类**统一取数，不再按已选分类过滤；结果以**单列**展示，不分组、不显示 chips。
- 匹配为**纯名称子串**（`NFKC` + `toLocaleLowerCase()` 后 `includes`），不做拼音 / 首字母匹配。
- 排序按相关度**降序**：名称精确 > 名称前缀 > 名称包含；同级依次按命中位置更靠前、名称更短、原候选顺序。
- 无结果时显示空提示；清空检索词后恢复分组视图与 chips。

## 6. 每组上限与展开

- 分组视图中每组默认最多显示 **5** 条，超出显示「展开其余 N 位 / 个」；展开后取消该组上限。
- 量词按分类：**人类用「位」**，个人助理 / 分身 / 数字员工 / 专家 / 专家团用「个」。
- 展开只作用于当前分组；切换分类或修改查询后恢复折叠。
- 「展开其余」为鼠标 / 触屏入口，**不进入键盘候选序列**，↑↓ / 回车不会落在它上面。
- 检索态（IM 与任务评论一致）不分组、不做上限，按 §5.1 相关度排序。

## 7. 键盘与关闭

- `↑` / `↓` 在候选间移动，`Enter` 选择当前项，`Esc` 或点击面板外关闭。
- **组词守卫**：输入法组词期间（拼音未上屏）视为「尚未输入」，提及菜单不刷新、不重排、不过滤，保持组词前状态；组词期间的 `Enter` / 方向键交给输入法，不被提及菜单拦截。文字上屏后才进入检索。IM 输入框已具备该守卫，任务评论需补齐。
- 候选选择后写入提及 token：IM 写入会话成员 uid；任务评论按 `tokenId` / `tokenType` 写回。

## 8. 弹层位置

- **IM**：面板固定在输入框上方（`bottom: calc(100% + 8px)`，宽 420，`max-width: calc(100% - 32px)`），沿用输入区浮层契约（`--eva-shadow-popover`）。
- **任务评论**：宿主 `position: fixed`，按光标 `clientRect` 定位，面板向上展开，不受编辑区裁剪。
- 弹层默认限制在系统标题栏下方的客户端内容区，不覆盖窗口外壳。

## 9. 广播项

广播行名称固定为「所有人」与「所有 AI 成员」；「所有 AI 成员」名称后紧跟公共 AI 标（`EvaAIIdentity.badge`），「所有人」不带 AI 标。是否显示、是否带副标题按会话上下文决定：

| 会话类型 | 「所有人」 | 「所有 AI 成员」 |
| --- | --- | --- |
| 项目群 / 子区 / 任务评论 | `所有人`　提及所有联系人 | `所有 AI 成员` [AI]　提及所有 AI 分身与数字员工 |
| 普通群 / 子区（无项目） | `所有人`　提及所有联系人 | `所有 AI 成员` [AI]　提及所有 AI 分身 |
| 我的 AI 小队 / 自定义 AI 小队 | 不显示（会话内只有本人一个真人） | `所有 AI 成员` [AI]（不带副标题） |
| AI 单聊 | 不显示 | 不显示 |

- 副标题统一用「提及」表述、数量词统一用「所有」并保持简短；群类（项目群 / 普通群 / 子区）保留副标题，AI 小队 / 自定义 AI 小队不带副标题。
- 某一类没有可选候选时不显示对应广播行（例如普通群内没有数字员工时，标题为「提及所有 AI 分身」）。
- 无输入且未选中分类时，面板顶部提供对应广播行（`broadcast`，默认开启）；写入的提及类型分别为 `all` / `ai`。

## 11. 变更要求

- 调整候选范围、顺序、分类名或外观时，必须同时核对 IM 与任务评论两个入口，不得只改一个。
- 新增 `@` 入口时复用 `EvaMentionCandidates` 与 `MentionPicker`，并按本规范运行对应浏览器回归。
