# 依据的采用边界

## 按问题分工，不按品牌一刀切

| 问题 | 处理方式 |
| --- | --- |
| 控件实现及原生交互能力 | 优先既有 Eva 公共封装；底层使用当前锁定版本 Semi，完整 Octo IM 能力保持原合同 |
| 组件何时使用及内部信息组织 | 查 Semi 对应设计指南；缺少覆盖时再查适用的 Ant/Arco 依据 |
| 已确认排版 | 保留公共主题合同中采用的 Arco 参数；不能用“Semi 优先”撤销用户已确认的规格 |
| 中文表达 | Ant 文案原则作为通用依据；Semi 对照用于识别补充内容和差异，冲突须记录，不能临时挑选有利条款 |
| 可访问名称与键盘 | 按实际交互语义查 W3C/WAI；不因组件名叫 Popover 就套用 tooltip 或模态焦点陷阱 |
| 身份、权限、保存时机、可恢复性 | 以当前 Eva 业务合同和用户明确决定为准，不由外部示例改变 |

## 记录结论时区分四类

- **官方明确规则**：给出来源与适用条件，保留建议/必须的原有强度。
- **官方实现参数**：给出对应组件的官方来源；实际数值在公共代码维护，不在多份文档复制。
- **Eva 已确认合同**：引用唯一维护文档及公共实现；只有相关范围适用。
- **基于依据的建议**：明确尚未确认，不提前写成全局强制规则。

## 现行边界

颜色、圆角、字体家族与暗色沿用 Eva 主题；个人 GDS 和团队 Octo 不互相覆盖。Modal 与填写型 Popover 可以采用不同已确认规格，不能因为名字都含“弹窗”而强制同一密度。

单字段不自动省略标签。W3C 允许上下文已明确用途时隐藏可见标签，但仍需可访问名称；具体界面还需检查标题是否持续可见、是否完整解释对象。关联父任务去掉重复标签目前属于建议，不是已验收决定。

原生控件与公共主题并不能自动规范任意 Card、段落或业务布局。发现新组合时先查已有能力和适用条件，修正公共责任边界，不在业务端叠加抵消样式。

外部指南发生变化时做差异核对，不自动覆盖 Eva 已确认行为。新增取舍写回相应合同并链接来源，本文不保存第二套业务规则。
