# 文案使用

通用参考为 [Ant Design 文案](https://ant.design/docs/spec/copywriting-cn/)，需要组件语境时对照 [Semi 文案](https://semi.design/zh-CN/experience/content-guidelines)。读相关章节的条件和例子，不把示例句子当成全局模板。以下是 Eva 中的应用入口，不另抄一份官方指南。

## 按内容找规则

| 内容 | Eva 采用方式与唯一维护位置 |
| --- | --- |
| 表单标题、标签、占位符、帮助和错误 | [表单统一规范](../表单统一规范.md)的“表单文案的信息分工”“校验提示文案” |
| 确认操作及后果 | [公共主题接入规范](../公共主题接入规范.md)的“焦点与文案依据”；业务提供真实对象、动作与后果 |
| 身份名称、项目与群术语 | [产品规则索引](../开发规范总览.md)中的身份及对应业务规范；不随修辞更改身份归属 |
| 聊天输入提示 | 根目录 AGENTS.md 的“IM 内核、输入提示与图标”；继续共用既有生成函数 |
| 选择提示、搜索范围及无结果 | 保留对应选择器或搜索业务含义，不把搜索误作必填表单 |

## 按一次操作检查

入口、标题、字段、帮助和按钮合起来表达一个任务。检查新增信息、术语一致性以及按钮是否对应实际结果，不能只逐句判断通顺。具体步骤见[完整任务评审](review.md)。

精简不等于删除必要信息。单字段是否省略可见标签取决于持续可见的上下文，控件仍须具有可访问名称；遵循 [W3C 表单标签](https://www.w3.org/WAI/tutorials/forms/labels/)，不只靠占位符。公共组件不按标题和标签的字符串相似程度自动隐藏字段。

简短提示的标点沿用已确认的表单规范；长说明保留必要标点，不用全局字符串替换处理所有文字。说明后果时区分移除、删除、退出、解散，不把不同业务动作统一成同一个模糊词。

## 文案不能虚构能力

是否需要二次确认、能否提供撤销，参考 [Ant 足不出户](https://ant.design/docs/spec/stay-cn/)并核对实际业务。只有真正实现恢复动作的操作才提供“撤销”；Toast 的按钮是可选能力，不是每条提示必备。

业务继续拥有权限、保存时机和撤销事务。公共组件提供呈现与交互支持，不自动把保存改成立即生效，也不自动承诺失败重试或恢复已删除内容。
