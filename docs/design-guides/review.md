# 完整任务的组合评审

本页是 Eva 的评审流程，不声称是某一家官方完整模板。依据包括 [Ant 文案](https://ant.design/docs/spec/copywriting-cn/)、[Semi Form](https://semi.design/design/zh-CN/input/form)和 [W3C 表单标签](https://www.w3.org/WAI/tutorials/forms/labels/)。它补足组件参数测试无法证明的整体体验。

## 以一次完整操作为单位

| 问题 | 需要看到的证据 |
| --- | --- |
| 用户要做什么、作用于谁 | 入口、标题、对象与结果含义一致，身份与权限来源明确 |
| 每段信息是否增加信息 | 标题、字段标签、占位符、帮助、按钮各有作用；必要限制在输入后仍可见 |
| 是否存在多余步骤 | 每次展开、确认、跳转都有业务理由；不为套组件新增中间层 |
| 何时生效、怎样放弃 | 实际选择/提交/取消行为与文案一致；不承诺未实现的撤销 |
| 失败后怎么办 | 字段错误对应字段；事务失败有可理解的原因或恢复动作；输入不会无故丢失 |
| 键盘和辅助技术能否完成 | 控件有可访问名称；焦点顺序、嵌套退出、关闭后的返回位置正确 |
| 组合后视觉是否稳定 | 长文案、错误、隐藏内容、窄窗口不造成重复留白、层级倒置或不可达按钮 |

## 自动检查与评审分工

自动化验证可访问名称存在、尺寸和几何距离、公共入口、校验、提交事务、键盘操作及状态隔离。测试预期来自确认合同，不能照抄当前实现来证明自己正确。

信息是否重复、术语是否准确、步骤是否过重需要结合完整画面和实际业务判断。AI 可以提出疑点及引用，但不按字符串相似度自动删除文案，也不把所有错误都升级为确认弹窗。

## 示例：关联父任务

“关联父任务”说明操作，“父任务”说明字段，两者各自合法但可能没有新增信息。可以提出省略可见字段标签的方案，同时保留可访问名称；不能据此推导所有单字段界面都要隐藏标签。选择后立即生效与点击保存是两种业务合同，精简文案不授权改变保存时机。

## 交付时记录

记录采用的公共入口、官方依据、保留的业务行为、仍需用户判断的取舍，以及正常/错误/键盘状态的实际验证结果。用户验收过的实例才标为已验收；源码存在、构建通过和截图好看都不能代替完整行为验收。
