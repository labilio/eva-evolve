# Eva GDS for AI 2.0

## 0. 规范角色

本文件是生成 Eva 桌面端界面的主设计契约。它同时回答三个问题：

1. 页面为什么看起来属于 Eva，而不是通用 AI 聊天工具；
2. 六种状态如何共享同一套骨架，同时只呈现当前阶段的信息；
3. 大模型如何把视觉事实转换成稳定、可验收的页面，而不是凭感觉近似。

规范关键词：

- **MUST**：不满足就不能称为 2.0 风格复现。
- **SHOULD**：除非有明确产品理由，否则应遵守。
- **MAY**：允许变化，但不得破坏更高优先级规则。
- `[O]`、`[D]`、`[R]` 分别表示观测、归纳和建议，含义见 `README.md`。

## 1. 视觉身份

### 1.1 一句话定义

Eva 是“安静、轻盈、可信的桌面智能工作台”：大面积白色、冷静的中性色、单一高纯度蓝色强调、轻玻璃质感，以及一个克制但有记忆点的挥手人物形象。[D]

### 1.2 五个不可替换的签名

1. **260 px 玻璃侧栏 + 940 px 白色工作区**。[O]
2. **主内容 776 px 居中列**，全局起点 `x = 342`。[O]
3. **#1563EB 单一品牌蓝**，只负责主行动、选中和品牌识别。[D]
4. **20 px 外壳圆角、16 px 浮层/输入圆角、12 px 胶囊圆角**的分级圆角系统。[D]
5. **右侧挥手 Eva + 淡蓝点阵光晕**组成首页情绪锚点。[O]

### 1.3 禁止混入

- MUST NOT 使用 1.0 的 1440 × 900 骨架、旧品牌名称“小智”、旧侧栏宽度或旧三栏分割。
- MUST NOT 用彩色渐变按钮、厚重投影、大面积品牌蓝背景替代当前的白色与细边框体系。
- MUST NOT 用 emoji、实心彩色图标或不同笔画体系替代线性图标。
- MUST NOT 把六个画板当成六套互不相关的页面；它们是同一任务生命周期的状态。

## 2. 令牌使用原则

### 2.1 来源优先级

冲突时按以下优先级处理：

1. 当前状态对应的 `assets/reference/*.png`；
2. 本文件的 MUST 规则；
3. `components.json` 的组件结构和变体；
4. `tokens.dtcg.json` 的语义令牌；
5. `tokens.json` 的已解析工程值；
6. 标为 `[R]` 的补全建议。

若基准图与数值相差不超过 1 px，优先保持整数像素和清晰边缘；不得累计误差到多个组件。[R]

### 2.2 只用语义，不直接散落原始值

- 页面代码 MUST 引用语义令牌，例如 `color.semantic.action.primary`，而不是复制 `#1563EB`。
- 原始色只允许出现在令牌文件和第三方素材中。
- 布局不得依赖“看起来差不多”的百分比。1200 × 800 基准态优先使用规范中的固定尺寸与约束。
- 设计令牌描述“是什么”；组件契约描述“值用在哪里、有哪些状态”。两者必须同时读取。

### 3.2 品牌蓝的配额

- 同一视觉区域内只允许一个明确的主蓝行动。[D]
- 品牌蓝 MAY 用于线性技能图标、选中边框和发送按钮；不得用来铺满普通卡片。
- 蓝色文字与图标应成组出现，不能同时再加蓝底，除非该控件是实心主按钮。
- 禁用发送按钮 MUST 使用 `rgba(30,30,30,.09)`，不能降低主蓝透明度冒充禁用态。[O]

### 3.3 透明与玻璃

- 侧栏前景是 `rgba(255,255,255,.80)`，背景模糊 200 px，边框 `#DBDBDB`。[O]
- 输入框、技能选择器和运营卡使用 20 px 背景模糊与轻投影。[O]
- 玻璃效果只用于浮在背景之上的层，不得对纯白主工作区整体加模糊。
- 侧栏底图应使用不含个人信息的冷白/浅蓝/浅紫弥散图。[R] 原 Figma 底图只在强模糊后可见，原始未模糊素材不得进入交付。

## 4. 字体与文字层级

### 4.1 字体家族

- 中文与界面正文 MUST 使用 `PingFang SC`；系统回退为 `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。[O]
- 首页人物气泡中的 `hi` 使用 `Praise` Regular 23，仅限装饰性品牌语气。[O]
- 不得在普通界面文字中使用 Praise，也不得用另一款展示字体替代 PingFang SC。

### 4.2 字阶

| 样式 | 字号/行高 | 字重 | 使用位置 |
| --- | --- | --- | --- |
| `typography.style.heroTitle` | 32/40 | 600 | “你好，我是Eva同学” [O] |
| `typography.style.header` | 16/24 | 500 | 应用名、任务标题 [O] |
| `typography.style.body` | 15/24 | 400 | 对话正文、输入正文 [O] |
| `typography.style.bodyMedium` | 15/24 | 500 | 技能标签、重点正文 [O] |
| `typography.style.label` | 14/22 | 400 | 导航、列表、辅助信息 [O] |
| `typography.style.labelMedium` | 14/22 | 500 | CTA、栏目标题、强调标签 [O] |
| `typography.style.chip` | 14/20 | 400 | 场景胶囊 [O] |
| `typography.style.caption` | 12/16 | 400 | 状态栏、文件元信息 [O] |
| `typography.style.toolbar` | 12/12 | 400 | 编辑器工具文字 [O] |
| `typography.style.mascot` | 23/normal | 400 | 人物气泡 [O] |

规则：

- 中文正文 SHOULD 保持 1.6 左右行高，信息密集的 14 px 标签保持 22 px 行高。[D]
- 首页标题只允许一行；任务标题超长时省略，不得挤压右侧操作。
- 列表描述和技能描述必须单行截断，不换成两行导致行高变化。
- 必要信息不得使用 14 px `#939393`；改用 `secondaryAccessible` 或 `secondary`。[R]

## 5. 间距、圆角、边框与投影

### 5.1 间距

基础网格为 4 px；常用阶梯为 `4, 6, 8, 10, 12, 14, 16, 20, 22, 24, 26, 32`。[D]

- 组件内部优先使用 8/12/16。
- 14 px 是桌面输入和底部停靠容器的重要安全边距。
- 不要为了“统一”把 Figma 中明确出现的 6、10、14 px 舍入为 8 或 16。

### 5.2 圆角层级

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `radius.control` | 8 px | 导航选中、CTA、技能行 |
| `radius.chip` | 12 px | 场景胶囊、缩略图、运营卡 |
| `radius.panel` | 16 px | 输入面板、技能选择器、画布 |
| `radius.window` | 20 px | 1200 × 800 应用外壳、输入外包层 |
| `radius.full` | 999 px | 圆形图标按钮、发送按钮 |

圆角表示层级，不是装饰：外层半径必须大于或等于内层半径。[D]

### 5.3 边框

- 标准边框 1 px；极轻的合成输入边缘可使用 0.5 px。[O]
- `#CCCCCC` 用于需要被看见的轮廓，`#DBDBDB` 用于结构分隔。
- 选中缩略图用 1 px 品牌蓝；不要同时增加粗投影。

### 5.4 投影

- 浮层主投影：`0 16px 48px -8px rgba(0,0,0,.07)`。[O]
- 浮层发丝边：`0 0 0 .5px rgba(20,20,20,.15)`。[O]
- 演示画布：`0 4px 80px 8px rgba(0,0,0,.04), 0 3px 6px rgba(0,0,0,.04)`。[O]
- 不得叠加默认浏览器阴影或高不透明黑影。

## 6. 图标系统

### 6.1 形态

- 使用 Lucide 风格的圆角线性图标：圆端点、圆连接、均匀笔画。[D]
- 导航图标 18 px；正文与功能图标 16 px；下拉箭头 12 px；工具栏图标 18–20 px。[O]
- 24 × 24 源图在 18 px 渲染时，等效源笔画约 1.5 px。[D]
- 常规颜色为 `text.primary` 或 `text.secondary`；技能类图标 MAY 使用品牌蓝。
- 关注、置顶等持续选中态及业务语义色遵循[公共主题接入规范的状态图标颜色规则](../../公共主题接入规范.md#状态图标的颜色)；不把普通实心图标统一改成品牌蓝。

### 6.2 语义映射

- 新建任务：`edit`
- 历史：`clock-2`
- 知识库：`book-open`
- 对比/工作流：`git-compare`
- 搜索：`search`
- 添加：`plus-circle`
- 文件：`folder-open`
- 更多：`more-horizontal`
- 下拉：`chevron-down`
- 反馈：`smile`

若实现环境没有同名图标，应选择形态与笔画一致的等价图标，并记录替换；不得用 emoji 或文字字符代替。[R]

## 7. 桌面骨架

### 7.1 基准画布

- 应用视口固定为 1200 × 800，外壳圆角 20 px，裁切溢出。[O]
- 常规状态：侧栏 `x=0, y=0, w=260, h=800`；工作区 `x=260, y=0, w=940, h=800`。[O]
- 主内容列：`x=342, w=776`，即在 940 px 工作区内左右各 82 px。[O]
- 不得把页面整体按比例缩放来适配其他尺寸。

```text
1200 × 800 Window
├── Sidebar 260 × 800
└── Workspace 940 × 800
    └── Main column 776 wide, centered at x=342
```

### 7.2 侧栏

- 背景层 `x=4, y=4, w=256, h=792, r=16`，必须裁切。[O]
- 玻璃前景同尺寸，白色 80%、模糊 200、边框 `#DBDBDB`。[O]
- macOS 控制点从 `x=22, y=20` 开始，直径 12，水平间距 8；色为红 `#FF5D56`、黄 `#FEB52E`、绿 `#34C03F`，带 15% 黑细边。[O]
- 品牌头部 `x≈16.5, y≈52.5, w=231, h=34`；头像 34，标题 16/24 Medium，右侧图标按钮 32。[O]
- 主导航从 `y≈102.5` 开始，内容左右内边距约 16；行高 38–39，圆角 8。[O]
- 选中“新建任务”为白色底 + `#DBDBDB` 边框；其右侧快捷按钮独立 39 × 39。[O]
- 账号行 `x≈16.5, y≈755.5, w=231, h=28`；账号头像属于用户内容，不是品牌资产。[O]

侧栏历史条目允许内容变化，但行高、缩进、图标尺度和省略行为 MUST 保持。

### 7.3 顶栏

生成中状态使用工作区顶栏：`x=260, y=0, w=940, h=52`，水平内边距 16、垂直内边距 14。[O]

- 左侧：16–18 px 类型图标 + 任务标题 16/24 Medium。
- 右侧：更多与侧栏控制。
- 标题过长先省略，图标按钮不得收缩。

- 有正文时发送按钮必须进入 enabled 变体；只有技能标签而没有有效正文时由产品逻辑判断，不由视觉自行推断。[R]

## 11. 生成中状态

### 11.1 对话区

- 顶栏下方对话区 `x=260, y=52, w=940`；内容列仍为 `x=342, w=776`。[O]
- 用户消息靠右显示，浅工作面胶囊中包含技能提及与正文。[O]
- 时间与系统状态使用 14/22 muted；助理正文使用 15/24 primary。[O]
- 工具事件由 16 px 线性图标 + 14/22 muted 单行组成。[O]
- 段落与事件以约 16 px 形成垂直节奏，不用聊天气泡堆叠所有助理内容。[D]

### 11.2 状态真实性

- generating 只渲染当前已发生的步骤和“正在运行…”状态。[O]
- MUST NOT 因 Figma 节点树中存在隐藏完成内容而提前显示结果卡、下载动作或完成文案。
- 工具状态应有 `queued / running / success / error`，但未在画板观察到的视觉差异必须按 `[R]` 实现并记录。

### 11.3 底部输入

- 输入面板 `x=346, y=668, w=768, h=118, r=16`，距离窗口底部 14 px。[O]
- 对话可滚动区域底部必须预留输入面板高度，最后一条消息不得被遮挡。[R]
- 此状态不显示首页的 166 px 外包层与快捷技能条。

## 13. 组件状态补全

以下状态未全部在六个画板中出现，但为可用产品所必需，均为 `[R]`：

- `hover`：只用 `surface.subtle` 或 6% 黑透明层，不改变尺寸。
- `pressed`：在 hover 基础上增加到 9% 黑透明层，不做位移跳动。
- `focus-visible`：2 px 品牌蓝外环，外偏移 2 px；只在键盘导航时显示。
- `disabled`：禁用交互并降低内容对比度；主按钮不得只靠颜色表达不可用。
- `loading`：保持组件原尺寸，局部替换为进度指示，避免布局抖动。
- `error`：错误颜色未在原稿中形成系统；实现前需新增令牌并经过产品确认，不得临时套用高饱和红。[R]

## 14. 可访问性与高保真模式

原稿中的 `#939393` 在白底上的对比度不足以承载多数 14 px 必要文本。为同时保留设计事实与生产质量，定义两种模式：

- **Fidelity 模式**：像素复刻、演示截图和视觉回归使用原始 `text.muted = #939393`。[O]
- **Production 模式**：占位、禁用和非必要元信息可保留 muted；必要的小字号说明改用 `secondaryAccessible = #6B7280` 或 `secondary = #4A4A4A`。[R]

生产界面 SHOULD 满足：

- 普通文本对比度至少 4.5:1，大号文本至少 3:1。
- 图标按钮具有可读的无障碍名称。
- 触控/点击目标 SHOULD 至少 32 × 32；22 px 运营卡关闭按钮应以透明热区扩展到至少 32 px，不改变视觉尺寸。[R]
- 键盘可到达所有按钮、技能行、标签和缩略图。
- 动效遵循 `prefers-reduced-motion`；当前六个画板未定义动效曲线。

## 15. 响应式边界

只有 1200 × 800 桌面画板得到验证。[O]

- 在 1200 × 800 必须逐像素遵循本规范。
- 大于基准尺寸时，保持侧栏宽、内容列宽和组件宽，增加工作区外侧留白；不要拉宽 776 px 主列。[R]
- 小于 1200 px 时，不得简单等比缩放字体和控件。应另立 compact 规范，决定侧栏折叠、编辑器最小宽和浮层重排。[R]
- 已完成状态的 390/810 分栏是任务上下文布局，不是一般响应式断点。

## 16. 大模型生成协议

### 16.1 输入要求

生成任务至少应提供：

- 目标状态：`home / input / skill-picker / operation / generating / completed`；
- 页面内容与数据；
- 使用 Fidelity 还是 Production 模式；
- 目标技术栈与视口；
- 是否允许替换用户内容素材。

信息不足时，模型只能替换内容，不得发明新的视觉系统。

### 16.2 执行顺序

1. **判状态**：只选择一个主状态，可叠加 operation 临时层。
2. **搭骨架**：先锁定 1200/800、260/940 或完成态 390/810。
3. **放语义区域**：侧栏、顶栏、主列、输入、对话、编辑器。
4. **装组件**：严格使用 `components.json` 的 anatomy、variant 和 state。
5. **套令牌**：颜色、字阶、圆角、投影不得写临时值。
6. **放内容**：内容溢出采用规范中的裁切、省略或滚动规则。
7. **核状态**：隐藏其他生命周期的内容；校验 enabled/disabled、selected、running。
8. **视觉回归**：与对应 `assets/reference` 在 1200 × 800 叠图比较。
9. **生产检查**：运行 `node validate.mjs`，再做键盘与对比度人工检查。

### 16.3 模型禁止行为

- 不得根据常见 ChatGPT 界面习惯添加头像气泡、渐变、快捷卡片或底部免责声明。
- 不得把编辑器完成态套进常规 260 px 侧栏外壳。
- 不得显示 Figma 中隐藏的节点或把它们推断成当前状态。
- 不得把运营图、用户头像、幻灯片内容当成不可替换的品牌元素。
- 不得用 CSS 默认控件、系统 emoji 或任意阴影近似。
