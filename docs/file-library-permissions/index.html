E 文件库权限设计 角色与动作矩阵

FILE SPACE PERMISSION

三个角色，一张权限矩阵

文件库不维护独立成员，项目角色自动映射为文件空间角色。项目成员最低即 Editor，不设置 Viewer 或单文件只读角色。

01

角色

O

Owner

个人空间本人，或项目负责人。唯一角色，负责文件空间最终治理。

M

Manager

项目管理员。可管理文件内容、普通成员、空间链接、设置、回收站和审计，但不能任免 Manager 或转移所有权。

E

Editor

普通项目成员。可查看、上传和整理项目文件，但不能治理成员、链接、设置、回收站或审计。

任务负责人不是文件 Owner

专家、专家团和数字员工不属于上述角色。执行任务时仅临时读取已选输入、写入当前任务产出；产出归项目文件空间，业务责任仍落到项目内人类。

动作 Review 结论

删除：当前文件库不存在在线文档和文件版本管理，不设计查看、上传或恢复历史版本。

回收站：文件夹及其中内容作为一个删除单元，回收站只展示被直接删除的文件夹；恢复和永久删除均作用于整个删除单元。原目录不可用时恢复到空间根目录，永久删除不得影响已经恢复的文件。

补充：增加空间信息、成员、链接、设置、所有权和审计动作，并保留当前空间内复制和查看回收站。

合并：发现空间、查看空间、浏览、搜索和元数据读取，统一为“浏览、搜索、查看详情”。

继承：文件库不建立独立成员体系，成员治理复用项目设置；项目空间 Owner 随项目负责人同步。

保留：将项目群文件保存到项目文件管理，项目群内所有成员均可执行。保存后生成项目副本，但不会额外开放来源群历史或其他附件。

新增：外部链接与外部文件夹入口共用文件的空间权限、目录、标签和回收站；不提供内容预览、下载、创建副本、目录同步或原平台权限管理。

不纳入：项目之间、个人与项目之间的复制或移动；查看自身权限、权限来源、Owner 同步等系统能力；任务输入、任务产出确认等任务模块动作；以及不改变共享权限的排序、筛选和收藏。

统一规则：文件与外部链接本身不设置独立 Owner；项目空间角色继承项目角色；内部链接、外部链接入口和快捷方式都不额外授权；上传者或 AI 生成者只用于来源和审计；项目成员退出后立即失去项目资源访问权。
