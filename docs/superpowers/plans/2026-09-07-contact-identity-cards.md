# 通讯录与统一身份卡实施计划

**目标**：沿用 Octo ProfileDetailShell 结构，让通讯录、消息及成员身份入口使用同一资料卡，按稳定 ID 联系正确对象。
**设计依据**：本任务用户已确认的方案；AGENTS.md、项目与群聊成员体系、我的 AI 子区会话方案。
**架构**：共享身份适配器负责数据与操作解析，React 组件拥有卡片与返回状态，路由负责导航；沿用公共头像、Semi Modal 与 Octo 资料卡结构。通讯录迁移到原生 React Route，移除对应 DOM 增强，保留布局与搜索。

## 约束
- 不加组织架构、备注、好友关系；不改个人 Eva 或三栏基准。
- 联系人与 AI 独立点击；所属人可在同一弹窗查看并返回。
- 联系人不允许给自己发消息；会话按稳定 ID 复用。
- 云端分身、数字员工按真实数据类型判断；不扩大项目和 AI 权限。
- 系统标题栏持续可见；查看资料不重建消息或输入区。
- 用户已于本任务明确授权“直接合进 main”；完成验证后按 CONTRIBUTING 发布并更新 release.json。
