# 群聊治理交互设计

2026-09-17 确认：项目负责人／管理员仅在已加入的项目群中自动获得群管理权限。继承权限从当前项目角色实时推导，不复制成群授权记录，不轮询或逐群同步；仅手动授权保存于群。撤销项目角色即失去继承权限，独立手动授权继续有效。继承不自动加群，不授予转让群主或解散群权限。

## 目标

让「群聊管理」中已经展示的群管理员、Bot 管理员、Bot 回复规则和 GROUP.md 都可实际操作，并在本地原型刷新后保留结果。

## 权限与身份

- 群主始终是群管理员。
- 项目负责人、项目管理员加入项目群后，自动成为该群的群管理员，并出现在管理员名单中。
- 群主可手动授予或撤销人类成员的群管理员身份。
- 自动继承和手动授予是两条独立来源：项目角色消失时，手动授予仍保留；撤销手动授予时，自动继承仍有效。
- 普通项目群与全员群使用相同规则；非项目群只有群主和手动授予的管理员。
- 群主可增删人类群管理员；任一有效群管理员可增删 Bot 管理员、修改群资料、编辑 GROUP.md 和群级 Bot 回复规则。
- Bot 管理员只从当前群内 AI 成员中选择，不改变项目角色或成员关系。

## 状态模型

每个父群维护独立 `groupGovernance` 记录：手动管理员 ID、Bot 管理员 ID、免 @ 开关和 GROUP.md。子区解析到父群并共享治理状态。项目全员群使用 `all:<projectId>` 作为治理键。

## 交互

- 管理员与 Bot 管理员均复用现有双栏成员选择器。
- 管理员列表展示所有有效来源；仅手动授予且不再由项目角色继承的人可由群主撤销。
- 免 @ 开关即时保存；默认开启，仍受 Bot 主人自身设置约束。
- GROUP.md 支持编辑、保存和取消；无管理权限时只读。
- 成员离群或群解散时同步清理失效的治理关系。
