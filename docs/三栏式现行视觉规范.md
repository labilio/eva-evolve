## 2026-09-15 导航选中表面以 EvaMate 0.3.0 为准（裁决两套规范冲突）

两套现行规范对选中态取值直接冲突：Eva GDS for AI 2.0 §7.2 要求白底 + `#DBDBDB` 中性描边；EvaMate Design System 0.3.0 要求 `color/surface/selected = blue/50 (#EBF3FF)`，强选中时再加 `border/selected = blue/600 (#1563EB)`。

用户 2026-09-15 明确裁决：**以 EvaMate 0.3.0 为准，采用浅蓝选中表面。** 据此：

- 浅色选中底色取 EvaMate 精确 token 值 `#EBF3FF`（原为 `#dce9ff`，与 EvaMate token 差 1–2 个通道，属「看起来差不多但不是同一个值」，一并校正）。
- 选中文字沿用 `action/primary` (`#1563EB`) 表达强选中。按 EvaMate `DESIGN.md` §71「避免多处并列强蓝」，**不再叠加** `border/selected` 蓝色描边。
- 该取值同时修正一处可访问性缺陷：`#dce9ff` 配 `#1563EB` 文字对比度为 4.27，未达 WCAG AA（15px 正文需 4.5）；`#EBF3FF` 为 4.68，达标。
- `@提及下拉选中项`（`--eva-list-option-selected`）与导航选中同属「选中表面」语义，共用同一取值，避免出现两个近似的浅蓝。IM 外发气泡不是选中表面，保持原值不变。

暗色下的选中表面**未**采用 EvaMate 的 `blue/700 (#0F50C7)`：该值需要配套的前景色取值，而 AGENTS.md 记录两套规范的明暗主题分工尚未逐条划定。暗色维持 `#1e3a63`，但修正其前景色缺陷：原配 `#1563EB` 文字对比度仅 2.18，严重不达标；按 GDS §3.4「链接/图标/焦点环提亮到 `#93B5FF`」把 `--eva-nav-accent` 在暗色下提亮，对比度升至 5.59 达标。

## 2026-09-15 导航 hover 改回覆盖层（覆盖同日早前的浅蓝 hover 决定）

用户明确授权：导航的 hover 与 pressed 恢复为公共覆盖层，不再使用不透明浅蓝表面。依据是两套现行设计规范在这一点上一致——Eva GDS for AI 2.0 §13 规定「hover 只用 `surface.subtle` 或 6% 黑透明层，pressed 增加到 9%，均不改变尺寸」；EvaMate Design System 0.3.0 `DESIGN.md` §71 规定「hover 与 pressed 是覆盖层，不是新的永久表面」。

## 2026-09-15 导航状态 token 解耦

`--eva-nav-selected` 原被一级导航选中态、IM 外发气泡、@提及下拉选中项三处共用，语义不同却共享同一名字。现拆为 `--eva-nav-selected`、`--eva-im-bubble-outgoing`、`--eva-list-option-selected` 三个独立 token，浅色与暗色各自显式定义。此后调整导航选中态不再波及 IM 气泡。修改任一 token 仍需按本仓库要求核对其全部消费入口。

`test:layout` 检查所有一级页面与导航的原生边框可见性、圆角外实际背景和布局交互；Edge 同视口检查上、下圆角，不以 CSS 数值代替视觉验收。替换实现时同步删除旧代码和旧说明。

## 2026-09-20 列表字阶与字色梯度收敛

三个列表（个人「Eva 同学」、「我的 Agent」、「我的消息-关注」）的所有层级统一到同一套字阶与字色，依据 GDS for AI 2.0 §4.2 与 EvaMate 0.3.0 §4.2 的交集。

### 字阶三档（层级靠字重与字色，不靠字号）

EvaMate §4.2 明确「不得用字号堆砌层级；优先通过内容顺序、间距和字重组织信息」。三档全部落在两套规范的合法集合内：

| 语义层级 | 字号/行高 | 字重 | 字色 |
| --- | --- | --- | --- |
| 分组/分区标题（分类头、组头、分区标签） | 12/16 | 400 | `secondaryAccessible`（浅 `#6B7280` / 暗 `#B0B4BD`） |
| 容器行（群、AI 小队、身份、文件夹） | 14/22 | 500 | `text-primary`（`#1E1E1E`） |
| 末级行（子区、会话） | 14/22 | 400 | `text-secondary`（`#4A4A4A`） |

- 分组标题字色取 `secondaryAccessible` 而非 `muted`：12px 结构标签是必要导航信息，`muted #939393` 白底对比度仅 2.85 不达标（GDS §14 Production 模式）。
- 末级行用 `secondary` 实色档（白底 CR 8.71），**不是**此前 0.6 透明合成灰（CR 4.0 不达标、发虚）。容器/末级/分组三层各占一个字色档，梯度互不挤压。
- **13px 不是列表档**：EvaMate 的 13/22 是 `Badge / Compact`，用途限定徽标与文件类型；列表行不得使用。
- **700 不是合法字重**：字重集合为 400/500/600，600 仅用于 Hero（GDS）与未读（见下）。

### 状态语义

- **未读**：字重升 600，仅用于**无计数徽标**的场景（父行红点形态）。有计数徽标的行（子区、最近列）不做任何字重字色特殊处理——未读状态完全由计数徽标承担，避免「待处理」与「正在看」共用同一信号。
- **选中**：不加字重、不改字色，信号只有蓝底 `--eva-conversation-row-selected`（EvaMate §71「selected 用于弱选中；强选中用表面语言」）。
- **hover**：三列表同源 `--eva-conversation-row-hover`（中性覆盖层，暗色自动翻转为白透明）。

### 行高

- 容器行与末级行统一 **32px**（min-height）；名称文字行高显式 **22px**（GDS「信息密集的 14px 标签保持 22px」）。
- 个人页原 36px 密度档并入 32px；**29.6 / 18.2 等倍率小数行高（1.4×14、1.4×13）一律改为显式整数**，避免半像素基线。

### 实现位置与验收

- 关注列：`prototype/039-team-message-project-recent.css`；我的 Agent：`prototype/046-ai-team.css`（token 段 `--eva-rail-name/label-size`、`--eva-rail-line-height`）；个人页：`prototype/043-final-layout-convergence.css`；最近列行高：`prototype/017-im-shell.css`。
- 验收：同视口对比三个列表的同语义层级，确认字号/字重/字色/行高逐项一致；分组标题与容器行、容器行与末级行之间的字色梯度可辨（ΔL* 明显）；暗色两态分别核验。修改任一档时需核对其全部入口，禁止为单列表另立字阶。
