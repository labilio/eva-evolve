# 我的消息：产品规则

版本：v0.3，2026-09-15。

## 阅读范围

本页定义“我的消息”的项目／大群／子区关系、关注与最近两种列表、群聊成员与治理规则。成员资格引用[我的项目](./我的项目.md)，身份外观引用[身份展示规范](../通用规范/联系人与AI身份展示规范.md)，附属面板引用[布局规范](../通用规范/布局规范.md)。

## 1. AI 发言触发

| 场景 | 普通分身／数字员工何时回应 |
| --- | --- |
| 普通群聊及子区、我的 AI 团队及其子区 | 被明确 @ 后回应，不因普通消息、进展更新或时间到达主动插话 |
| 与 AI 私聊、我的 AI 本人＋单一 AI 的两人会话 | 用户直接发送即构成请求，不要求额外 @ |
| @所有人 | 通知联系人，不批量唤醒分身 |

AI 不因自己的回复继续触发。演示预设也遵守同一规则，不能插入没有对应请求的普通 AI 总结。

项目管家是明确例外：可主动同步项目事项并 @所有人，包括欢迎、提醒和进展汇总；仍受项目及群的数据可见范围约束，不替联系人作出对外承诺。此例外不扩大到普通分身或数字员工。

## 2. 群与子区

- 项目是群聊的业务归属，不是一个会话。项目下有唯一全员群及可创建的普通大群；每个大群可以有子区，也可以没有子区。结构为“项目 → 大群 → 可选子区”，不能把项目、群和子区当成同一种对象。
- 本文“大群”和“父群”指承载子区的群聊层级，不表示全员群；全员群与普通群的成员管理方式不同。非项目群没有项目归属，不为展示分类而补造项目。
- 普通项目群、非项目群及全员群的成员资格引用[我的项目的成员规则](./我的项目.md)。
- 子区不是独立群，不设独立成员、加入或退出关系；访问权继承父群。
- 隐藏、置顶、归档不等于退出或改变访问权。子区参与人数不等于有权访问人数。
- **子区不提供“关注”入口。** “关注”只用于项目／大群的关注视图；不能把 Octo-Web 原版的子区 Follow 直接移植到 Eva，形成“关注里的关注”。子区只使用“置顶子区”（父群内排序）、“隐藏子区”（从日常列表收起）和“归档子区”三种个人整理状态。
- 私聊、非项目群、我的 AI 会话不提供会话内项目任务入口；项目群及子区仅在用户同时有群与项目权限时提供，任务按父群解析所属项目。

## 3. 退出、移除与解散

### 群聊拉人

- 新建项目群或非项目群使用创建形态，填写群聊名称，主按钮为“创建群聊”；已有群添加成员使用纯拉人形态，无名称字段，主按钮为“确认添加”。均默认空选。

- 新建项目群及向项目群添加成员，只选择当前项目内的合资格联系人与本人的已入项目分身；非项目群使用公司内已激活联系人与本人的可用分身。
- 新建群时本人自动成为群成员及群主，不重复作为联系人候选。添加已有群成员时排除已加入身份；分身只有主人已在群内才能加入。
- 全员群的添加转为项目成员添加；子区不提供独立拉人。搜索与批量提交引用[我的项目的拉人规则](./我的项目.md)，不额外发起审批或接受流程。
- 拉人形态与聊天信息面板分别遵循[布局规范](../通用规范/布局规范.md)，不能把添加成员做成另一套群成员权限体系。

### 退出与解散结果

- 普通成员退出父群时，其分身同步退出，并失去全部子区访问权；历史内容保留原作者。
- 群主可以直接退出。有其他有效联系人时按稳定成员顺序自动转让；没有时退出并解散父群及全部子区。AI 不能接任群主。
- 手动转让群主不自动退出。群主被强制移出时须指定接任者；没有其他联系人可接任的项目移除情形不能留下无群主群，应按既定解散边界处理。
- 主动解散普通群仅群主可执行，项目负责人或管理员不能据其项目身份代替群主解散。
- 加入项目即自动进入唯一全员群，无需再次加入或接受；本人加入不自动带入分身。全员群不能单独退出、踢人、转让或解散；在项目层处理成员关系，完整同步规则见[我的项目](./我的项目.md)。
- 清空记录只改变当前账号在当前会话的可见历史，不影响其他成员、父群或其他子区。
- 退出或解散后，旧草稿、未读、隐藏或置顶不能使无权会话重新出现。
- 默认与自定义 AI 团队的特殊规则引用[我的 AI](./我的AI.md)。

- 自动转让与退出、无人接任时的退出与解散分别作为整体完成，不能留下无群主或只移除一部分关联身份的状态。
- 主动解散经明确确认后使父群及全部子区对所有成员失效；取消确认不改变成员或内容。解散不把历史内容转给其他群或改写作者。
- 联系人私聊与 AI 单聊不提供退出群或解散群；子区不提供独立退出。重新加入不恢复原群主、分身关系或个人会话偏好。

## 4. 关注与最近

关注和最近是同一套团队会话的两种组织视图，不建立两份消息、草稿或成员关系；切换时沿用同一会话与输入能力。

| 规则 | 关注 | 最近 |
| --- | --- | --- |
| 组织方式 | 项目分类下展示大群，大群下展示子区；非项目会话按个人分类组织 | 会话按时间跨项目混排，子区可作为会话行出现，不照搬关注的分类树 |
| 项目范围 | 与项目页共用当前账号的项目置顶列表；展示置顶项目下当前可访问的全部大群，后续新建或新获得访问权的大群自动加入 | 不以项目置顶作为访问条件；项目取消置顶后，最近会话仍可访问 |
| 排序 | 分类及分类内的大群／私聊可保存个人排序；子区随父群移动，子区置顶只影响该父群内顺序 | 按时间混排，不套用关注的手动分类顺序，也不因子区置顶将它改成父群内排序 |
| 项目归属展示 | 已有项目分类上下文，群／子区行不重复显示项目归属 | 项目群在群名前展示项目名，项目子区展示“项目 / 父群”；消息摘要仍保留 |
| 私聊与非项目群 | 进入个人分类；未分配项进入初始名称为“其他会话”的默认分类 | 不增加项目归属行 |

- 取消项目置顶后，该项目分类退出关注；不退出项目或群，不删除会话，也不撤销访问权限。置顶同样不授予权限。
- 分类和分类内会话的个人排序按账号保存，新增项目／群追加到已保存顺序末尾。不得跨分类拖动项目群或子区来改变项目归属。
- 最近及跨项目搜索中的项目路径从会话的父群、项目关系和当前访问权限解析，不按群名猜测；长路径可截断，但须能查看完整内容。跨项目搜索采用与最近相同的归属展示。
- 从关注、最近或搜索进入同一个子区，仍是同一个父群下的子区，成员与项目权限不因入口改变。最近中的独立会话行不代表独立群或独立成员体系。
- 聊天顶部第一行保留大群／子区层级；项目会话的第二行仅显示项目图标与项目名，聊天信息中的“所属项目”可进入对应项目。项目身份配色引用[配色规范](../通用规范/配色规范.md)。
- 子区可在主会话区完整打开，也可使用附属子区侧栏；侧栏覆盖原聊天区域、不挤占聊天页，具体形态引用[布局规范](../通用规范/布局规范.md)。不能仅因最近将子区列为一行，就改变它的归属或另建聊天数据。

## 5. 个人分类

- 非项目会话可放入个人自定义分类；默认分类初始名称为“其他会话”，也可编辑名称及会话归属。未分配项回到默认分类。
- 分类名称必填、1–50 字符，同一账号不能重名；允许空分类，之后再添加会话。分类及会话分配按账号保存。
- 分类只用于个人整理，不创建项目或群，不改变群名、成员与访问权限。项目群及子区始终由项目归属决定，不能移入个人分类。

## 6. 消息页顶部与列表样式

### 右上角操作区

| 入口 | 含义与范围 | 打开方式 |
| --- | --- | --- |
| 搜索 | 当前会话的搜索入口，不扩大为全局搜索 | 沿用会话搜索能力，不显示快捷键提示 |
| 任务 | 当前所属项目的 Loop 任务；仅有项目及群访问权的项目群／子区提供 | 右侧任务面板 |
| 子区 | 大群会话的子区入口；子区完整会话不再提供创建下一级子区的入口 | 右侧子区面板 |
| 更多（三个点） | 当前群／子区的聊天信息与管理；私聊展示对象信息 | 右侧聊天信息面板 |

- 按搜索、任务、子区、更多的顺序排列适用入口。私聊不因共用标题栏而增加项目任务或普通群治理能力；不保留不支持功能的空占位。
- 功能按钮采用同一组中性线性图标、尺寸、点击热区和间距；默认无独立边框，不将任务、子区或更多做成主色实心按钮。图标含义引用[图标规范](../通用规范/图标使用规范.md)。
- 任务、子区、聊天信息面板均覆盖而不挤占聊天页；标题栏与关闭位置遵循[布局规范](../通用规范/布局规范.md)。打开信息面板保留消息滚动位置与输入草稿。
- 群聊信息保留群名、头像、公告、成员及适用的添加／移除／转让／退出／解散；私聊保留对象信息。免打扰、置顶、清空记录沿用各自会话范围。全员群与子区的限制优先于普通群操作清单。

### 关注：项目、大群、子区三级样式

| 层级 | 展示与对齐 |
| --- | --- |
| 项目分类 | 左侧折叠箭头＋灰色项目名称，右侧为项目色的项目跳转图标；名称不染成项目色，不增加标题背景 |
| 大群 | 圆形群头像＋名称，右侧保留 @我、未读数及展开箭头；默认群头像使用所属项目色，自定义头像优先 |
| 子区 | 用 CornerDownRight 层级箭头连接父群，后接子区名；这里使用层级图标，不重复摆放圆形父群头像；保留本子区的未读状态 |

- 项目标题 13px、700 字重，左内边距 14px，折叠箭头占 10px、与文字间隔 4px；标题文字起点对齐大群头像。
- 大群头像起点为 28px，头像槽 22px，头像与名称间距 8px；子区箭头起点对齐父群名称起点。拖拽手柄放在左侧预留槽，不挤动文字。以上为逻辑像素，不按放大的截图反推尺寸。
- 项目分类之间留白 8px，分类标题与首条群聊间距 4px；不增加分隔线或分类底色。列表随中栏宽度变化，不能固定为截图裁剪宽度。
- 大群及子区行使用 8px 圆角，悬停 #F5F6F7，选中及选中后悬停 #F0F1F2。项目分类标题不套用会话行底色。
- 普通未读数为中性浅灰数字徽标，@我用蓝色；未读名称与已读的次级文字形成强调差异，不将整行染为项目色。展开箭头保留固定右侧位置。
- 行背景的左右外留白一致；层级缩进在行内计算。滚动条不通过左侧补空槽实现对称。

### 最近：会话条目

- 左侧显示会话圆形头像。子区使用父大群头像，不以子区箭头替代主头像；子区名称前仍保留层级箭头。
- 项目会话右侧信息分三行：第一行项目归属（子区为“项目 / 父群”），第二行会话名称及右侧时间，第三行消息摘要。项目图标用项目色，路径、时间、摘要用次级文字色，名称保留主要文字层级。
- 私聊与非项目群省略项目归属行，不留空项目行、不伪造项目名称。最近条目不增加关注树的展开箭头。
- 路径、名称和摘要各自单行截断，保留头像、时间与未读提示的空间；不能让长名称把状态挤出可视区域。选中以整条会话背景表达。

### 聊天标题

- 子区标题左侧使用父大群圆形头像；第一行按“父群名称 › 当前子区名称”排列，父群使用次级文字、当前子区加重突出。第二行显示项目图标与项目名，不重复子区路径。
- 直接打开大群时展示大群名，不伪造子区层级；无项目会话不显示项目归属行。标题和归属各自截断，不挤占右侧操作区。
- 群名、子区名和项目名不加 AI 标；人员身份的 AI 标仍按身份规范处理。

## 7. 子区头像与个人整理

- 子区使用父大群的同一份头像。父群上传或更换头像后，子区在最近、搜索及聊天标题等需要圆形会话头像的位置同步更新；不保存另一份子区头像，不提供独立换头像入口。父群的自定义图片不染色；默认头像继续继承父群项目色。
- 关注树中的子区箭头表达层级，不能据此把最近或标题的父群头像改成箭头。AI 单聊的私聊外观继续引用[我的 AI](./我的AI.md)，不机械套用普通子区展示。
- 普通群与 AI 团队子区的置顶、隐藏按账号和子区保存，不改变成员、权限、消息或草稿。置顶只调整父群内顺序，不改变最近的时间排序。
- 隐藏使子区从日常中栏及活跃／已归档列表收起；父群子区面板的“已隐藏”中可恢复。隐藏不等于免打扰、取消置顶或归档，普通新消息不自动取消隐藏。
- 隐藏后可设置“被 @ 时自动取消隐藏”，默认关闭。开启时，只有新增消息明确提及本人才能取消隐藏；普通消息、@所有人、@自己的 AI 和读取历史不触发。恢复不自动切换会话，不改变置顶、免打扰或归档；再次隐藏沿用此前设置。
- 子区信息中，免打扰、置顶子区、隐藏子区按此顺序成组展示，免打扰保留父群继承说明；清空聊天记录只影响当前账号当前子区。归档／取消归档与清空分开，不提供“离开子区”或“删除子区”。其他已有管理菜单的删除能力不因此转移到信息面板。
