# 我的项目：产品规则

版本：v0.1，2026-09-15。成员模型同时供“我的消息”的项目群与非项目群引用。

## 1. 成员资格与添加

- 联系人候选为公司内部已登录并激活 Eva 的用户；仅存在于 SSO、未激活账号、外部用户或访客不进入候选。
- 联系人与其分身分开管理。联系人只能添加自己的分身；本人必须已在目标范围，分身才能加入或留在该范围。
- 他人添加本人时不自动带入分身；本人可以不带分身。每人最多一个分身，数量规则引用[我的 AI](./我的AI.md)，具体身份按[身份展示规范](../通用规范/联系人与AI身份展示规范.md)呈现。
- 联系人直接添加生效，无审批、接受、邀请信箱或待处理邀请流程。重复添加不产生重复关系；批量添加任一候选失败则整体失败。
- 个人助理不成为普通项目／群成员；“我的 AI”的个人两人会话及 AI 小队是单独范围。
- 数字员工“加入项目”与成员资格的关系尚待确认，不能从旧成员文档或现有代码推导完整授权，见[数字员工市场](./数字员工市场.md)。

| 范围 | 联系人候选 | 分身候选 |
| --- | --- | --- |
| 项目 | 公司内已激活、尚未加入的联系人 | 只由本人添加自己的分身 |
| 项目普通群 | 当前项目的联系人 | 本人已加入项目的分身，且本人先在群内 |
| 非项目群 | 公司内已激活的联系人 | 本人的分身，且本人先在群内 |
| 全员群 | 与项目同步，不单独维护 | 与项目同步 |
| 子区 | 继承父群 | 继承父群 |

### 拉人与单人选择

- “添加项目成员”使用纯拉人形态，仅提供尚未加入项目的合资格联系人，不提供 AI 候选或替别人带入分身；主人自行带入自己的分身属于另一个身份配置流程。
- 项目／群拉人分组使用“联系人 N”“我的 AI 分身 N”，不使用“同事”；不存在合资格候选的分组不显示。联系人的项目治理排序与第二行项目分工分别读取各自字段，不能混用。

- 项目负责人、管理员及普通成员均可直接添加合资格联系人。添加项目联系人时不替对方选择分身；本人加入后自行带入。
- 搜索只过滤当前范围内的合资格候选，不扩大权限。已经加入的身份不重复进入添加候选，重复请求不产生第二份成员关系。
- 添加时重新校验操作者、候选及分身归属；任一候选失效则整批失败，不留下部分成员。
- 当前项目的联系人候选按负责人、管理员、普通成员排序，同级保留稳定顺序。尚未加入项目的联系人没有当前项目治理角色，不预设角色用于排序。
- 转让负责人、选择任务负责人或接任者是单人选择，不套用批量拉人流程；资源加入与带入本人分身也不等同于批量拉人。
- 共同选择器形态引用[布局规范](../通用规范/布局规范.md)，联系人／AI 候选和已选引用[身份展示规范](../通用规范/联系人与AI身份展示规范.md)。

## 2. 治理与继承

- 项目负责人必须且仅有一位联系人；项目管理员可有多位。普通联系人可添加联系人、带入自己的分身和创建项目普通群。
- 分身不继承主人的治理权限，不能成为负责人、管理员或群主，也不能管理成员、项目或群设置。
- 项目创建时自动创建唯一全员群，项目创建者自动进入；此后联系人加入项目即自动进入全员群，无需再申请、接受邀请或手动加入全员群。
- 联系人加入项目不自动带入分身；主人另行将自己的分身加入项目后，该分身才同步进入全员群。成员集合始终与项目同步。
- 全员群不能单独退出、踢人、转让或解散，也不能另建第二个全员群。“添加成员”进入项目添加流程；退出或移除成员在项目层处理。联系人退出项目时，本人及其分身同步退出全员群。
- 全员群默认展示名称与所属项目同名并随项目改名更新，可在聊天信息中自定义；默认排在项目群列表首位，用户仍可在「消息 － 关注」中拖动调整顺序。
- 自动进入全员群不等于自动加入所有项目普通群；普通群仍独立维护成员资格。
- 项目负责人／管理员未加入普通群时不能查看该群消息或参与治理；加入后才具备相应管理权限。群解散仍限群主。
- 普通群成员可添加合资格联系人及自己的分身，但不能移除其他联系人或其他人的分身。
- 产品、前端、HR 等项目分工不等于负责人、管理员等治理身份，不因设置分工授予管理权限。

## 3. 退出与历史

- 负责人主动退出项目前必须转让负责人。普通群群主退出按[我的消息](./我的消息.md)处理。
- 联系人退出项目，本人及其分身退出项目、全员群和项目普通群，失去相关子区访问权。
- 联系人只退出普通群，不因此失去项目成员身份。单独移除分身不移除主人。
- 历史消息、文件和行为保留作者；成员关系失效后不能继续产生新的范围内行为。
- 重新加入是一段新成员关系：不自动恢复普通群、治理角色或此前分身关系。

## 3.1 项目归档与恢复

项目归档用于结束项目协作并保留公司资产。项目不提供解散操作；项目负责人通过项目设置中的“归档项目”入口归档，恢复使用同一入口卡片，按钮文案分别为“归档项目”和“恢复项目”。归档与恢复均需输入确认短语，输入框不设置占位文案。

- 只有项目负责人可以归档或恢复项目。项目管理员不能代替负责人执行。
- 归档后项目保留在原项目与会话入口中，允许打开查看；同时提供已归档项目的小入口，不新增独立项目页签。
- 归档不改变访问权限。归档前有权查看项目、群聊、子区、任务、文件、消息和评论的成员，归档后继续按原权限查看；原本无权查看者不会因归档获得权限。
- 归档后项目完全进入只读冻结状态：禁止新增、移除、退出成员，禁止转让负责人或修改管理员；禁止发消息、评论、上传文件、新建任务、修改任务、编辑项目资料及修改群聊设置。
- 项目全员群、项目普通群及其子区随项目归档，输入框禁用，历史消息和资料可查看。非项目群不受项目归档影响。
- 项目全员群、项目普通群及其子区随项目恢复；已单独归档的子区保持单独归档，不因项目恢复而自动恢复。
- 归档后允许在原有权限范围内搜索、预览、下载、复制和导出，不额外显示“已归档”搜索标记，不扩大权限。
- 归档后的项目可以由项目负责人恢复；恢复时恢复归档时的项目成员、分身、负责人和管理员快照，重新开放人员和内容修改。
- 归档不改变个人置顶、取消置顶和排序等账号级设置。
- 归档时正在运行的任务、自动化和 AI 执行全部中止；未完成任务保留归档时的实际状态，不自动完成或取消。恢复后不自动重启，也不补发归档期间提醒。
- 归档与恢复在项目消息中写入系统记录，记录操作者和时间，不额外发送成员通知。归档人、归档时间、恢复人和恢复时间同时显示在原归档入口卡片中。
- 恢复后项目回到可协作状态，但不自动重启任务、自动化或 AI；已单独归档的子区恢复项目后仍保持归档。
- 删除仅在项目已归档时提供，只有项目负责人可以执行。删除立即永久移除项目、任务、文件、群聊、子区、消息、评论及历史记录，不进入可恢复的回收站；删除前要求输入项目名称确认。
- 负责人离职或账号失效时，项目负责人权限自动交给其直属上级；直属上级默认存在，不建立无法确定时的异常分支。

## 4. 项目任务

- 任务是所属项目的 Loop 任务，不等同于个人待办、自动化计划或 AI 执行记录。任务看板与会话入口引用同一规则。
- 项目成员可以创建任务；执行负责人须为当前项目可用的联系人、分身、数字员工或项目管家。存在验收人时只能是当前项目联系人。
- 编号保留项目前缀并支持完整编号查找；创建不重写旧任务编号。
- 状态为待办、进行中、审核中、已完成、受阻、已取消；旧待规划归入待办，旧筛选也要兼容，不能丢任务。
- 创建任务、分派给 AI、修改任务状态均不自动启动 AI 执行，不凭任务状态虚构执行历史或成功结果。
- 父子任务属于同一项目，子任务独立设置状态、负责人、优先级和截止日期。父任务完成不自动完成子任务；有未完成子任务时须确认，批量完成则先处理未完成子任务。
- 禁止自己作为父任务、移动到自己的后代；有子任务时不能直接删除父任务，应先转移或删除子任务。
- 任务详情、评论、子任务和执行历史按任务与项目隔离；统计全部后代，不因展示折叠改变完成数。

### 任务视图边界

- 项目任务提供看板、列表、层级三种视图，不把旧的按负责人分组视图列为当前项目入口。
- 看板只按任务自身状态平铺独立卡片，不展示多级结构、父子嵌套、树线、缩进、展开控件或父子关系提示。具有父任务关系的任务仍按自身状态展示为普通卡片，不挂在父卡片下面。
- 列表按状态分组展示任务行，可附轻量父任务编号与直接子任务进度；不把列表关系提示复制到看板。
- 父子树形关系在独立“层级”视图与任务详情的子任务区查看。看板不展示层级，不表示删除任务数据中的父子关系，也不取消父任务完成、删除等已有约束。
