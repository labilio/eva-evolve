# 人员身份与 IM 统一

## 数据合同

通讯录是组织内全部已激活 Eva 人类账号的目录，不使用演示人员白名单。当前预置 42 位人类，包含原组织名单及历史消息中的康执玺、威少、昊总、陈博；不虚构后四人的部门或岗位。

- `009-2-data-supply.js` 的 `__EVA_PEOPLE` 是人类账号预置来源；兼容运行时中的 `ORG_PEOPLE` 在构建时由该来源投影，保留既有 AI 兼容记录。
- 运行时档案由 `EvaMembership` 持有。`people()` 和 `person()` 统一筛选有效内部人类账号；`personRecord()` 仅供按稳定 ID 读取已有档案（包括停用账号的历史头像），不授予成员资格。
- 通讯录、IM 搜索、成员候选和演示账号切换复用账号资格。项目和普通群继续按各自成员关系限制访问与候选，目录可见不代表已加入项目或群。
- `EvaAvatar.personUri(personId)` 统一选择人员自定义头像或稳定默认头像。`conversationUri(channel)` 对私聊读取明确的 `personId`，不把 `dm-` 会话 ID 当头像种子；最近、关注和标题共用此入口。
- 资料卡、成员列表、选择器及 Loop 人员头像调用同一人员头像 API。AI 头像及项目配色继续遵循各自现行合同。

## 旧数据升级

加载时按稳定 ID 增补缺失档案和缺失字段；已有姓名、头像、停用状态保留。不清空 localStorage，不恢复已退出的成员关系，不覆盖私聊消息、草稿或项目角色。账号字段为原型数据，不代表已经接入 SSO。

历史消息保留原作者和原内容，登记历史作者不自动将其加入项目或群。通讯录不增加成员管理入口。
