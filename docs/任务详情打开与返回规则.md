# 任务详情打开与返回规则

日期：2026-10-14。适用于 Eva 原型中的项目 Loop 任务详情。

本文是任务详情打开、尺寸、导航和返回行为的统一规则入口。用户已确认交互方向并授权核对后合并；本文区分已验证行为与仍需专项验收的边界。任务创建与字段规则仍见[会话内项目任务规范](会话内项目任务规范.md)。

## 1. 核心规则

**在哪里点击任务，就在哪里打开同一个任务抽屉；查看任务不自动带走用户。**

“在哪里”指保留当前页面、项目、会话和工作上下文，不是让各页面自行决定抽屉宽度或实现任务详情。

同项目与跨项目都遵循这条规则。任务详情只保留右侧抽屉、用户主动全屏两种展示状态，不另做消息版、个人版或跨项目版详情。

## 2. 来源上下文与任务归属

用户在“供应链运营协同”的聊天中打开“客户联合交付”的 CLIENT-103：

- 背景仍是供应链项目及原聊天，一级导航、项目选择和页签不被切换。
- 抽屉顶部显示真实归属“客户联合交付”，正文与属性显示 CLIENT-103。
- 两处项目名称不同是正确结果：背景说明用户从哪里来，抽屉说明任务属于哪里。
- 关闭后继续原聊天；点击抽屉顶部“客户联合交付”，才进入该项目任务页并定位任务。
- 不能为了让两处名称一致而改背景项目，也不能把任务误标为来源项目。

任务链接必须能定位真实项目和任务，优先使用稳定任务 ID；不能仅凭名称或跨项目可能重复的编号推断归属。

## 3. 入口与行为矩阵

| 入口 / 动作 | 行为 | 背景处理 |
| --- | --- | --- |
| 我的消息：关注、最近、项目群、子区中的任务链接或引用卡 | 原地打开共享抽屉 | 保留当前会话 |
| 我的 Agent：小队、子区或 AI 单聊中的任务引用 | 同上 | 保留 Agent 与会话上下文 |
| 个人 Eva 同学：消息中的结构化任务链接 | 同上 | 保留个人对话，不改成团队 IM |
| 项目群聊天中的同项目或跨项目任务 | 同上，不按是否跨项目分叉 | 保留来源项目和群聊 |
| 聊天任务列表点击任务 | 打开共享抽屉 | 保留原聊天与任务列表上下文 |
| 创建成功通知中的“查看任务” | 打开共享抽屉 | 不强制进入任务项目 |
| 项目内看板、列表、分组、层级视图点击任务 | 继续在原项目打开详情，复用公共实现 | 保留原视图和筛选 |
| 自动化或执行记录中的有效关联任务 | 打开共享抽屉 | 保留原记录页面；不触发执行 |
| 详情描述、评论中的任务引用 | 在同一个抽屉内切换，可返回前一任务 | 不切换背景项目 |
| 详情中的父任务、子任务和任务层级路径 | 原位替换当前详情 | 保留展示状态，不叠加第二个抽屉 |
| 抽屉内点击所属项目名称 | 主动进入所属项目任务页并定位任务 | 允许切换项目，这是明确导航 |
| 从应用外直接访问分享 URL、新标签页打开任务链接 | 进入目标项目任务页并打开详情 | 没有可保留的应用内来源上下文 |
| 刷新页面 | 按当前 URL 恢复页面 | 临时原地抽屉不写入来源 URL，不承诺刷新恢复 |
| 不存在可识别任务引用的普通文字、普通链接 | 沿用原能力 | 不把提到任务的文字自动变成任务入口 |

“能查看任务链接”不等于“拥有会话任务创建入口”。个人 Eva、私聊、非项目群等不因本次改动增加项目任务创建入口，也不因打开任务获得项目或群成员权限。未来新增搜索结果、通知等任务入口，必须按本表接入公共能力；本表不表示这些尚未新增的产品入口已经存在。

## 4. 尺寸与全屏

- 所有入口以同一个客户端内容区为尺寸基准；该区域位于系统标题栏下方。不能按聊天区、个人页面或项目内部容器分别计算。
- 同一窗口大小、缩放和应用外壳状态下，各入口默认抽屉宽度、右边界和顶部边界一致。
- 默认宽度沿用本次确认的较宽方案，给正文与右侧属性保留空间。具体尺寸只在公共样式维护，不在入口重复配置。
- 小窗口统一适配。空间不足时铺满公共内容区，不能出现某入口已铺满、另一入口仍使用窄抽屉的差异。
- 主动全屏只扩大任务详情，不改变页面路由、背景项目或任务归属；收起恢复默认抽屉。
- 默认、全屏和窄窗口状态都保留系统标题栏，不复制标题栏。
- 同一条任务查看链路中切换任务，保持当前全屏状态；关闭整个详情后重新打开，恢复默认状态。

## 5. 返回、关闭与来源状态

| 操作 | 结果 |
| --- | --- |
| 任务 A 的正文引用打开 B，再返回 | 回到 A；引用链中的原详情实例保留，维持其评论草稿与滚动位置 |
| 重复打开当前任务 | 复用当前详情，不重复叠层 |
| 引用链返回已打开的任务 | 回到已有层级，不无限堆叠同一任务 |
| 父子层级切换 | 替换当前详情，不保证像引用链一样保留被替换任务的未提交草稿 |
| 点击关闭按钮 | 结束整条任务查看链，露出来源页面；不是只退一层 |
| 点击抽屉外露出的来源内容 | 关闭详情；来源区仍可正常交互，会话切换不能被透明遮罩拦住 |
| 离开来源路由、切换会话或操作账号 | 结束旧详情，防止旧任务残留到新上下文 |
| 失去目标任务项目的访问权限 | 关闭受影响的详情，不继续沿用旧授权 |

来源会话的输入草稿、原列表筛选和滚动位置不因查看任务而重置；若用户主动切换来源，会按新来源自身规则加载内容。关闭时在原触发元素仍存在的情况下恢复焦点。

**保存边界：** 已保存修改仍有效；关闭不是撤销。未提交的任务评论或编辑不承诺在关闭、层级替换、离开或刷新后保留，也没有因此新增统一“放弃修改”确认。来源聊天草稿与任务编辑草稿是两类不同状态。

浏览器后退/前进遵循路由历史，不作为任务引用链的返回键。当前没有新增全局 Esc 关闭任务机制；附件预览、下拉菜单等内部浮层先遵循自己的关闭规则，不能按一次 Esc 把内外层一起关闭。

## 6. 权限、归档与数据隔离

- 打开前检查目标项目存在、当前账号可访问且任务真实存在。访问失败留在来源，给出对应提示；不能跳到别的项目或用相似任务替代。
- 在 A 的详情内点击无权限或失效的引用 B，保留 A 并提示失败；点击抽屉外的来源内容仍先遵循关闭规则。
- 抽屉内的读取、修改、评论、附件、标签、人员候选、父子关系及新建子任务均按**目标任务所属项目**处理。
- 不为预览修改背景页面的当前项目；不能把 B 的评论、标签或子任务写进背景 A 项目。
- 归档只读由目标任务项目决定：来源项目归档不自动把其他可编辑任务变为只读；目标归档时不能因来源可编辑而开放写入。
- 查看、指派、修改状态与打开关联执行记录，都不等于授权启动 AI 或自动化执行。
- 本文不改变原型的业务数据存储、服务端接入或跨设备同步范围。

## 7. 统一实现与防回退约束

| 职责 | 唯一实现位置 |
| --- | --- |
| 任务链接解析、权限校验、导航栈与公共详情宿主 | `prototype/009-6-patch-general.js`：`evaTaskLinkOpen`、`evaTaskNavigation`、`EvaTaskDetailHost` |
| 任务内容 | 现有 `IssueDetailPage`，禁止复制入口专属内容组件 |
| 宿主尺寸基准 | 唯一 `.eva-task-outlet`，禁止按来源入口挑选 `.ch-main` 或 `.collab-body` |
| 默认宽度、全屏外观 | `prototype/060-task-drawer.css` |
| 窄窗口状态与全屏状态 | 公共 React 宿主持有；不能用各页面监听器或全局 class 再维护一份 |
| 个人 Eva 的链接适配 | 路由宿主注入窄服务，个人消息调用公共打开入口，不复制任务 UI |
| 演示引用 | `prototype/009-3-data-im.js`，引用现有供应链任务，不复制任务对象 |

本次尺寸问题的原因是“详情组件统一了，尺寸参考容器没有统一”：70% 分别取自聊天区和整个页面区，且窄窗口阈值按入口分叉。修复是统一宿主和状态规则，不是分别调整两个页面的百分比。

`npm run test:task-navigation` 已接入 GitHub 质量检查，覆盖共享尺寸与主要任务导航流程。

新增入口必须同时证明内容、数据归属、导航和尺寸均复用公共实现。只证明调用同一个详情组件，不足以证明体验统一。

还需保留在后续验收清单中的边界：

1. **任务打开期间被删除、项目被删除或成员权限实时撤回**：静态失效链接与账号切换已有覆盖；这些实时变化的完整交互尚未逐项实测。
2. **完整键盘路径**：Tab/Shift+Tab、返回焦点、读屏、内部浮层与 Esc 的组合需要专项检查；当前未提供全局 Esc 关闭任务。
3. **浏览器后退/前进、刷新、新标签页及不同缩放**：规则已明确；本轮新增几何测试只覆盖固定缩放下三种窗口宽度，不代表所有组合已验证。
4. **未提交任务编辑的丢失保护**：当前没有统一新增保护；若要关闭确认或自动保留，须单独确定范围，不能混同于来源聊天草稿保留。
5. **任意粘贴文字的链接识别**：个人 Eva 本次接入的是结构化任务链接示例，并非新增完整 Markdown/任意文本任务识别能力。
6. **显示状态**：最新尺寸修改未补做全部暗色、极端长标题和极窄窗口视觉验收。

## 9. 人工验收路径

在同一个本地测试版、同样窗口与缩放下，分别从个人 Eva、我的 Agent、我的消息、项目任务打开 SC-103，比较默认与全屏尺寸。再从供应链聊天打开 CLIENT-103，检查背景仍是供应链、抽屉归属是客户联合交付；编辑或评论落在客户任务，关闭回到供应链聊天。

继续检查引用返回、关闭、草稿、来源切换、点击目标项目路径、无权限任务和归档任务。构建、发布和合并纪律引用 [CONTRIBUTING.md](../CONTRIBUTING.md)，本规则不另建发布流程。
