# 会话内项目任务规范

本规范适用于团队 IM 中的任务入口、后续消息转任务入口及其创建流程。依据本轮已确认的产品定义：**这里的任务只指所属项目的 Loop 任务**。它不是个人待办、自动化任务，也不是某次 AI session 的执行记录。

## 1. 入口与适用范围

| 会话类型 | 项目任务入口 | 任务归属 |
| --- | --- | --- |
| 项目全员群 | 有权限时显示 | 当前项目 |
| 项目内普通群 | 有权限时显示 | 群所属项目 |
| 项目群的子区 | 有权限时显示 | 子区所在群的项目 |
| 非项目群及其子区 | 不显示 | 无 |
| 人与人私聊 | 不显示 | 无，即使双方同属项目 |
| 人与分身、数字员工的私聊 | 不显示 | 无，即使该 AI 加入了项目 |
| 我的 AI 的 OpenClaw session | 不显示 | 无 |
| 个人 Eva 会话 | 不显示此入口 | 不适用 |

不得根据名称、聊天内容提到的项目、上一次打开的项目或 AI 的归属猜测任务项目。子区先解析父群，再通过成员体系的稳定 ID 获取项目。当前供应链演示关联：协作项目 `prod`，任务看板项目 `p-supply`；二者是适配关系，不得复制项目。

## 2. 当前交互与后续边界

当前实现：会话右上角“创建任务” → 在当前会话上打开统一 Loop 创建弹窗 → 确认提交 → 关闭弹窗并显示完整任务编号。不得跳转项目页替代创建入口。

所属项目由当前群/子区解析并传入表单，不依赖上一次打开的项目。提交时再次校验群及项目权限。创建后保留当前会话；任务进入所属项目看板。当前没有自动发送聊天任务卡片，不能把提示成功说成已发送任务卡片。

后续若加入“将消息转为任务”，必须继续复用同一创建组件和数据入口；消息只能预填上下文，必须让用户检查并提交。不能把 AI 的建议、普通消息发送或打开任务页视作创建授权。

## 3. 权限与数据边界

- 展示与点击时均检查：当前人类账号能够访问父群和所属项目。无权限时不显示入口；权限发生变化后不得继续进入或提交。
- 项目成员可以创建任务，不把创建权限擅自收紧为管理员专属。UI 操作身份来自当前账号，不把私聊对象当作创建者。
- 创建时重新检查项目存在及访问权限。当前项目固定，不在来自会话的创建流程中切换其他项目。
- 执行负责人只能来自当前项目可用的人类、分身、数字员工或项目专员；身份名称与类型从稳定 ID 对应的业务数据派生，不能接受表单伪造值。
- 验收人只能是当前项目的人类成员。父任务必须属于同一项目；任务详情、评论、子任务和执行历史必须按任务及项目隔离。
- 数字员工能参与项目任务不等于能被拉进群；不能借创建任务绕过成员或身份规则。

## 4. 创建表单

| 字段 | 规则 |
| --- | --- |
| 所属项目 | 顶部路径固定显示当前外层项目，不提供旧 Loop 项目选择器 |
| 标题 | 必填，去除首尾空白后不可为空 |
| 描述 | 可选，支持补充目标、完成标准与背景 |
| 执行负责人 | 可选，默认未指派，候选范围见权限规则 |
| 状态 | 默认待办，可通过属性胶囊调整；选择状态不触发 AI 执行 |
| 优先级 | 默认无，可调整 |
| 附件 | 可选，当前原型单文件上限 20 MB |
| 任务标签 | 在下拉框中选择或直接输入新建当前项目标签；新建标签名称限 1–20 个字符，提交后关联到该任务 |

按用户最新决定恢复 `7da18d9` 之前的 Loop 创建框结构与公共样式：路径、无边框标题和描述、属性胶囊、底部附件和取消/创建按钮。项目页、子任务和会话右上角入口共用这一组件。创建框不再展示目标、标准、验收人等独立表单行；已有任务数据不受影响。

选中项及候选身份复用公共头像组件；AI 标紧跟姓名。弹层限定在系统标题栏下方，长内容内部滚动。

## 5. 提交、编号与后续状态

- 只有点击“创建”或在标题输入框按 Enter 才提交；提交期间防止重复点击创建多份任务。失败保留填写内容，允许重试；已创建后补存标签失败，不得再次创建任务。
- 编号保留项目前缀，例如 `SC-108`。在当前项目中递增，并支持完整编号查找。不能仅展示数字或为新任务改写旧任务编号。
- 成功后关闭表单，任务进入所属项目所选状态列（默认待办）；会话入口保持当前会话，项目看板入口刷新看板；取消不创建任务。
- 给 AI 分派任务不等于启动执行。不得自动展示“执行中”、历史运行或成功结果；新任务没有执行记录时应显示真实空状态。
- 描述允许使用 Markdown；日常短文字不强行增加标题或表格。

### 5.1 子任务一期

- 子任务与父任务使用同一任务数据源，通过 `parent_issue_id` 建立关系；父子任务必须属于同一协作项目，不建立独立子任务表或复制项目对象。
- 任务详情始终显示子任务区。无子任务时展示可操作空状态；有子任务时展示完成数、总数、进度及每项真实状态、负责人和优先级。父任务面包屑和属性区可返回上级任务。
- 项目任务页提供“层级”视图，以可展开树形列表展示父子关系；默认展开根任务的第一层子任务。筛选或搜索时保留匹配任务的祖先上下文，项目或筛选结果切换时重置组件展开状态。
- 看板状态列以顶层任务作为卡片，列头分别展示该状态的顶层任务数与包含在当前可见任务树中的全部任务数。父任务卡片默认展开直接子任务，并以树线、状态、编号、标题、直接子任务数量和负责人继续承载更深层级；子任务点击进入同一任务详情，折叠只属于当前卡片组件。分组视图仍按每项任务自己的负责人分组，并使用轻量父任务编号或直接子任务完成进度提示关系。
- 子任务可独立设置状态、优先级和负责人。完成父任务不会自动完成子任务；存在未完成子任务时须先确认。批量完成父任务则先要求处理未完成子任务。
- 禁止任务成为自己的父任务，也禁止将任务移动到任一后代任务下。父任务存在子任务时不得删除，须先转移或删除子任务，避免产生孤儿引用。
- 从父任务详情或层级行新建子任务时，统一创建框的路径显示“项目 > 父任务完整编号 > 新建子任务”，提交时保存父任务稳定 ID。分派给 AI 仍不自动启动执行。

### 5.2 任务分解树

- “分解树”是单个任务的上下文视图，不作为项目任务页的第五种主视图。项目页继续保留“层级”用于全项目紧凑浏览；任务详情的子任务区通过“查看分解”在原位置展开当前任务及其全部后代的分解画布，更多菜单提供同一入口并自动定位到该区域。
- 没有子任务时不打开空画布，详情空状态显示“开始分解”并直接打开统一子任务创建框。创建成功后仍使用 `parent_issue_id` 写入当前项目的同一任务数据源。
- 分解树以当前任务为根。每个节点展示状态、完整编号、单行截断标题、优先级、负责人名称与头像、截止时间、最多两个标签和直接子任务完成数；支持逐节点及全部展开/收起、65%–125% 缩放、适应视图、打开子节点详情和从任意节点继续新建子任务。
- 分解画布只替换任务详情子任务区中的列表和进度条；任务标题、描述、评论、面包屑和右侧属性区始终保留。画布继续受现有任务详情及 `routeRight` 宿主约束，不能覆盖客户端系统标题栏或新增一级路由。点击子节点属于明确的详情导航，可进入同一任务详情组件。
- 是否显示画布由任务详情组件持有；展开集合与缩放比例由画布组件持有。任务切换时统一重置，关闭画布后恢复直接子任务列表。节点与统计始终从当前项目任务关系推导，不保存第二份树数据、DOM 状态或 `window` 全局状态。
- 一期不提供拖拽改父级、批量改层级或跨项目移动。父任务更改、删除、完成确认及 AI 执行边界继续遵循 5.1 的既有约束。

## 6. 状态归属与实现位置

- 项目、群、子区与成员权限：`prototype/009-2-membership.js`。
- 会话任务入口及项目路由：`prototype/009-5-patch-im.js`，统一 IM 内核的配置，禁止各入口复制任务控件。
- 任务创建、查询和数据隔离适配：`prototype/009-6-patch-general.js`。
- 统一创建表单及样式：`prototype/049-loop-task-create.js`、`prototype/049-loop-task-create.css`。
- 表单草稿由组件持有，在关闭后重新打开、项目或父任务切换时重置；异步结果必须校验当前表单代次，不污染新表单。

当前为本地原型：任务和附件保留在当前页面内，附件使用本地对象 URL，并未上传服务端。真实 CLI 查询、后端持久化、调度执行和聊天任务卡片回流未完成，不能以预设内容冒充实际联调结果。

## 7. 验收要求

获得测试授权后，覆盖入口矩阵、项目切换、权限变化、身份候选、重复提交、失败重试、完整编号查询和新任务空历史。至少走通“项目群 → 右上角创建任务 → 弹窗提交 → 留在原会话 → 到所属项目核对任务”；返回后不得串会话、重复输入区或覆盖系统标题栏。私聊和非项目群必须没有该入口。

本规范记录规则及当前实现范围，不表示本次已重新执行验收。

## 8. 项目成员角色

按用户最新决定，项目角色只作为成员管理的附加列；不设独立页签，不在姓名下重复展示，不改变原有负责人、管理员和成员权限。负责人及管理员通过成员管理右上角、添加成员旁的“角色设置”按钮，选择成员后多选已有角色或输入新建角色。角色列只读，不显示逐行设置按钮。既有角色数据保留。

任务创建不再选择角色，任务列表、看板和详情不展示角色；已有任务下达者信息保留。历史角色字段兼容保留，不扩大到其他项目功能。
