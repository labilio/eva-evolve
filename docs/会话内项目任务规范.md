# 会话内项目任务规范

本规范适用于团队 IM 中的任务入口、后续消息转任务入口及其创建流程。依据本轮已确认的产品定义：**这里的任务只指所属项目的 Loop 任务**。它不是个人待办、自动化任务，也不是某次 AI session 的执行记录。

## 1. 入口与适用范围

| 会话类型 | 项目任务入口 | 任务归属 |
| --- | --- | --- |
| 项目全员群 | 有权限时显示 | 当前项目 |
| 项目内普通群 | 有权限时显示 | 群所属项目 |
| 项目群的子区 | 有权限时显示 | 子区所在群的项目 |
| 非项目群及其子区 | 不显示 | 无 |
| 人与人私聊 | 不显示 | 无，即使双方同属项目 |
| 人与分身、数字员工的私聊 | 不显示 | 无，即使该 AI 加入了项目 |
| 我的 AI 的 OpenClaw session | 不显示 | 无 |
| 个人 Eva 会话 | 不显示此入口 | 不适用 |

不得根据名称、聊天内容提到的项目、上一次打开的项目或 AI 的归属猜测任务项目。子区先解析父群，再通过成员体系的稳定 ID 获取项目。当前供应链演示关联：协作项目 `prod`，任务看板项目 `p-supply`；二者是适配关系，不得复制项目。

## 2. 当前交互与后续边界

当前实现：会话右上角“创建任务” → 在当前会话上打开统一 Loop 创建弹窗 → 确认提交 → 关闭弹窗并显示完整任务编号。不得跳转项目页替代创建入口。

所属项目由当前群/子区解析并传入表单，不依赖上一次打开的项目。提交时再次校验群及项目权限。创建后保留当前会话；任务进入所属项目看板。当前没有自动发送聊天任务卡片，不能把提示成功说成已发送任务卡片。

后续若加入“将消息转为任务”，必须继续复用同一创建组件和数据入口；消息只能预填上下文，必须让用户检查并提交。不能把 AI 的建议、普通消息发送或打开任务页视作创建授权。

## 3. 权限与数据边界

- 展示与点击时均检查：当前用户账号能够访问父群和所属项目。无权限时不显示入口；权限发生变化后不得继续进入或提交。
- 项目成员可以创建任务，不把创建权限擅自收紧为管理员专属。UI 操作身份来自当前账号，不把私聊对象当作创建者。
- 创建时重新检查项目存在及访问权限。当前项目固定，不在来自会话的创建流程中切换其他项目。
- 执行负责人只能是当前项目的联系人（AI 身份不作为负责人）；身份名称与类型从稳定 ID 对应的业务数据派生，不能接受表单伪造值。
- **任务身份候选父容器规范**：所有选人入口的候选一律由父容器（任务所属项目）唯一推导，禁止入口自取全局名单。负责人 = 项目联系人；来源者与创建者 = 全部联系人（通讯录）+ 已加入当前项目的 AI 分身与数字员工；写入校验与候选同源，AI 身份不在项目成员范围内一律拒绝。候选面板「联系人」分组内本人（当前操作人 `actorId`）恒排在第一位，其余联系人保持候选原始顺序；检索态仍按相关度排序，不因置顶破坏检索语义。
- 验收人只能是当前项目的联系人。父任务必须属于同一项目；任务详情、评论、子任务和执行历史必须按任务及项目隔离。
- 数字员工能参与项目任务不等于能被拉进群；不能借创建任务绕过成员或身份规则。

## 4. 创建表单

| 字段 | 规则 |
| --- | --- |
| 所属项目 | 顶部路径固定显示当前外层项目，不提供旧 Loop 项目选择器 |
| 标题 | 必填，去除首尾空白后不可为空 |
| 描述 | 可选，支持补充目标、完成标准与背景 |
| 执行负责人 | 可选，默认未指派，候选范围见权限规则 |
| 来源者 | 手动创建时固定为当前操作人本人，不提供选择 |
| 创建者 | 手动创建时固定为当前操作人本人，不提供选择；创建后在详情属性区可改选（候选为全部联系人及已加入当前项目的 AI 分身、数字员工） |
| 状态 | 默认待办，可通过属性胶囊调整；选择状态不触发 AI 执行 |
| 优先级 | 默认无，可调整 |
| 截止日期 | 可选，按 `YYYY-MM-DD` 写入任务唯一 `due_date` 字段；创建时可设置，详情属性区可修改或清除 |
| 附件 | 可选，支持一次选择多个文件并按选择顺序上传；每个文件单独校验，当前原型单文件上限 20 MB |
| 任务标签 | 在下拉框中选择或直接输入新建当前项目标签；新建标签名称限 1–20 个字符，提交后关联到该任务 |

按用户最新决定恢复 `7da18d9` 之前的 Loop 创建框结构与公共样式：路径、无边框标题和描述、属性胶囊、底部附件和取消/创建按钮。项目页、子任务和会话右上角入口共用这一组件。创建框不再展示目标、标准、验收人等独立表单行；已有任务数据不受影响。

选中项及候选身份复用公共头像组件；AI 标紧跟姓名。弹层限定在系统标题栏下方：宿主固定在标题栏下沿，Semi 的溢出回弹只在该区域内进行；面板内容区限高（`max-height`）随触发点上下可用空间自适应，长内容内部滚动，内容不足上限时按内容收缩。

- 编号保留项目前缀，例如 `SC-108`。在当前项目中递增，并支持完整编号查找。不能仅展示数字或为新任务改写旧任务编号。
- 成功后关闭表单，任务进入所属项目所选状态列（默认待办）；会话入口保持当前会话，项目看板入口刷新看板；取消不创建任务。
- 给 AI 分派任务不等于启动执行。不得自动展示“执行中”、历史运行或成功结果；新任务没有执行记录时应显示真实空状态。
- 描述允许使用 Markdown；日常短文字不强行增加标题或表格。
- 多个任务附件在详情正文左侧按群聊文件卡规格纵向排列，卡片间距 4px；每个附件分别提供预览、下载和保存到项目文件库。文件图标须按扩展名显示可辨识的类型标识，例如表格显示 `X`、PDF 显示 `PDF`，未知类型回退到扩展名或通用文件标识。
- 任务详情中的文件附件点击后复用统一文件预览能力，从任务详情右侧并排推出并挤压详情内容；不新开页面、不使用蒙层，也不改变任务详情本身在聊天入口中的既有呈现方式。预览左边缘可拖拽并支持键盘调整宽度，双击或按 `Home` 恢复默认宽度。预览头部与消息、项目文件和文件库共用全屏按钮，全屏覆盖系统标题栏下方工作区；首次按 `Esc` 退出全屏，再次按下才关闭预览，退出后恢复原来的右栏宽度与拖拽能力。切换任务时关闭原任务的文件预览，点击预览外区域关闭。

### 5.1 子任务一期

- 子任务与父任务使用同一任务数据源，通过 `parent_issue_id` 建立关系；父子任务必须属于同一协作项目，不建立独立子任务表或复制项目对象。
- 任务详情始终显示子任务区。无子任务时展示可操作空状态；有子任务时递归展示当前任务的全部后代，以紧凑缩进和树线表达真实父子层级，并展示每项真实状态、负责人和优先级；默认展示直接子任务起算的前 3 层，第 4 层及更深任务初始收起，提供“展开全部层级”一次展开全部后代，同时保留逐节点展开和收起。完成数、总数和进度始终按全部后代统计，不受当前折叠状态影响。详情顶部保留可点击的项目入口，并最多展示离当前任务最近的 3 个任务层级；每个任务层级同时显示完整编号与任务名称，更早层级以省略标记提示。实际展示的任务层级均可点击，不再提供独立的“返回某任务”入口；属性区的父任务也可切换到上级详情。
- 项目任务页提供“层级”视图，以可展开树形列表展示父子关系；默认展开根任务的第一层子任务。筛选或搜索时保留匹配任务的祖先上下文，项目或筛选结果切换时重置组件展开状态。
- 看板中父任务与所有层级的子任务都使用同规格独立卡片，并按每项任务自己的真实状态进入对应状态泳道。看板不在父任务卡片内嵌子任务列表，也不展示树线、层级缩进、展开控件或父子关系提示；父子层级只在任务详情和项目“层级”视图中查看。分组视图仍按每项任务自己的负责人分组，并使用轻量父任务编号或直接子任务完成进度提示关系。
- 子任务可独立设置状态、优先级、负责人和截止日期。截止日期与普通任务共用 `due_date`，看板、分组、列表、层级和详情均从该字段读取。完成父任务不会自动完成子任务；存在未完成子任务时须先确认。批量完成父任务则先要求处理未完成子任务。
- 禁止任务成为自己的父任务，也禁止将任务移动到任一后代任务下。父任务存在子任务时不得删除，须先转移或删除子任务，避免产生孤儿引用。
- 从父任务详情或层级行新建子任务时，统一创建框的路径显示“项目 > 父任务完整编号 > 新建子任务”，提交时保存父任务稳定 ID。分派给 AI 仍不自动启动执行。

### 5.2 任务分解层级

- 任务详情只通过子任务区的递归层级树查看分解关系，不再提供图形分解画布、查看分解入口、缩放、适应视图或全屏画布编辑。项目任务页继续保留“层级”视图，用于全项目紧凑浏览。
- 层级树以当前任务为根，展示全部后代的真实父子关系；默认展示前三层，第 4 层及更深任务初始收起，并提供“展开全部层级”和逐节点展开、收起。完成数、总数和进度按全部后代统计，不受折叠状态影响。
- 详情面包屑固定保留项目入口，并展示“任务完整编号 + 任务名称”。任务链不超过 3 级时全部展示；超过 3 级时仅展示当前任务及离它最近的两级祖先，更早层级以省略标记提示。项目和实际展示的每个任务层级均可点击；点击项目返回所属项目任务页并同步恢复项目地址，点击任务层级后在当前详情位置切换任务，不叠加新的详情页，也不保留独立的“返回某任务”入口。右侧父任务属性使用相同的原位切换行为。
- 没有子任务时，详情空状态显示“开始分解”并直接打开统一子任务创建框。创建成功后仍使用 `parent_issue_id` 写入当前项目的同一任务数据源；一期不提供拖拽改父级、批量改层级或跨项目移动。父任务更改、删除、完成确认及 AI 执行边界继续遵循 5.1 的既有约束。

## 7. 验收要求

获得测试授权后，覆盖入口矩阵、项目切换、权限变化、身份候选、重复提交、失败重试、完整编号查询和新任务空历史。至少走通“项目群 → 右上角创建任务 → 弹窗提交 → 留在原会话 → 到所属项目核对任务”；返回后不得串会话、重复输入区或覆盖系统标题栏。私聊和非项目群必须没有该入口。

本规范记录规则及当前实现范围，不表示本次已重新执行验收。

## 8. 项目成员角色

按用户最新决定，项目角色只作为成员管理的附加列；不设独立页签，不在姓名下重复展示，不改变原有负责人、管理员和成员权限。负责人及管理员通过成员管理右上角、添加成员旁的“角色设置”按钮，选择成员后多选已有角色或输入新建角色。角色列只读，不显示逐行设置按钮。既有角色数据保留。

任务创建不再选择角色，任务列表、看板和详情不展示角色；已有任务创建者信息保留。历史角色字段兼容保留，不扩大到其他项目功能。
- 2026-09-21：界面字段「下达者」更名「创建者」，仅文案变化，数据字段仍为 creator_id，候选与校验规则不变。
