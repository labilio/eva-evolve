# 供应链运营协同：演示与验收教程

本机 Edge 地址：**http://127.0.0.1:4174/#/collab**。进入“供应链运营协同”，不需要另外创建项目。预计 8～12 分钟。

这是本地交互原型，角色切换、邀请与共享权限由本机演示数据模拟；不代表真实登录、后台鉴权或通知已经接通。浏览器刷新保留成员、邀请、消息和共享版本，但需从项目列表重新进入供应链项目。

## 开场准备（每次演示做一次）

1. Edge 打开测试地址 → 点击“供应链运营协同” → “项目设置” → “成员管理”。
2. 打开顶部信封图标「邀请信箱」→“重置演示数据” → 阅读影响范围 → “确认重置”。将恢复本机该项目的成员、群成员、邀请、演示消息，并清除该项目本地转存的共享版本；其他项目不受影响。
3. 页面应显示：**王宜林身份、3 位联系人、2 个分身**，下面有“何静 · 待管理员审批 · 林晓发起邀请”。
4. 后文所有“切换身份”，都在 **左下角账号头像／姓名 → 切换身份**操作。它是演示工具，不是真实登录。默认身份为王宜林。

| 人员 | 初始状态 | 演示职责 |
| --- | --- | --- |
| 王宜林 | 项目负责人；带自己的分身 | 审批、共享文件、邀请进入普通群 |
| 林晓 | 普通成员；带自己的分身 | 已预先邀请何静，演示普通成员需审批 |
| 周远 | 项目管理员；未加入整改协同群 | 可选演示管理员也不能直接读取未加入的群 |
| 何静 | 尚未加入，邀请待审批 | 自己接受、选择分身、查看共享文件、入群、退出 |

预置普通群为 **供应商整改协同**，初始 **2 联系人／1 分身**（王宜林、林晓、林晓的分身）。其子区为 **A-2409整改证据**。群中已放入两条说明消息和 **A-2409来料异常分析报告.pdf**，关联任务 **SC-103**。

分身选择均为可选：默认不选即可继续，不存在单独的“不带入”选项。下文主动勾选何静的分身，是为了演示分身同步与退出，不是加入的前置条件。

## 1. 林晓：展示普通成员发起邀请

切换到 **林晓**，停留成员管理。

- 看邀请记录：“何静 · 待管理员审批 · 林晓发起邀请”。
- 林晓可以撤回，但没有“同意”审批按钮。演示时不要点撤回。

讲解：“普通成员可以发起邀请，但不能自己审批。这里已经预先发起，现场从审批继续。”

## 2. 王宜林：审批项目邀请

切换到 **王宜林** → 顶部信封「邀请信箱」→「待我审批」→ 点击 **同意**。

- 邀请变为 **待本人接受**。
- 项目仍是 **3 联系人／2 分身**，何静尚未真正加入。

讲解：“负责人同意只代表允许邀请，对方接受才算加入。”

## 3. 何静：接受并带入自己的分身

切换到 **何静**。

1. 打开顶部信封「邀请信箱」→「收到的邀请」，可在项目外处理。
2. 点击 **接受** → 勾选 **何静的分身** → **确认加入**，然后关闭信箱。本教程需要带入分身，才能观察后续级联退出。
3. 进入供应链运营协同 → 项目设置，成员页变为 **4 联系人／3 分身**，何静的联系人行下面关联自己的分身。
4. 点顶部 **群聊**：目前只出现 **全员群**，没有“供应商整改协同”。
5. 点 **聊天信息**：全员群也是 **4 联系人／3 分身**，成员管理入口指向项目。

讲解：“主人自己选择带入自己的分身。全员群自动跟项目同步，但普通群需要单独加入。”

## 4. 王宜林：把群文件共享到项目

返回项目设置，切换 **王宜林**。

1. 顶部 **群聊** → **供应商整改协同**（选大群，不是下面的子区）。
2. 对 **A-2409来料异常分析报告.pdf** 文件卡片点击鼠标右键；触控板可双指点击。
3. 选择 **转存到项目** → 目标选择 **供应链运营协同**。
4. 停留确认框讲解：来源为“供应商整改协同 / 任务 SC-103”，共享范围 **4 联系人／3 分身**。
5. 点击 **确认转存** → 看到“已转存到项目” → **完成**。

讲解：“这一步明确扩大的是文件共享版本的可见范围，不会把原群聊天一起公开。”

## 5. 何静：能看共享文件，仍不能看原群

返回项目设置，切换 **何静**。

1. 顶部 **团队文件** → 点击 **A-2409来料异常分析报告.pdf**。
2. 看“共享版本 v1”、来源群和任务标识，打开实际 PDF 样例预览。
3. 关闭预览 → 顶部 **群聊**：仍只有全员群，没有“供应商整改协同”及其子区。

讲解：“何静已经是项目成员，所以能读项目共享文件；她还没加入原群，所以看不到群聊天。”

## 6. 王宜林邀请、何静接受普通群邀请

先切换 **王宜林**：

1. **群聊 → 供应商整改协同 → 聊天信息 → 查看与管理成员**。
2. 点击 **邀请成员** → 选择 **何静** → **发送邀请**。
3. 看到“何静 · 待本人接受”，人数仍为 **2 联系人／1 分身**。关闭群成员弹窗。

再到项目设置切换 **何静**：

1. 顶部 **群聊** → 左栏“待接受邀请”下面点击 **供应商整改协同**。
2. **接受邀请** → 选择 **何静的分身** → **确认**。
3. 群成员变为 **3 联系人／2 分身**。关闭邀请弹窗。
4. 左栏现在出现大群和 **A-2409整改证据**子区，点击子区读取林晓的预置消息。
5. 输入并发送：“已收到整改证据，我会补齐现场验证记录，结论请负责人确认。”

讲解：“普通群要自己接受，分身也由本人选择带入。加入大群后，子区沿用大群权限，不再邀请一遍。”

## 7. 何静退出：验证人、分身和群权限一起收回

仍以 **何静**身份：

1. 返回 **项目设置 → 成员管理**，在何静自己的行点击 **退出** → 确认。
2. 项目内容变为不可访问，群聊和团队文件入口也不再显示原有内容。
3. 在仍可见的演示身份控件切到 **王宜林**：项目回到 **3 联系人／2 分身**。
4. **群聊 → 供应商整改协同 → 聊天信息**：回到 **2 联系人／1 分身**。
5. 点击 **A-2409整改证据**：何静刚发的历史消息仍在。

讲解：“退出项目会收回联系人及其分身在项目和群中的访问，已有工作历史保留。”

负责人转让不放在主演示里，避免改变演示起点。需要额外验收时可在最后测试：王宜林直接退出应提示先转让；转让对象只能是当前项目内另一位联系人。

## 验收勾选

- [ ] 载入后 3 联系人／2 分身，何静待审批；普通成员不能自行审批。
- [ ] 审批后仍未加入；本人选择自己的分身并接受后变为 4 联系人／3 分身。
- [ ] 全员群同步；未独立加入的普通群和子区不可见。
- [ ] 转存前确认来源、任务和目标可见范围；何静能看共享 PDF 但不能看原群。
- [ ] 群邀请单独接受，加入后自动能读子区并发送消息。
- [ ] 退出项目后联系人和分身都离开群，其他成员仍能读历史消息。
- [ ] 切换其他一级入口再返回、刷新后重新进入，邀请和共享结果保留，无上一身份内容残留。

## 再次演示与排错

演示完成后打开邀请信箱，点击“重置演示数据”，下一次从第 1 节开始。中途不要载入，否则会重置当前进度。

如果人数与教程不一致，先检查顶部演示身份，再确认是否从头载入过预设。只重载页面不会重置演示数据。不要清空整个浏览器存储，也不要以正式站替代本机功能分支验收。
