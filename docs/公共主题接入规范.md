# Eva 公共主题接入

目标：业务使用公共组件就获得 Eva 主题，不要求调用方查数值、重画组件或复制 CSS。

## 唯一来源

| 内容 | 代码所有者 |
| --- | --- |
| Eva 颜色、字族、字重、圆角、间距阶梯 | `prototype/047-gds-tokens.css` |
| Semi / 旧运行时语义变量映射 | `prototype/049-gds-brand-reroot.css` |
| 暗色语义映射 | `prototype/057-gds-dark-tokens.css` |
| 表单、确认、操作控件的文字层级与间距引用 | `prototype/063-ui-theme.js` |
| Modal 独有布局映射 | `prototype/063-dialog-theme.js` |
| Semi 官方 Sass 主题构建 | `tools/build-dialog-theme.mjs` |
| 公共业务接入出口 | `prototype/063-forms-entry.jsx`（运行时 `createForms`） |

个人对话正文的 GDS 字阶、Octo IM 内核和身份组件继续由原合同管理，不能用控件正文覆盖聊天正文。`dialogText` 只是公共 typography 的兼容别名。

## 新组件怎么接

1. 先检查是否已有 Eva 业务组件；有则复用。没有时在公共层使用锁定版本的原生 Semi。
2. 颜色、圆角、投影引用既有语义变量，不再定义一套色板。Portal 挂到 body 时也必须得到同一主题。
3. 优先使用原生 props；需要改组件参数时，使用已安装 Semi 的官方 Sass 变量，由构建器生成差异。不存在的变量必须构建失败。Semi 未开放参数的必要集成样式集中维护并说明原因，不落在业务页面。
4. 公共组件负责主题，业务负责文案、对象、危险性、位置、权限和保存事务。不能把“移出群聊”、左侧弹出或危险按钮写成通用默认。
5. 在 `tools/check-ui-theme.mjs` 登记精确的原生 import 所有者。增加组件须同时提供主题映射或说明它已经完整消费全局变量，并补浏览器验证；不使用通配白名单。
6. 业务通过公共出口调用。`npm run build` 会检查新增原生 Semi 引用；`npm test` 包含同一合同及反例测试。

## 组件不同，主题相同

Modal 保留标题区/正文/页脚及分割线；Popconfirm 保留原生锚点浮层与紧凑结构。它们共享文字层级、颜色、圆角来源和按钮规范，不共享固定高度。Form 的必填标记、错误提示、校验与 Dialog 的焦点规则保持原公共实现。

## 边界与验证

这不是宣称所有历史 CSS 已清零。旧运行时、Octo 内核与未迁移业务仍存在；本次保护模块源码中的原生 Semi 接入，不扫描 vendor 并伪称已经全部迁移。不能通过改白名单绕过主题适配。

新增或修改适配至少检查：亮/暗、Portal、长文本、取消/确认、危险与普通按钮、键盘和已有 Modal/Form 回归。自动检查是防误接入机制，不是对任意 CSS 的安全沙箱；代码审查仍须核对主题覆盖。合并遵循用户亲自验收后明确同意的要求。

## 已接入浮层

`Popover` 与 `Popconfirm` 均从现有 `063-forms-entry.jsx` 导出，旧运行时通过共享 `forms.Popover / forms.Popconfirm` 使用，不新建 React 实例。
两者共同读取 `floatingSurface`，通过 Semi 原生 style 属性接入表面、文字、圆角、投影与箭头语义色；不重写定位、Portal 或关闭控制器。
Popover 提供 title/content 统一内容布局，不在调用方重复增加外侧留白。Popconfirm 的原生内边距由公共 Sass 映射管理。两类浮层按 Arco 使用内容自适应宽高、最大宽度 350px，同时限制在视口宽度内，不增加固定最小宽度。业务可传宽度等布局参数，但共同外观由公共层收口。Popconfirm 默认保留警示图标、不显示关闭图标，单句标题正常字重、带说明标题中等字重；按钮使用统一紧凑参数。既有完整选择器暂不批量迁入此正文布局，避免重复留白。

### 已确认的浮层布局来源与验收

布局参考 Arco Design React 的 Popover / Popconfirm / Button 官方实现（2026-10-10 核对）。数值只在 `063-ui-theme.js` 维护；不将 Modal 的正文尺寸或按钮规格整体套给轻量浮层。Popover 的可选 title 由公共布局处理，content 支持原生函数形式并透传焦点上下文。两类组件均保留原生 ref、可控显隐、定位、异步确认与关闭能力。

Semi Popconfirm 的 style 仅传入内层确认卡，因此外层表面使用公共生成样式补齐。只有外壳绘制背景与投影；带箭头时移除 Semi 额外外壳留白，内边距仍由同一 Sass 参数负责。这些集成样式仅作用于公共组件标识，不改变未迁移的历史浮层。

本地查看使用真实 Eva 业务入口：供应链运营协同的任务详情 → 更多 → 关联父任务，以及项目文件/文件库中的标签编辑和删除操作。不再维护独立演示页。
验证：`node --test tests/ui-theme.test.mjs tests/browser/ui-theme.mjs`。公共 Modal/Form 回归仍由原有浏览器测试负责。

### 焦点与文案依据

- 焦点与语义参考 [W3C APG Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 与 [Tooltip](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)。Popover/Popconfirm 不是阻断整个页面的 Modal，不标记 `aria-modal=true`。仅展示信息的 hover 浮层保留触发器焦点，同时支持键盘聚焦触发；含交互内容使用 click/custom dialog，不以 tooltip 承载可操作控件。
- Popconfirm 通过原生 cancelButtonProps.autoFocus 默认聚焦取消，保留 Tab/Shift+Tab、Escape 和关闭返回触发器；业务可以使用原生按钮参数选择其他合理初始目标。Popover 的 click/custom 默认通过 Semi initialFocusRef 聚焦首个可用字段，跳过隐藏、禁用和 inert 内容；无字段时选择可用按钮，再回退到内容容器。阅读内容可传 initialFocus="content"，业务也可以提供目标函数或原生 initialFocusRef。可访问名优先绑定 title，无标题的复杂内容必须传 aria-label。Semi 缺少外层命名 prop，由公共标签适配一次绑定，不添加新的定位、关闭或焦点陷阱。
- 文案参考 [Ant Design 文案规范](https://ant.design/docs/spec/copywriting-cn.md)：名称前后一致、先表达关键操作及后果、精简重复信息；标题和按钮不加句号，简短独立提示省略无用句末标点，多句说明保留标点。按钮使用实际动作名称；示例使用“移出群聊”，业务词语不写入公共组件默认值。警示图标保留，不用文案中的感叹号反复制造紧张感。

### Popover 内的提交表单

需要保存／取消的轻量浮层统一使用公共 `FloatingForm`，它组合 Semi Form 与内部操作区，操作区不单独导出。Popover 管外壳内边距；字段本身不提供外侧 padding，组合通过布局 gap 统一提供字段之间的间距；按钮区独占最后的 20px 默认表单项目间距。错误或帮助内容位于字段之后时仍按同一字段边界处理，其自身说明间距保留。业务不得另设字段底部留白或再拼一行按钮。Modal 继续使用 Dialog/Form/Actions，不改为轻量浮层组合。

当前调用：文件标签编辑、关联父任务。回归见 `tests/browser/business-overlays.mjs` 与 `tests/browser/file-tags-form-migration.mjs`，其中直接测量标题到首字段标签的 4px、选择框到按钮的 20px 距离。

### 浮层共享行为边界

- `063-floating-focus.js` 统一处理关闭后的焦点返回，支持受控浮层；入口会消失时传 `returnFocus={() => 后续入口元素}`。点击外部可操作内容不抢回焦点。业务不得再用 onCancel/onEscKeyDown 或卸载 effect 重复调用 focus。
- `description` 默认关闭；简单短说明可显式开启 aria-describedby，复杂表单或多段结构不整块朗读。无标题必须提供明确 aria-label。
- Popconfirm 统一等待 onConfirm 返回的 Promise；同步异常和异步失败显示公共错误提示，保留浮层以便重试。处理中阻止重复确认，关闭后忽略旧结果对当前浮层的影响。业务仍负责实际数据事务；关闭不等于撤销已经发出的请求。异步业务需要后续 UI 操作时，使用 onConfirm 第二参数的 isCurrent() 判断是否仍属当前打开周期。
- FloatingForm 提供 disabled 与 busy；取消仍可用。业务只声明权限状态，不重画禁用或 loading 样式。
- 内容宽度受视口限制，高度扣除客户端标题栏与边缘空间，长内容通过浮层内部滚动到达末尾操作；不固定普通短内容高度。定位、Tab 导航和 Portal 继续由 Semi 管理。
- FloatingForm 自身拥有主题，不依赖 Popover 祖先。嵌套字段组使用公共 FloatingForm.Fields；帮助说明用原生 extraText、错误用原生字段错误或 SubmissionError。隐藏字段不占布局 gap。自定义横向布局或 Form.Section 不是可任意叠加的透明容器，新增结构须补充几何测试。

行为回归：`node --test tests/browser/floating-policy.mjs`；同时运行现有主题和业务浮层测试，不能仅凭适配器单测宣称所有业务入口验收完成。

### Popover 表单与 Popconfirm 的尺寸区别

Arco 的 Popover 只定义标题及内容容器，不自带按钮区。其内表单按默认 Form/Button 规格组合：标签 14px/400，标签到控件 8px，控件和按钮 32px 高，按钮文字 14px、水平 padding 15px，表单项目间距 20px。FloatingForm 将这些值映射到 Semi 官方 Form Sass 参数及 Button props，统一维护；不是声称 Arco 提供了独立的 Popover 表单模板。标题到内容仍为 Popover 原生 4px，容器留白为上下12px、左右16px。

Popconfirm 源码明确使用 mini 按钮，继续保持 24px 高、12px 字、水平 padding 11px，说明到按钮16px。禁止把这一规格复用于填写后保存的表单。按钮相互间距均为8px。Eva 的颜色、圆角及字体家族保持原有主题；已确认的 Modal 表单规格不在本轮变更。

核对来源：[Popover tokens](https://github.com/arco-design/arco-design/blob/main/components/Popover/style/token.less)、[Form tokens](https://github.com/arco-design/arco-design/blob/main/components/Form/style/token.less)、[Button tokens](https://github.com/arco-design/arco-design/blob/main/components/Button/style/token.less)、[Popconfirm 实现](https://github.com/arco-design/arco-design/blob/main/components/Popconfirm/index.tsx)。

### 组合约束与现有用法核查（2026-10-10）

`063-ui-theme.js` 的 composition 按语义区分 form / confirmation；FloatingForm.Fields、FloatingForm 和 Popconfirm 分别消费对应规格。浮层位置不决定按钮规格。表单自动生成 id 并关联内部提交按钮，业务可传已有 id。Semi 继续拥有字段、帮助、错误和校验行为。

现有公共浮层调用：关联父任务、文件标签（项目、文件库、详情入口共用）、个人对话删除、文件永久删除。前两类统一 FloatingForm，后两类统一 Popconfirm；未发现业务单独调用 FloatingActions，故移除该公共出口。文件标签的帮助说明迁入 extraText，不再在浮层内借用文件库页面的段落间距。标准 Modal 保留已有 Dialog/Form/Actions 和现有14场景间距矩阵；群资料行内编辑和转发子区内联创建的 compact Actions 保留既有行为。Octo 选择器、历史运行时和非提交浮层不视为已迁移，不能用此次核查声称全仓库任意组合均受保护。

构建检查拒绝业务重新设置字段 padding/margin/fontSize/fontWeight，拒绝单独拼 FloatingActions；允许 display:none 等真实字段可见性配置。该检查针对当前显式调用写法，是辅助护栏，不声称能识别任意动态 CSS。浏览器矩阵验证实际字号、控件尺寸、首尾/字段间距、隐藏字段、嵌套 FloatingForm.Fields、帮助信息、错误重试和提交关联；未来新增组合应补代表结构，而不是补页面特例。

### 官方依据与 Eva 组合约定的边界

Semi 的 [Form 设计指南](https://semi.design/design/zh-CN/input/form)规定字段标签、帮助、校验与分组职责；[Space](https://semi.design/zh-CN/basic/space)负责组件之间的间距；[Tokens](https://semi.design/zh-CN/basic/tokens)提供统一视觉参数。这些能力不代表任意嵌套会自动抵消外边距。Arco 的 Popover、Form、Button 参数分别参考上方官方源码；把它们组合成填写型浮层，以及字段外距归零、由布局 gap 单独负责相邻距离，是 Eva 的组合约定，并非官方提供的完整模板。

嵌套字段组只通过 `FloatingForm.Fields` 使用；它要求 FloatingForm 上下文，禁止作为普通 Modal/Form 的通用布局出口。现有 Modal 的14场景矩阵只验证已接入模板，不保证任意 Card/Section 嵌套。Card 与自由文本仍需使用其各自正式接入的组件规格，不能声称本轮已经覆盖。

### Token 与组件参数的维护边界

圆角、语义颜色、常用间距与字重引用既有 Eva token；不为同一设计决定复制数值。组件专属宽度、图标尺寸、按钮几何、零值及字体文件字重声明可以保留原参数，不以消灭所有 px 为目标。字号仍由公共 typography 表管理，不能在仍追加 px 的消费者中机械换入 CSS var。

不同角色继续不同：普通成员窗引用 window 圆角，单选转让窗及选择器引用 panel 圆角，不因 token 化改成同一个值。未使用的配置删除，不为它建立新 token。主题回归同时验证默认外观和运行时 token 联动；本轮不引入密度切换功能。
