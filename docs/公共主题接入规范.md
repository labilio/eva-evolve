# Eva 公共主题接入

目标：业务使用公共组件就获得 Eva 主题，不要求调用方查数值、重画组件或复制 CSS。

## 唯一来源

| 内容 | 代码所有者 |
| --- | --- |
| Eva 颜色、字族、字重、圆角、间距阶梯 | `prototype/047-gds-tokens.css` |
| Semi / 旧运行时语义变量映射 | `prototype/049-gds-brand-reroot.css` |
| 暗色语义映射 | `prototype/057-gds-dark-tokens.css` |
| 表单、确认、操作控件的文字层级与间距引用 | `prototype/063-ui-theme.js` |
| Modal 独有布局映射 | `prototype/063-dialog-theme.js` |
| Semi 官方 Sass 主题构建 | `tools/build-dialog-theme.mjs` |
| 公共业务接入出口 | `prototype/063-forms-entry.jsx`（运行时 `createForms`） |

身份卡中的多行人员展示通过公共 `IdentityList` 接入 Semi List；行对齐、文字层级与间距在公共层维护，业务只提供身份数据及统一头像节点。

个人对话正文的 GDS 字阶、Octo IM 内核和身份组件继续由原合同管理，不能用控件正文覆盖聊天正文。`dialogText` 只是公共 typography 的兼容别名。

## 新组件怎么接

1. 先检查是否已有 Eva 业务组件；有则复用。没有时在公共层使用锁定版本的原生 Semi。
2. 颜色、圆角、投影引用既有语义变量，不再定义一套色板。Portal 挂到 body 时也必须得到同一主题。
3. 优先使用原生 props；需要改组件参数时，使用已安装 Semi 的官方 Sass 变量，由构建器生成差异。不存在的变量必须构建失败。Semi 未开放参数的必要集成样式集中维护并说明原因，不落在业务页面。
4. 公共组件负责主题，业务负责文案、对象、危险性、位置、权限和保存事务。不能把“移出群聊”、左侧弹出或危险按钮写成通用默认。
5. 在 `tools/check-ui-theme.mjs` 登记精确的原生 import 所有者。增加组件须同时提供主题映射或说明它已经完整消费全局变量，并补浏览器验证；不使用通配白名单。
6. 业务通过公共出口调用。`npm run build` 会检查新增原生 Semi 引用；`npm test` 包含同一合同及反例测试。

## 组件不同，主题相同

### 状态图标的颜色

常规操作图标与相邻文字保持相同的中性色。关注、置顶等持续开关的**已启用态**可使用 `--eva-action-primary` 表达选中；未启用态保持常规色。只在该图标确实表示已选中时使用实心形态，不因 SVG 有填充就统一涂蓝。菜单中的“关注”“置顶”及“取消关注”“取消置顶”等命令均使用普通操作色。列表标题旁仅用于说明“已置顶”的标记使用次级中性色；直接可点击的关注、订阅和置顶开关可以用主题色表达已开启。普通工具按钮（更多、复制、全屏、关闭）显式使用 tertiary，不能依赖默认 primary。

错误、警告、成功、任务优先级、项目归属等图标沿用各自业务语义色；禁用态不使用品牌蓝。浅色与暗色都引用公共语义 token，不在业务 CSS 或 SVG 属性中复制品牌色数值。公共 Semi `primary` 按钮的浅色和无边框形态读取 `--eva-action-primary`；`tertiary` 普通操作不因此变成蓝色。新状态图标同时检查未启用、已启用、悬停、禁用和暗色下的计算颜色；源码合同不能替代浏览器层的 CSS 优先级验证。

Modal 保留标题区/正文/页脚及分割线；Popconfirm 保留原生锚点浮层与紧凑结构。它们共享文字层级、颜色、圆角来源和按钮规范，不共享固定高度。Form 的必填标记、错误提示、校验与 Dialog 的焦点规则保持原公共实现。

## 边界与验证

这不是宣称所有历史 CSS 已清零。旧运行时、Octo 内核与未迁移业务仍存在；本次保护模块源码中的原生 Semi 接入，不扫描 vendor 并伪称已经全部迁移。不能通过改白名单绕过主题适配。

新增或修改适配至少检查：亮/暗、Portal、长文本、取消/确认、危险与普通按钮、键盘和已有 Modal/Form 回归。自动检查是防误接入机制，不是对任意 CSS 的安全沙箱；代码审查仍须核对主题覆盖。合并遵循用户亲自验收后明确同意的要求。

## 已接入浮层

`Popover` 与 `Popconfirm` 均从现有 `063-forms-entry.jsx` 导出，旧运行时通过共享 `forms.Popover / forms.Popconfirm` 使用，不新建 React 实例。
两者共同读取 `floatingSurface`，通过 Semi 原生 style 属性接入表面、文字、圆角、投影与箭头语义色；不重写定位、Portal 或关闭控制器。
Popover 提供 title/content 统一内容布局，不在调用方重复增加外侧留白。Popconfirm 的原生内边距由公共 Sass 映射管理。两类浮层按 Arco 使用内容自适应宽高、最大宽度 350px，同时限制在视口宽度内，不增加固定最小宽度。业务可传宽度等布局参数，但共同外观由公共层收口。Popconfirm 默认保留警示图标、不显示关闭图标，单句标题正常字重、带说明标题中等字重；按钮使用统一紧凑参数。既有完整选择器暂不批量迁入此正文布局，避免重复留白。

### 已确认的浮层布局来源与验收

布局参考 Arco Design React 的 Popover / Popconfirm / Button 官方实现（2026-10-10 核对）。数值只在 `063-ui-theme.js` 维护；不将 Modal 的正文尺寸或按钮规格整体套给轻量浮层。Popover 的可选 title 由公共布局处理，content 支持原生函数形式并透传焦点上下文。两类组件均保留原生 ref、可控显隐、定位、异步确认与关闭能力。

Semi Popconfirm 的 style 仅传入内层确认卡，因此外层表面使用公共生成样式补齐。只有外壳绘制背景与投影；带箭头时移除 Semi 额外外壳留白，内边距仍由同一 Sass 参数负责。这些集成样式仅作用于公共组件标识，不改变未迁移的历史浮层。

本地查看使用真实 Eva 业务入口：供应链运营协同的任务详情 → 更多 → 关联父任务，以及项目文件/文件库中的标签编辑和删除操作。不再维护独立演示页。
验证：`node --test tests/ui-theme.test.mjs tests/browser/ui-theme.mjs`。公共 Modal/Form 回归仍由原有浏览器测试负责。

### 焦点与文案依据

- 焦点与语义参考 [W3C APG Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 与 [Tooltip](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)。Popover/Popconfirm 不是阻断整个页面的 Modal，不标记 `aria-modal=true`。仅展示信息的 hover 浮层保留触发器焦点，同时支持键盘聚焦触发；含交互内容使用 click/custom dialog，不以 tooltip 承载可操作控件。
- Popconfirm 通过原生 cancelButtonProps.autoFocus 默认聚焦取消，保留 Tab/Shift+Tab、Escape 和关闭返回触发器；业务可以使用原生按钮参数选择其他合理初始目标。Popover 的 click/custom 默认通过 Semi initialFocusRef 聚焦首个可用字段，跳过隐藏、禁用和 inert 内容；无字段时选择可用按钮，再回退到内容容器。阅读内容可传 initialFocus="content"，业务也可以提供目标函数或原生 initialFocusRef。可访问名优先绑定 title，无标题的复杂内容必须传 aria-label。Semi 缺少外层命名 prop，由公共标签适配一次绑定，不添加新的定位、关闭或焦点陷阱。
- 文案参考 [Ant Design 文案规范](https://ant.design/docs/spec/copywriting-cn.md)：名称前后一致、先表达关键操作及后果、精简重复信息；标题和按钮不加句号，简短独立提示省略无用句末标点，多句说明保留标点。按钮使用实际动作名称；示例使用“移出群聊”，业务词语不写入公共组件默认值。警示图标保留，不用文案中的感叹号反复制造紧张感。

### Popover 内的提交表单

需要保存／取消的轻量浮层统一使用公共 `FloatingForm`，它组合 Semi Form 与内部操作区，操作区不单独导出。Popover 管外壳内边距；字段本身不提供外侧 padding，组合通过布局 gap 统一提供字段之间的间距；按钮区独占最后的 20px 默认表单项目间距。错误或帮助内容位于字段之后时仍按同一字段边界处理，其自身说明间距保留。业务不得另设字段底部留白或再拼一行按钮。Modal 继续使用 Dialog/Form/Actions，不改为轻量浮层组合。

当前调用：文件标签编辑、关联父任务。回归见 `tests/browser/business-overlays.mjs` 与 `tests/browser/file-tags-form-migration.mjs`，其中直接测量标题到首字段标签的 4px、选择框到按钮的 20px 距离。

### 浮层共享行为边界

- `063-floating-focus.js` 统一处理关闭后的焦点返回，支持受控浮层；入口会消失时传 `returnFocus={() => 后续入口元素}`。点击外部可操作内容不抢回焦点。业务不得再用 onCancel/onEscKeyDown 或卸载 effect 重复调用 focus。
- `description` 默认关闭；简单短说明可显式开启 aria-describedby，复杂表单或多段结构不整块朗读。无标题必须提供明确 aria-label。
- Popconfirm 统一等待 onConfirm 返回的 Promise；同步异常和异步失败显示公共错误提示，保留浮层以便重试。处理中阻止重复确认，关闭后忽略旧结果对当前浮层的影响。业务仍负责实际数据事务；关闭不等于撤销已经发出的请求。异步业务需要后续 UI 操作时，使用 onConfirm 第二参数的 isCurrent() 判断是否仍属当前打开周期。
- FloatingForm 提供 disabled 与 busy；取消仍可用。业务只声明权限状态，不重画禁用或 loading 样式。
- 内容宽度受视口限制，高度扣除客户端标题栏与边缘空间，长内容通过浮层内部滚动到达末尾操作；不固定普通短内容高度。定位、Tab 导航和 Portal 继续由 Semi 管理。
- FloatingForm 自身拥有主题，不依赖 Popover 祖先。嵌套字段组使用公共 FloatingForm.Fields；帮助说明用原生 extraText、错误用原生字段错误或 SubmissionError。隐藏字段不占布局 gap。自定义横向布局或 Form.Section 不是可任意叠加的透明容器，新增结构须补充几何测试。

行为回归：`node --test tests/browser/floating-policy.mjs`；同时运行现有主题和业务浮层测试，不能仅凭适配器单测宣称所有业务入口验收完成。

### Popover 表单与 Popconfirm 的尺寸区别

Arco 的 Popover 只定义标题及内容容器，不自带按钮区。其内表单按默认 Form/Button 规格组合：标签 14px/400，标签到控件 8px，控件和按钮 32px 高，按钮文字 14px、水平 padding 15px，表单项目间距 20px。FloatingForm 将这些值映射到 Semi 官方 Form Sass 参数及 Button props，统一维护；不是声称 Arco 提供了独立的 Popover 表单模板。标题到内容仍为 Popover 原生 4px，容器留白为上下12px、左右16px。

Popconfirm 源码明确使用 mini 按钮，继续保持 24px 高、12px 字、水平 padding 11px，说明到按钮16px。禁止把这一规格复用于填写后保存的表单。按钮相互间距均为8px。Eva 的颜色、圆角及字体家族保持原有主题；已确认的 Modal 表单规格不在本轮变更。

核对来源：[Popover tokens](https://github.com/arco-design/arco-design/blob/main/components/Popover/style/token.less)、[Form tokens](https://github.com/arco-design/arco-design/blob/main/components/Form/style/token.less)、[Button tokens](https://github.com/arco-design/arco-design/blob/main/components/Button/style/token.less)、[Popconfirm 实现](https://github.com/arco-design/arco-design/blob/main/components/Popconfirm/index.tsx)。

### 组合约束与现有用法核查（2026-10-10）

`063-ui-theme.js` 的 composition 按语义区分 form / confirmation；FloatingForm.Fields、FloatingForm 和 Popconfirm 分别消费对应规格。浮层位置不决定按钮规格。表单自动生成 id 并关联内部提交按钮，业务可传已有 id。Semi 继续拥有字段、帮助、错误和校验行为。

现有公共浮层调用：文件标签（项目、文件库、详情入口共用）、个人对话删除、文件永久删除。文件标签统一 FloatingForm，删除类统一 Popconfirm；关联父任务按《会话内项目任务规范》改为公共 Dialog 内的即时搜索选择器；未发现业务单独调用 FloatingActions，故移除该公共出口。文件标签的帮助说明迁入 extraText，不再在浮层内借用文件库页面的段落间距。标准 Modal 保留已有 Dialog/Form/Actions 和现有14场景间距矩阵；群资料行内编辑和转发子区内联创建的 compact Actions 保留既有行为。Octo 选择器、历史运行时和非提交浮层不视为已迁移，不能用此次核查声称全仓库任意组合均受保护。

构建检查拒绝业务重新设置字段 padding/margin/fontSize/fontWeight，拒绝单独拼 FloatingActions；允许 display:none 等真实字段可见性配置。该检查针对当前显式调用写法，是辅助护栏，不声称能识别任意动态 CSS。浏览器矩阵验证实际字号、控件尺寸、首尾/字段间距、隐藏字段、嵌套 FloatingForm.Fields、帮助信息、错误重试和提交关联；未来新增组合应补代表结构，而不是补页面特例。

### 官方依据与 Eva 组合约定的边界

Semi 的 [Form 设计指南](https://semi.design/design/zh-CN/input/form)规定字段标签、帮助、校验与分组职责；[Space](https://semi.design/zh-CN/basic/space)负责组件之间的间距；[Tokens](https://semi.design/zh-CN/basic/tokens)提供统一视觉参数。这些能力不代表任意嵌套会自动抵消外边距。Arco 的 Popover、Form、Button 参数分别参考上方官方源码；把它们组合成填写型浮层，以及字段外距归零、由布局 gap 单独负责相邻距离，是 Eva 的组合约定，并非官方提供的完整模板。

嵌套字段组只通过 `FloatingForm.Fields` 使用；它要求 FloatingForm 上下文，禁止作为普通 Modal/Form 的通用布局出口。现有 Modal 的14场景矩阵只验证已接入模板，不保证任意 Card/Section 嵌套。Card 与自由文本仍需使用其各自正式接入的组件规格，不能声称本轮已经覆盖。

### Token 与组件参数的维护边界

圆角、语义颜色、常用间距与字重引用既有 Eva token；不为同一设计决定复制数值。组件专属宽度、图标尺寸、按钮几何、零值及字体文件字重声明可以保留原参数，不以消灭所有 px 为目标。字号仍由公共 typography 表管理，不能在仍追加 px 的消费者中机械换入 CSS var。

不同角色继续不同：普通成员窗引用 window 圆角，单选转让窗及选择器引用 panel 圆角，不因 token 化改成同一个值。未使用的配置删除，不为它建立新 token。主题回归同时验证默认外观和运行时 token 联动；本轮不引入密度切换功能。

## Eva 自有抽屉动效

公共动效适配层 `prototype/008-gds-tokens.css` 定义 `--eva-drawer-duration` 与 `--eva-drawer-easing`。任务详情抽屉的进退场引用这两个 token，关闭卸载读取同一时长；方向和位移由组件管理。保持现有滑动效果，不给原本无滑动的聊天侧栏新增动画，不覆盖 Semi 或 Octo 原生动效。

## Semi 默认动效

除下述明确例外外，所有 Semi 组件的过渡行为沿用锁定版本的原生默认值。业务入口不显式开关 `motion`，不覆盖原生动画时长、曲线或动画类；不因为入口不同而分别关闭 Popover、Popconfirm、Dropdown 等组件的动效。Eva 自有抽屉、视图切换和 Octo 业务组件仍遵循各自合同，不纳入 Semi 默认策略。

普通浮层关闭时用原生 `visible` 驱动，需要销毁业务宿主时由 Semi `afterClose` 清理；退出期间保留原内容，不用自定义定时器等待动画。路由离开、目标被删除等上下文失效情形立即清理，不能为播放退场留下无主浮层。

用户明确的产品例外：身份信息卡不使用过渡动画，`009-3-identity-card.js` 的 Popover 保留 `motion:false`，打开与关闭直接完成；头像裁切 Modal 等其他组件保持原行为。

现有功能例外为共享表单实例的 Select：`063-forms.jsx` 保留 `Select: {motion: false}`。Semi 2.103.0 的受控单选将变更回调延至 Popover 关闭完成；动画期间立即保存可能读到旧字段值。遵循《表单统一规范》的立即提交合同，待此时序问题解决后再恢复默认；文件标签不重复设置局部开关。

验证：`tests/browser/semi-motion.mjs` 检查实际文件菜单、标签编辑、删除确认的原生进退场，以及身份卡无过渡、关闭后焦点返回；同时执行相关业务与表单回归。

### Checkbox 悬停回归

Checkbox 的边框、选中填充、半选和禁用态沿用原生 Semi 与现有语义 token。历史兼容样式中引用未定义 `--wk-color-theme` 的两条全局 Checkbox hover 覆盖已删除；不得恢复该覆盖或在表格、筛选等业务入口增加局部补丁抵消。未定义 CSS 变量会令整个 box-shadow/background 声明失效，不会自动回退到前一条规则。

`tests/browser/checkbox-states.mjs` 使用完整构建样式验证任务筛选、表格、成员选择器的实际悬停与键盘交互，并验证亮暗、半选、禁用与卡片形态；已纳入 `npm run test:buttons`。诊断其他原生或 Octo 复选控件时应先确认实现归属，不批量覆盖所有 checkbox。

### 交互型复选框统一入口

产品自行提供的选择控件使用原生 Semi Checkbox；公共出口为 `063-forms-entry.jsx` 的 `Checkbox`，直接导出、不额外绘制 CSS。IM 消息多选、转发对象与发送目标、聊天记录发送人筛选，以及旧页面授权选项和显示已归档控件均沿用各自业务状态，只替换选择控件。原有任务、表格和成员选择器继续使用 Semi。Markdown 正文渲染的只读任务清单不属于交互选择控件，不在此迁移范围。

非 React 页面通过原生页面宿主 services.mountCheckbox 接入同一 React 渲染器及公共组件，页面/弹窗负责调用返回的卸载函数；不使用 Observer 扫描替换 input，也不创建第二套选择状态。行容器只承担布局与业务点击，不嵌套 label；点击控件不重复触发行切换，空格键由 Semi 原生处理。

### 任务详情面包屑

`063-task-breadcrumb.jsx` 通过公共表单组件出口提供 Semi Breadcrumb，使用 Eva 公共 body 字体参数、语义颜色与字重，保留调用方 Lucide ChevronRight。关闭自动折叠，完整路径在独立容器内滚动；首次打开直接定位；原位切换任务通过当前详情导航链传递滚动位置，从原位置平滑定位不可见的目标，目标已可见时不滚动。关闭详情后重置导航链；减少动态效果时直接定位。不抢键盘焦点、不周期性纠正用户滚动。其余 Breadcrumb 参数沿用 Semi 默认值。

返回祖先任务且目标不可见时，面包屑暂时保留原路径的后续层级作为不可操作的过渡内容；原生滚动到目标后再移除，避免滚动范围提前收缩。目标已完整可见或减少动态效果时直接收起后续层级。过渡随组件卸载、用户滚动或操作取消，不保留旧任务回调。
## Notification 公共通知

业务从 `063-forms-entry.jsx` 的 `Notification`（旧运行时 `forms.Notification`）调用 `open / success / info / warning / error / close / destroyAll`，原生 title/content/position/duration 等参数直接透传。Semi 唯一管理通知列表、计时器、Portal、相同 id 更新、关闭及悬停暂停。

`063-ui-theme.js` 的 notificationTheme 和 notificationLayout 将颜色、圆角、字重及间距映射至现有 Eva token，通过官方 Sass 参数编译。标题、正文与操作文字复用 Form/Modal 的公共 typography；Semi 未提供组件级字号与行高参数，因此由同一主题构建器生成限定于 `.eva-notification` 的文字样式。字体与投影读取 Eva 公共 token。标题到正文、正文到操作均使用 `--eva-space-2`。这些是 Eva 主题配置，不称为 Semi 默认。

公共通知不统一固定宽度；任务创建继续通过原生 style 设置宽度 350px，正文自然换行、不截断。Semi 原生图标、关闭按钮、定位、动画、默认 3 秒及悬停暂停保持不变；位置由业务传入，任务创建用 bottomRight。

链接操作按官方推荐，在 content 中组合公共导出的 Typography.Text link；可用原生 Space 排列说明与操作。第三行操作仅用可点击文字，不加图标。不提供另一个 actions 参数或固定三行模板。公共组件不预设第二行内容；任务创建使用“任务编号 任务标题”，以一个空格分隔，不追加状态或重复“已创建”。

成功反馈使用 Semi 原生成功状态图标；其他状态保留 Lucide 图标。关闭按钮及关闭图标均保留 Semi 原生实现，不进行替换。

任务业务统一调用公共出口 `notifyTaskCreated`：成功保存后显示「已创建任务」，第二行为「任务编号 任务标题」，第三行为「查看任务 / 转发」。项目、看板列、子任务与会话创建共用此入口，不重复弹 Toast。查看使用项目和任务稳定 ID；转发复用现有 IM 目标选择面板，用户确认后才投递任务链接，可附带留言，不自动发送或启动 AI。点击和发送时重新校验当前账号、源项目与任务，目标发送权限沿用消息数据层。

验证使用 `tests/notification-theme.test.mjs`、`tests/browser/notification-theme.mjs` 和 `tests/browser/task-created-notification.mjs`；组件测试生成临时 `/notification-preview.html`，业务验收从供应链运营协同的真实创建入口开始。

任务创建通知保留官方 title/content 组合方式；视觉参数由 Eva 公共主题统一管理，任务名称使用公共中等字重。

### 客户端更新通知完整流程

2026-10-15 用户体验 Firefox 分离式流程后，明确要求恢复原来的单张右下角通知、进度条和按钮位置。Firefox 只作为文案参考，不再整套照搬其承载方式与操作区。

`063-update-notification.jsx` 全程通过同一 Notification ID、`duration:0` 原位更新，不切去关于面板。设置 → 关于恢复「检查更新」入口，用于检查或重新打开当前阶段；只有「新版变化」使用公共 Dialog。

| 阶段 | 标题 / 内容 | 操作 |
| --- | --- | --- |
| available | 有可用更新；下载最新版 Eva 智能办公系统 {版本号} | 新版变化／下载 |
| downloading | 正在下载更新；进度条；已下载／总大小 | 无；关闭仅收起通知 |
| preparing | 正在应用更新…；不确定进度条 | 无额外按钮 |
| ready | 更新已准备就绪；Eva 智能办公系统 {版本号} 已下载完成，重启后即可完成更新。 | 忽略／更新并重启 |
| error | 下载更新失败；更新未能下载完成，请稍后重试。你可以继续使用当前版本。 | 稍后再试／重新下载 |
| 安装请求中 | 正在重启 Eva 智能办公系统… | 原按钮 loading，禁止重复提交 |
| demo-complete | 演示已完成；明确未执行实际安装或重启 | 完成 |

按钮恢复左对齐，正文到操作区16px，按钮间8px；下载时进度条下8px仅显示下载大小。数值只在 `updateNotificationActions` 维护。用户最新确认：正常更新、已是最新版及演示完成使用绿色 Lucide refresh-cw（--semi-color-success）；检查、下载、校验、解压、安装及权限失败统一使用红色 Lucide circle-alert（--semi-color-danger）。失败恢复后回到绿色更新图标，正文、按钮和关闭按钮保持原样；关闭按钮保留公共 Notification 原生实现。Progress 使用锁定版本原生 Semi 和主题色；无可见百分比，未知大小使用不确定进度。准备阶段不留空操作区。

更新器是版本、进度及阶段的唯一所有者；控制器只管理当前宿主周期的关闭状态、动作锁与错误。关闭只隐藏，不取消下载；已关闭版本的后续进度和就绪不自动重开，主动检查才重新显示，新版本可再次提示。用户开始下载后不提供取消操作，关闭通知仍持续下载。100% 不等于就绪，收到 ready 后才允许重启。下载和安装失败在原卡恢复；旧请求失败不能覆盖新阶段、新版本或卸载后的状态。路由切换不卸载唯一宿主。

接口 `window.EvaDesktopUpdates`：`getSnapshot()` 返回 `{status,version,percent?,transferred?,total?}`；`subscribe(listener)` 返回卸载函数；`check()` 检查但不自动下载；`download(version)` 启动下载；`install(version)` 请求安装重启；`openChangelog(version)` 打开日志。原卡的“重新下载”作为重试动作属于 Eva 流程，不能声称与 Firefox 的手动下载链接行为完全相同。

演示目标版本2.0.28。默认进入原型即显示 available 通知，用户点击下载才开始；设置检查可重新打开当前阶段；下载、准备和安装均为计时模拟。`?updateDemo=available` / ready 快速查看；download-error / install-error 演示失败恢复。模拟结束明确未实际安装或重启，不刷新或写产品业务数据。真实下载、安装及系统权限不在本原型内。

文案参考 [Firefox 通知中文资源](https://github.com/mozilla-l10n/firefox-l10n/blob/main/zh-CN/browser/browser/appMenuNotifications.ftl)与[关于状态中文资源](https://github.com/mozilla-l10n/firefox-l10n/blob/main/zh-CN/browser/browser/aboutDialog.ftl)。不保留 Firefox 标签页和窗口恢复的承诺；模拟完成属于原型说明。

验证：`tests/update-notification.test.mjs` 与 `tests/browser/update-notification.mjs` 覆盖单卡状态、持续下载/重试、关闭/重开、迟到结果、卸载、明暗/窄屏、原按钮几何、键盘与跨路由。用户亲自验收并明确同意前不合并 main。

### 文档编辑基础控件

公共出口 `063-forms-entry.jsx` 导出锁定版本原生 Semi TextArea，与 Checkbox、Breadcrumb 一样消费现有全局 Semi/Eva 语义映射，不建立另一份组件库实例。TextArea 的输入、组合输入和校验状态由 Semi 管理。业务仅选择原生 type/size/rows/resize、传入公共 typography 和布局，不重写控件内部结构或交互态。

协作说明有权限直接编辑，无权限直接阅读，不提供编辑/预览切换；正文使用公共 body 字体参数与 Eva 字族，辅助文字使用 auxiliary；表面消费 Eva 主表面，明暗随既有 token 切换。保存事务与权限仍属于共享 GroupMdEditor。

父任务搜索使用公共出口 Input（锁定版本原生 Semi Input），消费现有搜索样式；任务行复用公共 Button、typography 与任务状态图形，不增加第二份 Semi 实例或主题。

更新失败演示：仅原型模拟源在设置「检查更新」按钮下提供「演示更新失败」，点击打开故障场景选择。一般失败直接展示；断网、超时与空间不足在48%中断；校验与解压在下载完成后的准备阶段失败；权限不足展示等待重新安装。故障原因由更新源 failure 字段提供，未知原因不猜测。重新下载从零开始；权限问题重试复用已下载包。模拟重试视为外部问题已解决，不代表真实网络恢复或获得权限。下载、准备与重启请求中禁用此入口，避免中止进行中的更新。接入真实更新源时不显示演示入口。错误分类参考 Sparkle 官方中文资源；本例不在无诊断依据时断言网络断开。
