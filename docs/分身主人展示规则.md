# 分身身份与所属人展示规则

2026-09-09 用户确认，覆盖此前多分身、自定义名称／头像和灰色 `@主人` 的规则。

- 每位真人可以没有分身，最多一个。名称由稳定 ownerId 对应的真人姓名推导为「xxx的 AI 分身」，不可独立修改；统一使用既有 Eva Logo，不允许更改头像。
- 公共名称与头像分别调用 `EvaAIIdentity.cloneName(owner)`、`cloneAppearance(owner)`，头像仍由 `EvaAIIdentity.avatar` 渲染。单张圆形主图、不加主人角标。
- 人类与 AI 仍是独立身份；不改变项目访问权限、添加成员规则和 AI 发言触发条件。个人助理、数字员工、项目管家不适用本次单分身限制。

| 入口 | 展示 |
| --- | --- |
| 会话标题、消息署名 | 固定分身名＋公共 AI 标，移除灰色 `@主人` |
| 添加成员、群／项目成员、提及候选 | 固定头像＋分身名＋AI 标，不再显示主人第二行 |
| 紧凑会话列表、头像网格、已选标签 | 同一公共身份，不重复所属人 |
| 身份资料卡 | 保留可点击的「所属人：姓名」及真人头像，可以进入真人资料并返回 |
| 正文提及 | 仍是真实的 `@xxx的 AI 分身`，不额外提及所属真人 |
| 输入提示 | 继续使用 `evaIMPlaceholder`，不追加所属人 |

`ownerLabel` 仅负责资料卡的所属人文本；标题、消息、候选中的调用和专用 CSS 已退出。资料卡解析、历史消息和结构化提及按身份 ID 读取，不通过名字猜测归属。

## 旧数据兼容

- 我的 AI 保留原 `persona-initial`（没有时保留首个分身）作为唯一身份；额外身份建立 ID 别名，旧会话的 ID、消息与会话草稿保留。
- 额外身份的未发送草稿分别恢复为该分身下的「未发送草稿」会话，不覆盖主分身草稿；旧配置备份在本地业务状态中，不作为另一可用分身。
- 成员数据按稳定 ownerId 合并多分身，保留原有项目／群成员关系和角色关系，不给其他真人增加访问权限。旧链接仍可解析所属人的唯一分身。
- 配置保存及来源同步均不接受分身改名或自定义头像；并发创建也只能成功一次。
- 所有数据仍为浏览器本地原型数据，本次没有扩大 Supabase 职责。
