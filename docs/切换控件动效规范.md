# 切换控件动效规范

本规范只用于明确的视图切换器，不根据 `role="tab"`、选中背景或横向排列自动判断适用范围。用户确认：弹窗内默认出现的选项、查询分类与筛选不能全套使用滑动动画。

## 适用范围

当前仅接入以下明确切换器：

| 入口 | 切换内容 |
| --- | --- |
| 我的消息：关注／最近 | 两种会话列表视图 |
| 项目任务：看板／列表／层级 | 同一任务集合的展示方式 |
| 个人自动化：定时任务／运行记录 | 任务管理与运行历史视图 |

以下入口保留原有反馈，不接入本规范的滑动选中背景或指示线：子区管理状态选项、聊天搜索的全部／消息／图片视频／文件、查询筛选、连接中心分类、技能来源选项、AI 配置与创建表单页签、项目导航页签、一级导航、下拉选择、开关、树展开和排序拖拽。它们存在选中态，不代表就是本规范中的切换器。后续新增入口先判断产品语义，不能批量套用所有 tabs 或按钮。

## 动效合同

- 保留当前外形、颜色、圆角和阴影，同一个选中背景滑向目标项；文字颜色同步过渡。
- **首次打开、挂载或恢复默认选中态时，直接呈现最终位置，不播放切换动画。** 仅用户切换已有控件时播放。
- 业务视图立即切换，不等待动画结束，不新增点击锁、延时或页面整体滑入。
- 快速连续点击从当前位置转向最后目标，不排队、不弹跳。
- 不改变按钮或容器整体高度，不使用缩放；尺寸变化直接适配布局，不当作一次用户切换。
- `prefers-reduced-motion: reduce` 时关闭过渡，直接显示最终状态。

公共 Eva 适配 token 位于 `prototype/008-gds-tokens.css`，不修改客户原始 GDS 包：

| Token | 参数 |
| --- | --- |
| `--eva-switch-duration` | 220ms |
| `--eva-switch-easing` | cubic-bezier(.22,1,.36,1) |
| `--eva-switch-color-duration` | 180ms |

## 实现边界

现有等宽切换器使用同一个 CSS 伪元素背景；位置由原 React 选中状态推导。不新增另一份业务选中状态，不使用全局 MutationObserver、捕获点击监听或定时器模拟切换。指示器使用 `pointer-events: none`，不占焦点，不阻挡点击；保留原有键盘、禁用和可见焦点行为。

实现位于 `039-team-message-project-recent.css`、`034-project-task-toolbar-v3.css` 和 `031-shared-automation-v2.css`。禁止全局覆盖 Semi Tabs，禁止使用 `transition: all`，禁止为了统一动画重建表单或选项控件。

## 验收

本地 HTTP 浏览器检查：首次显示没有切换动画；往返切换有中间位移且最终位置正确；快速点击落在最后目标；减少动态效果时即时完成；离开再返回保留原有状态边界。对上述排除入口检查没有新增滑动指示器或全局动画规则。

回归脚本：`tests/browser/switch-motion.mjs`。检查与发布分级遵循 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 最近页群内切换（2026-10-08）

用户确认采用 Telegram 群内切换策略，默认会话命名为「主聊天」，使用 Lucide MessageCircle；子区保留 CornerDownRight，主聊天与子区之间保留竖分隔线。不增加「全部」消息聚合入口。

用户验看后否定自定义滑动效果，确认改用 Semi Tabs。最近页群内导航由 `EvaRecentTopicNavigation` 适配现有 Semi `Tabs`（line、medium、受控 activeKey、collapsible），选中会话仍由 `ChannelsView` 管理。删除自定义指示线、几何测量、ResizeObserver、滚动动画与键盘控制；选中反馈、键盘焦点和溢出滚动使用 Semi 原生实现。聊天流与输入框保持既有内核，`tabPaneMotion` 关闭，页签不另建聊天面板。该入口不套用本规范上方的公共滑动指示器。

范围仅最近页，不接入关注、项目或我的 AI。消息、搜索、转发和权限继续由现有 IM 内核按会话处理。最近页群聊草稿按账号与会话 ID 保存在当前 React 会话组件中；切换主聊天与子区可恢复，发送成功后清除。该补齐不提供刷新后持久化，也不改变私聊与我的 AI 的既有草稿数据源。参考 TelegramSwift `579cebbf0c01fd41b712eff3647fa7f69db9665d` 的 `MonoforumHorizontalView.swift`、`ScrollableSegmentView.swift` 和 `ChatController.swift:6418`；这是已保存的本地源码版本，非最新发行版声明。


### 后续用户确认：补充轻量动效

保留 Semi Tabs 的导航、键盘和溢出能力；通过组件内部 ref 测量受控选中项，单一下划线使用公共 220ms token 移动。首次挂载、尺寸变化及溢出滚动直接定位。切换时仅既有消息流做 120ms 淡入，不重建聊天面板或输入框；快速切换取消前次淡入，减少动态效果时关闭。该决定替代上文“不增加自定义指示线”的限制，仍仅限最近页。

### 子区新消息提醒（2026-10-08）

参考同版本 TelegramSwift `MonoforumHorizontalView.swift:64–115` 与 `ScrollableSegmentView.swift:344–346`：话题文字后带紧凑数字徽标，有未读才显示，未静音用强调色、静音用灰色；选中态不替代消息提醒。Eva 保留自身明暗主题 token 和 99+ 数量上限。用户随后确认使用 Eva 既有浅蓝底、蓝色数字胶囊，直接复用 017 的共享未读徽标样式（16px 高、11px 字号、500 字重），不采用 Telegram 实心蓝底白字。主聊天也能显示自身的计数，左栏父群计数继续汇总主聊天与可见子区。

按用户要求，最近页演示提醒常驻，查看或刷新不消耗预置计数；预置由 `009-3-data-im.js` 的 `__EVA_RECENT_UNREAD_DEMO` 维护，仅限指定供应链会话，不修改真实已读记录和用户静音偏好，不影响关注／项目。正常新增会话无强制提醒。回归为 `tests/browser/recent-topic-unread.mjs`。

### 普通成员创建子区（2026-10-09，本地待验收）

- 最近页的「＋」紧随最后一个子区；横向内容溢出时保留在导航右端，Semi 负责滚动。没有子区时也显示「主聊天」和创建入口。按钮不是页签，不显示选中下划线。
- 新建弹窗只填写名称，说明「本群所有成员均可查看和参与」。主按钮「创建并进入」；成功后选中新子区，父群消息中留下按稳定子区 ID 跳转的创建记录。
- 名称沿用现行 30 字限制，去除首尾空格后在同父群内判重；归档子区也占用名称，不允许使用保留名「主聊天」。不同父群可同名。重复时提供打开已有子区的入口，不引入相似名称推荐。
- 每位有效人类群成员可创建。重命名、归档和恢复限创建者或实际群管理员；项目管理员身份本身不授予普通群治理权。所有访问与成员资格仍继承父群。
- 右键导航项不改变当前会话，提供消息提醒、复制链接及有权限的治理操作；主聊天只提供个人提醒和聊天链接。子区列表的「…」复用同一组操作，并保留已发布的置顶、隐藏能力。
- 本轮不修改关注／项目的布局，不另建聊天、搜索或转发实现。AI 的上下文隔离是产品语义与演示场景，原型没有接入真实模型上下文组装。

### 长子区名称（2026-10-09）

本地 TelegramSwift `579cebbf0c01fd41b712eff3647fa7f69db9665d` 中，`MonoforumHorizontalView.swift` 和 `packages/TGUIKit/Sources/ScrollableSegmentView.swift` 使用无限可用宽度测量标题，单项宽度为文字、图标、徽标和留白之和；整行由 `HorizontalScrollView` 承载，选中项自动滚到可见区域，并没有统一定宽省略。

Eva 沿用自然宽度、单行、完整显示优先及横向滚动。桌面内容区较窄时，仅对宽于整个可用滚动区域的单个标签做文字省略，图标与未读徽标不压缩，「＋」保持可见；不缩字号、不折成两行、不增加 Tooltip。子区信息的「子区名称」保留完整文字和换行。多子区演示的最后一个标签使用接近 30 字的名称，覆盖宽／窄窗口、未读与新建入口的组合状态。

### 子区免打扰（2026-10-09 用户确认）

最近页横向子区导航的右键菜单复用会话列表的「设为免打扰／取消免打扰」文案与图标，与信息面板共用 conversationMuted 和聊天偏好。普通子区使用主要文字色；免打扰子区标题与图标使用次级灰色，排列在未免打扰子区之后，各组内部保留原排序；取消后回到原排序。主聊天始终位于首位。切换免打扰不切换当前会话、不清空草稿，当前子区移动后仍保持可见和选中下划线。

### 最近页子区导航收敛（2026-10-09，替代本轮早期滚动折叠方案）

主聊天固定首位，按可用宽度显示完整子区标签，其余通过右侧子区列表选择；不显示滚动箭头或重复溢出菜单。新建与列表组成固定右侧操作组，组前一条分割线。选中收起的子区后，将其纳入可见末位，不写回业务排序；单个极长名称在可用宽度内省略。

最近页复用 EvaThreadList 的 compact 配置，由 Semi Popover 锚定列表按钮下方：搜索当前分类子区、活跃／隐藏／归档、未读与免打扰、每行操作菜单；隐藏消息摘要、日期、回复数及重复创建按钮。选择后关闭，Escape／点击外部关闭。关注和项目仍使用原抽屉。查询与分类状态随浮层关闭重置，浮层开关由当前导航组件持有，不复用右侧面板状态。

2026-10-09 后续确认：横栏未展示的子区以紧随标签的「更多 N」提示，N 不包含主聊天、隐藏及归档子区；无溢出时显示「全部子区」。同一入口打开标题为「全部子区」的原 compact 面板，不增加第二套溢出菜单。最右侧仅保留分隔线与新建加号。

### 连续滚动与选中居中（2026-10-09，最新确认）

用户取消“不露半个标签”的限制。最近页保留所有子区的连续横向滚动，边缘允许露出部分标签；主聊天固定左侧，更多／全部子区与新建按钮保持在滚动区域外。选中子区按自身中心对齐扣除主聊天后的可视区域中心，使用平滑滚动并在首尾限位；首次进入、窗口尺寸变化和减少动态效果时直接定位。取消按完整标签挑选可见窗口及布局位移动画。更多数量为当前未完整显示的子区数，仍打开同一 compact 子区面板。

### 子区个人置顶（2026-10-09）

最近页子区右键与列表「…」复用消息列表的个人置顶偏好和「置顶会话／取消置顶」菜单，使用公共 Lucide Pin／PinOff。置顶子区排在主聊天之后、未置顶子区之前；各组内保留免打扰后置及原排序。置顶不改变当前会话或草稿，名称旁展示小号 Pin，未读胶囊与免打扰灰色仍保留。取消置顶后按现有排序恢复。该个人操作不修改全群共享排序，不引入管理员权限限制。

### Telegram 排序与免打扰（2026-10-09，替代免打扰后置）

最近页置顶子区在前并保持已有置顶组顺序；其余子区按最新消息时间倒序，横栏与 compact 列表一致。免打扰不参与排序，也不改变标题文字色，只将未读胶囊变为中性灰；右键沿用设为免打扰／取消免打扰。横栏尾部有未读时展示数字，无未读的置顶项展示 Pin，与 TelegramSwift 的优先级一致。仍保留 Eva 的个人置顶权限、固定主聊天和演示未读常驻，不引入 Telegram 群管理员共享置顶权限模型。

#### 排序与继承的实现验收补齐

- 子区默认继承当前用户对父群的免打扰设置；显式开启或取消后使用子区自己的设置，父群后续变化不覆盖它。数据层以 mute 缺省表示继承，true/false 表示显式覆盖。
- 新置顶项进入置顶组前部，保存个人 pinOrder；后续新消息不改变置顶组内部顺序，取消后按最新消息时间回到普通组。
- 排序统一由 EvaMembership.topicNavigation 提供，仅返回 ID、时间及置顶信息，不复制完整消息；组件按业务 revision 缓存，导航和 compact 面板使用相同顺序。
- 回归：tests/topic-creation.test.mjs、tests/browser/topic-order-mute.mjs、tests/browser/topic-compact-picker.mjs、tests/browser/im-switch-performance.mjs。保留演示计数常驻以及现行个人置顶权限。本轮对齐 Telegram macOS 横向子区右键直接切换免打扰的入口，不把其他通知设置页的声音、定时静音表单搬进横栏右键。
