# 列表留白与操作对齐规范

列表背景行相对所属列表**内容区**的左右外留白必须一致。它是布局合同，不要求行内左右 padding 相同，也不将滚动条算进内容区。

## 计算边界

- 内容区横向可用边界是滚动容器的内侧左边缘至 `clientWidth` 的右边缘，包含列表外留白，排除边框；关注和最近的悬浮滚动条不挤占此宽度。
- 左留白 = 行左边缘 − 内容区左边缘；右留白 = 内容区右边缘 − 行右边缘。
- 两侧差值允许不超过 1 CSS px 的渲染误差。不使用截图的设备像素直接比较。
- 滚动条作为独立区域。禁止为视觉上对齐整个面板给左侧补滚动条空槽，或用 `scrollbar-gutter: stable both-edges` 挤窄列表。用户确认关注和最近使用悬浮滚动条：保留灰色圆角外观与比例长度，叠在右侧边缘，不挤占行宽度。停止滚动或鼠标活动 1.2 秒后自动隐藏；滚动和鼠标活动时显示，拖动中保持可见，结束后重新计时。淡出 150ms，减少动态效果时直接隐藏。

## 内容与操作

层级缩进、头像槽及文字间隔在行内部计算，沿用现行业务规范。父群与子区可以有不同左内边距，但行背景的左右外留白相同。

同一列表中项目入口与群展开按钮使用同一右侧操作中心线。展开图标在按钮内水平、垂直居中。hover、选中、展开或收起不得改变行的横向位置、宽度或右侧按钮中心线。展开按钮保留简单 hover 底色，不增加旋转或过渡特效。

当前消息列表外留白为两侧 10px；按钮对齐由行右内边距 8px 与 32px 操作槽确定。其他列表沿用各自已确认的尺寸，不能为了统一数值改动其产品信息结构。

## 纵向密度：关注列分组留白（2026-09-15 密度稿）

消息「关注」列关注树的纵向节奏按用户确认的密度对比稿取值，限定 `body.eva-message-hierarchy-ready .eva-msg` 关注列，不影响项目群 IM 与我的 AI；行高、字号、颜色沿用既有一致值，不为统一而取平均。

- 分类组之间（`.eva-follow-category` 下外边距）8px。
- 分类标题到其首个频道块（`.eva-follow-category-title` 底外边距）2px；此前为 4px，偏大。
- 连续频道块之间（`.eva-follow-channel + .eva-follow-channel` 上外边距）4px 呼吸感；紧跟项目头的首块不加（相邻兄弟选择器天然满足）。此前组间为 0，属「过密／无呼吸感」。
- 实现位于 `prototype/039-team-message-project-recent.css`，纯 CSS，不改会话数据、分组与信息结构。

## 自动化验收

`npm run test:layout` 在本地 HTTP 构建产物上运行浏览器几何验收，目前覆盖消息关注列表的分组、父群与子区及最近会话行，220／260／480px 中栏，以及有／无滚动溢出与悬浮滚动条、hover、选中、展开／收起。检验实际 `getBoundingClientRect`、`clientWidth` 与按钮图标中心，不只核对 CSS 字面值。

测试还注入一次不对称的容器留白，确认检测器确实能识别偏差，再恢复测试夹具。测试中的滚动条状态仅用于隔离验收，不改变产品样式。新增或修改其他列表时，应按其实际内容容器和行选择器补充测试，不将消息列表通过表述为全项目所有列表已验收。
