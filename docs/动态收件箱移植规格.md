# 任务动态

## 已确认范围（2026-10-16）

用户决定将个人「动态」收窄为「任务动态」，入口置于「我的 Agent」下方，继续使用 Inbox 图标及现有路由。此决定替代此前的跨模块收件箱方案。

只汇集当前账号有权访问、按现行任务订阅规则收到的项目 Loop 任务更新。群聊、私聊、子区、AI 小队及 AI 单聊消息均不进入，包括 IM 中的 @我；消息仍在「我的消息／我的 Agent」阅读。

删除整个「全部／任务／群聊／消息」类型导航，不保留只有“任务”的导航。保留应用侧栏、可调宽任务列表及共享原任务详情。本轮不新增重要性字段、不调整自动订阅、不新增到期提醒。

## 保留行为

- 按任务聚合，置顶优先、最新更新排序；保留任务编号、状态、作者与更新摘要。
- 打开任务或具体事件沿用共享 IssueDetailPage，权限、评论及属性操作不变，不复制详情组件。
- 打开未读任务推进源已读；单任务归档、标记未读、置顶沿用原事务。
- 归档只移出提醒，不完成任务、不删除任务、不退订。归档过程中到达的新事件不在本次范围；新更新会重新出现。已有归档记录仍保留，不删除源任务或事件。
- 操作失败显示真实错误；已成功写回的已读状态不伪造回滚。
- 按用户确认，标题栏只显示「任务动态」，移除设置与三点菜单，底部不补按钮。未读筛选、已归档视图及批量操作不再提供入口；旧未读筛选偏好不生效。任务行三点菜单保留，已归档记录不提供手动恢复入口，新事件仍可重新出现。
- 清除与置顶记录按账号、项目及任务稳定键隔离；旧消息记录不参与任务列表，不清除原消息已读状态。旧消息 context URL 不能打开消息详情。

## 公共呈现与键盘

沿用 Semi List/List.Item、公共 Button、ActionMenu 及共享详情。未读蓝点、标题字重与字色遵循《未读提示公共组件规范》的任务动态例外。

标题按钮以 aria-current 表达当前项。上下、Home/End 移动焦点，Enter/Space 打开，Delete/Backspace 归档；输入区不拦截这些键。归档后聚焦下一项，无下一项则上一项，空列表聚焦区域。菜单键盘行为沿用公共实现。

数据按 store revision 派生；选中和焦点移动不重读来源或重复解析摘要，仅前后选中行更新。原数据变化使缓存失效。

## 数据与配套

任务适配器是任务动态的唯一来源。跨模块消息/AI 适配器、会话分组样式和嵌入详情分支移除。IM 逐事件已读连接独立归入 IM 层，继续读写 membership 原状态；AI 原入口保留自己的会话、草稿与未读体系。

任务详情与任务动态共用任务活动日志、评论的读取入口；任务动态只筛选和聚合原事件，沿用原事件 ID、作者和时间。移除独立演示提醒，不另造提及、复核或任务变化。列表中的字段变更文案直接复用任务详情的同一格式化函数，保留修改前后值，不另写概括文案。长内容沿用单行省略和完整 title，点击或键盘打开可在原详情查看全文；截断只发生在呈现层。已读、归档、置顶仍是独立的阅读元数据，不复制业务内容。

业务仍为本地原型数据，不宣称接入服务端或跨设备同步。

## 验证与交付

自动回归覆盖任务范围、旧消息 URL 隔离、列表性能、任务权限及归档，以及 IM 历史已读、新消息和提及兼容。Edge 检查入口顺序、无类型导航、任务详情、单项归档及我的 Agent／我的消息往返。构建和自动测试不等于用户验收；用户亲自确认前不得合并 main。
