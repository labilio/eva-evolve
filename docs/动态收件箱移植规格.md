## 已确认范围

个人「任务看板」改为「动态」，使用 Lucide Inbox。默认全部跨模块汇集，类型只是可选筛选。以业务对象聚合，而非把每次变化拆成互不相关的任务。左栏使用应用导航，中栏收件箱可调宽，右栏直接使用既有业务内容。颜色、组件、头像、未读提示、权限和数据源全部使用 Eva 现行实现。

这是完整交互迁移，不是静态列表。不得用跳转按钮或详情摘要代替可操作的原业务内容。原项目任务看板继续存在；项目级任务收件箱占位最终接入相同聚合能力。

## 数据与状态边界

业务数据保持唯一来源。聚合器只接受原数据适配器返回的对象与事件引用；不复制任务、聊天、项目或人员。已读状态通过来源适配器写回原未读体系。独立持久化仅保存账号级收件箱清除记录和显示偏好；清除按稳定事件 ID 记录，不能永久屏蔽整个对象或凭时间戳吞掉同一时刻的新消息。

每次读取与写入都重新检查权限。对象键同时包括来源、项目及对象 ID。关闭/清除提醒不完成任务、不归档群聊、不退订、不删除源消息。私聊、群聊、子区、AI 身份与个人 session 保持各自模型，不把 Huly Channel 机械改名成 Eva 子区。

**来源入口订正（2026-10-16）：** 用户截图/URL `/notification/…` 对应 `notification-resources/src/components/inbox/Inbox.svelte`，不是同版本另一个 `inbox-resources/InboxApplication.svelte`。截图中的勾选实际调用 `archiveContextNotifications`，设置通知 `archived:true,isViewed:true` 并推进 `lastViewedTimestamp`；归档筛选可恢复。前期“清除”的实现接口名称保留作为内部名称，产品文案和行为按“归档提醒”实现，不能误用另一个入口的永久删除。隐藏用户名设置只在另一套入口出现，不作为截图版本的迁移要求。

Eva 在源已读写入成功后保存归档元数据；任一步失败均反馈失败并保留提醒，已经成功写回的已读状态不伪造回滚。异步过程中到达的新事件不包含在本次归档范围。恢复仅将提醒移回收件箱，不自动变为未读。归档通知与归档群聊/项目完全独立。

右栏嵌入任务详情是本次用户明确指定的新增宿主；扩展共享详情的宿主配置，保留其他入口现有抽屉、全屏、引用返回和权限语义，不复制详情组件。

## 交付门槛

业务行为测试、适配器集成测试、构建与装配合同、Edge 实际流程逐项通过。现有占位测试随已授权功能升级改为行为断言，不能删掉保护来获得通过。最终报告必须区分自动验证、人工待验收、未合并状态。仅完成聚合器或布局不算完成目标。

### 未读视觉（2026-10-16 用户确认）

动态列表采用 Multica 的蓝点、主标题字重与字色区分；具体规则见《未读提示公共组件规范》的动态列表例外。仍按 Huly 聚合项内实际未读事件判断，不采用 Multica 仅取最新通知 read 状态的算法。归档操作统一为“归档提醒／已归档／恢复提醒”，使用归档盒图标。

### 第一阶段行操作（2026-10-16 用户确认）

每条动态右上角仅保留三点菜单，依次提供「归档」「标记为未读」「置顶」，均配 Lucide 图标，不分组、不设分隔线。已置顶项显示「取消置顶」；已归档视图提供「恢复提醒」。标记为未读始终执行未读操作，不随当前状态改成已读按钮。置顶只调整本人动态列表顺序，不修改源任务或会话；置顶项在前，各自仍按更新时间排序，取消后回到时间顺序。置顶按账号及对象稳定键持久化，归档仍移出当前列表，恢复保留置顶偏好。此为用户对原 Huly 行操作布局的明确调整。

### Semi List 与键盘焦点（2026-10-16）

中栏使用锁定版本 Semi List/List.Item，通过公共主题入口直接导出原生组件；标题和摘要使用公共 Semi Button，操作使用公共 ActionMenu 的原生 click Dropdown 模式。普通列表不使用 listbox/option 承载交互子元素，当前打开项以 aria-current 表达，类型筛选为带 aria-pressed 的按钮组。Tab 按阅读顺序到达标题、菜单和摘要；标题上的上下/Home/End 保留既有快捷移动，Enter/Space 由按钮默认行为打开，不将移动焦点自动当作阅读。

依据 W3C APG Keyboard Interface、Menu Button 和 Menu and Menubar：菜单 Enter/Space 打开并聚焦第一项、上下键移动、Escape 返回触发器使用 Semi 原生实现；原生缺失的 Tab/Shift+Tab 退出由公共菜单适配补齐，关闭后进入触发器相邻控件。归档/恢复移除当前项后，聚焦下一项标题，无下一项则上一项，空列表聚焦有名称的区域。焦点显示沿用 Semi/浏览器默认样式，选中背景独立。未规定的尺寸、动画和交互参数沿用 Semi 默认。

参考：https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/ 、https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/ 、https://www.w3.org/WAI/ARIA/apg/patterns/menubar/ 。

### 列表切换性能（2026-10-16）

焦点由实际标题按钮维护，不因 focus 触发整页状态更新。数据聚合按原 store revision 与归档视图更新；选中项和类型筛选不重读全部来源，原数据订阅变化仍使派生结果失效。摘要按本轮列表数据解析一次；Semi List.Item 的组合行按对象引用和选中态复用，仅选中切换时更新前后两行。操作回调读取当前已提交页面的处理器，避免行复用后使用过期筛选或选择状态；归档后的焦点恢复保留独立请求。

`tests/activity-render-performance.test.mjs` 验证选中/键盘移动不重复读取来源或解析摘要、仅前后选中行更新，以及源更新后的改名/删除立即反映。原来源权限与归档测试保持不变。Edge 本地 4215 两次同数字员工会话切换从点击到后续绘制约 28–30ms（双 requestAnimationFrame 采样，不是所有入口耗时承诺）；采样日志已从产品代码移除。

### 同对象预览署名（2026-10-16 用户确认）

AI 单聊 session 的预览作者稳定 ID 与上方身份 ID 相同，省略该条预览重复的头像、姓名及 AI 标，保留正文与时间。不同作者、任务更新、群聊及 AI 小队继续显示原署名。不得按姓名字符串判断同一身份；此调整仅作用于动态摘要，不改变右侧原始消息署名或 session 聚合。

### 消息聚合与排版调整（2026-10-16 用户确认）

任务保留原对象标题与多条更新摘要。个人 AI 单聊按稳定身份 ID 形成外层分组，同名不同 ID 不合并；身份名称只显示一次，下方各 session 保留标题、一条最新预览、时间与独立三点菜单。群聊主聊天、每个子区及 AI 小队仍按原会话独立聚合，不进一步合到父群。类型筛选先筛具体条目再分组，不制造空组。

这是显示层分组，session 的通知键、已读、归档、恢复、置顶和右侧打开目标保持独立。组的位置由组内最靠前的条目决定（置顶优先，其次最新时间），组内保持相同排序。归档一个 session 不归档同身份其他 session；方向键及移除后的焦点按实际显示顺序移动。组标题不设置批量操作。

排版使用原生 Semi 嵌套 List：外层身份标题、内层紧凑 session 行；组内去掉重复身份元数据和预览引用竖线，标题和预览左对齐，菜单与时间右对齐，当前 session 单独显示选中背景。任务、群聊与子区继续保留原更新列表。

组内相邻 session 之间使用浅色短分割线，左端与 session 文字起点对齐、右端与内容右边缘对齐；组间保留原分割线，标题与预览之间不加线，最后一项不重复加线。

### 真人私聊、群聊与子区的紧凑条目（2026-10-16）

团队会话来源移除独立的“消息／群聊”类型文字行，改为会话图标与名称同排，下方仅展示一条最新预览。真人私聊不重复预览作者；群聊和子区保留作者身份。预览为 12px 次级文字并紧贴标题，取消引用竖线，时间仍右对齐。标题/摘要点击与三点菜单保持原目标和操作；任务及个人 AI 分组不在此次调整范围。
