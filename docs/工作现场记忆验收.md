# 工作现场记忆（2026-10-14 原型）

本轮按用户决定保留工作现场，范围是个人 Eva、团队消息、我的 AI 的聊天与中栏，以及任务页已有的视图偏好。仅使用当前浏览器本地存储；刷新、关闭再打开同一地址可以恢复，不接入后端或跨设备同步。原先“离开页面重置展开状态”的约定由本轮决定取代。菜单、弹窗、悬停、消息多选等临时操作不恢复。

## 状态合同

| 状态 | 唯一所有者与恢复边界 |
| --- | --- |
| 文字草稿 | 个人 Eva / 团队 / 我的 AI 各自已有数据仓；按会话、父群和子区隔离。成功发送才清空。 |
| 当前会话与子区 | 页面自身的选择控制器保存检查点，进入时验证对象仍可访问。明确的 URL 指定优先。个人 Eva 侧栏入口导航到最后的有效会话，`/guid` 仍明确表示新对话。 |
| 聊天滚动 | 当前会话的消息流；阅读历史时恢复位置，原先在底部时跟随底部。明确跳转某条消息优先。子区侧栏和完整子区共用同一记录。 |
| 中栏滚动 | 当前入口的实际滚动列表，团队按关注/最近及提醒筛选隔离。 |
| 待发送引用 | 统一 IM 按会话记录真实消息引用；切走保留，取消或成功发送清除。恢复不重复插入 @，不抢焦点。个人 Eva 沿用现有能力，不新造引用入口。 |
| 输入光标/选区 | 当前会话输入组件保存文本偏移与输入区内滚动，恢复不主动抢焦点，保留正常全选、编辑和清空。 |
| 展开/收起 | 个人文件夹由 EvaPersonal 管理；团队与我的 AI 由各自列表组件管理。首次仍沿用既有默认值，操作后记忆。 |
| 筛选、排序、视图 | 团队和我的 AI 的提醒筛选、关注/最近由入口组件管理；任务页沿用已有偏好存储，不另建一份。 |
| 待发送附件 | 本轮是仓库内的示例 Markdown 附件，按会话记忆；移除或发送后清空。没有实现真实本地文件上传或文件持久化。 |

`EvaWorkspaceMemory` 只提供 UI 检查点的读写和输入/滚动绑定，不接管路由、消息、权限或页面生命周期。团队状态按当前账号隔离；恢复选择仍通过现有可访问会话源。

## 五分钟演示路径

演示数据只初始化一次，后续不覆盖你修改或清空的内容。示例沿用「供应链运营协同」项目和已有会话、成员。

1. **我的消息 → 最近 → 采购与招投标**：默认有“采购周会草稿”、一份「供应链周会核对清单.md」和待回复消息。先观察草稿和附件，点击文字中间或选中一段，向上滚动，然后切到 Eva 同学再回来；刷新再检查一次。
2. **同一采购群 → 任一子区**：写一段不同的草稿，点回形针添加示例附件；切到其他页面再回来，应仍在该子区。回到主聊天，主聊天的草稿不受影响。
3. **中栏**：切换关注/最近或未读筛选，展开/收起一组；列表足够长时滚动到中间。切走、返回、刷新，检查对应状态。筛选可能因消息已读而没有结果，这是原有筛选语义。
4. **Eva 同学 → 核对供应商交期风险**：另有一份个人草稿和相同示例附件。收起一个文件夹，切到我的消息，再点左侧 Eva 同学，应回到此会话并保留草稿、附件和文件夹状态。
5. **Agent → 我的 AI 小队**：填写草稿、添加示例附件，切换身份分组的展开状态；切走、返回、刷新。选择不同会话时草稿互不串联。
6. **发送或移除**：发送当前草稿后，该会话文字、引用、附件清空；刷新不会再次自动补回 mock。其他会话草稿不清除。
7. **任务看板**：在供应链运营协同切换已有列表/看板视图、排序和筛选，刷新确认原有偏好恢复。

示例附件内容见 [供应链周会核对清单](../prototype/fixtures/supply-resume-checklist.md)。

## 本地自动化

构建后运行 `node tests/browser/chat-drafts.mjs` 和 `node tests/browser/workspace-memory.mjs`。测试使用独立 Edge 上下文，不清理人工评审浏览器的状态。单元测试覆盖按账号/会话隔离、重载、清空、一次性初始化和滚动恢复。人工验收通过前不合并 main。
