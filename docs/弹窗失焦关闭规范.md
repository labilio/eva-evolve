# 弹窗失焦关闭规范与浮层清单

适用范围：Eva 原型中所有「临时浮出的操作表面」——右键菜单、点击触发的下拉与选择器、
可展开的浮出面板、抽屉式详情、对话框。规范要求：**在浮层打开状态下点击内容区空白处即收起**。
浮层自身的开关状态仍由各自业务入口拥有，本规范只统一「判定外部点击并收起」这件事。

系统标题栏（`.topbar`）属于客户端窗口外壳，不参与本规范，且任何浮层都不得遮挡它。

## 唯一实现

`prototype/004-popup-dismiss.js` 是全站唯一的失焦关闭控制器，导出 `window.EvaPopupDismiss.watch`：

```js
window.EvaPopupDismiss.watch({
  id: '入口标识',
  isOpen: () => boolean,        // 该入口当前是否打开
  keep: () => Element | NodeList, // 点在这些元素内不算「外部」（浮层本体、触发按钮、所属输入区）
  token: () => any,             // 当前打开实例的标识（可选，用于避免误关刚打开的另一实例）
  close: () => void             // 由入口自己实现关闭
});
```

实现要点：

- 只有一个 `document` 级 `pointerdown` 捕获监听器；入口不得再各写一套 document 监听器。
- 只处理主键；右键由 `contextmenu` 自己打开，拖拽滚动条不应收起浮层。
- 关闭动作统一延后到本次点击处理完之后执行。入口的 `close()` 常会重绘宿主 DOM，
  若在捕获阶段同步重绘，本次点击后续的委托处理器会拿到已脱离文档的目标节点，
  把「点另一行打开它的菜单」误判成什么都没点。延后执行前用 `token` 复检，
  保证不会关掉这次点击刚刚打开的另一个实例。
- 入口的 `keep` 必须包含触发按钮：这样「再次点击触发按钮」仍由入口自己的 toggle 决定，
  不会出现「先被外部判定关闭、又被 toggle 打开」的抖动。

## 已确认：设置对话框点遮罩关闭

设置对话框（`.eva-settings-dialog`）原先在 `tests/browser/settings-dialog-shell.mjs` 里被断言为
「蒙层不可点关（`maskClosable:false`），弹窗仍开着」。用户已确认：**按统一规则，点遮罩应关闭**。
因此该弹窗保持 `maskClosable:true`，并把原用例的断言改为验证新行为：点击顶栏坐标后弹窗收起，
同时侧栏宽度不变——即点击落在蒙层上而没有穿透到顶栏。
该用例原本要保护的「蒙层盖住整窗、不穿透顶栏」这一条未被削弱，仍需保持通过。

## 回归护栏：本类取舍被并行改动覆盖时必须报错

`maskClosable` 这类「一行之差的产品取舍」很容易在并行分支整合时被静默带回旧值——
Git 只合并文本、不合并意图，不会报冲突。因此 `tests/page-architecture.test.mjs` 里固定了
一条静态断言：成员选择器、转让（接任者）弹窗、设置对话框、定时任务设置弹窗必须保持
`maskClosable:true`，且这几个文件里不得再出现 `maskClosable:false`。
合并他人分支后跑一次 `npm test`，这类静默回退会直接变成红灯，而不是留到验收才被发现。
若确实要改回不可点关，必须同时改这条断言并在本文件说明取舍。

## 例外清单（不适用本规范，附理由）

1. **浏览器原生控件**：如个人页的文件夹选择 `.eva-personal-folder-picker`（原生 `<select>`）、
   各类原生日期／文件选择。开合由浏览器控件本身管理，页面无法也不应接管。
2. **悬停触发的浮层**：如侧栏「更多」导航 `.eva-nav-more-menu`（`trigger:"hover"`）。进入用悬停、
   离开自动收起，本身不存在「打开后停滞」的问题。
3. **系统标题栏**：`.topbar` 是客户端窗口外壳，始终可见，不参与关闭，也不允许被浮层遮挡。
4. **评审批注侧栏**：位于 `review/` 的独立评审工具层，是可拖拽、位置持久化的常驻工具窗口，
   由自身关闭控件收起；批注过程需要在页面上反复浏览与滚动，点页面即收起会打断批注。不改其职责。
5. **列表行内联表单**：如个人页的新建／重命名文件夹表单（`.eva-personal-rail-form`）。
   它是行内编辑而不是浮出层，保留原有的取消按钮与 Escape 收起。
6. **无活动入口的残留样式**：`.eva-space-picker`（空间选择器菜单）在运行时没有任何标记生成，
   仅剩 CSS 与处理器；本次不为它登记失焦关闭，也未改动这段既有残留代码。

## 新增浮层时的做法

1. 判断它是否属于「临时浮出的操作表面」。是，则必须接入 `EvaPopupDismiss.watch`，
   不要新写 document 监听器。
2. `keep` 至少包含浮层本体与触发按钮；输入型浮层还要包含所属输入区（用户在其中继续输入不应被收起）。
3. 打开状态若可能与其它实例互换（列表行菜单、文件夹菜单等），提供 `token`。
4. 不要为了统一而改变浮层自身的开关状态归属、数据源或视觉样式。
5. 在 `tests/browser/popup-dismiss.mjs` 增加对应用例，并在本文件清单补一行。
