# 未读提示公共组件

数字徽标由公共呈现层统一管理。业务入口只提供数量、语义单位、是否静音以及位置；业务状态仍由各自的数据仓负责。项目的「未读任务」按任务去重，消息与 Agent 的未读按会话规则计算，不能为了视觉统一混成一个总数。

- 计数与原生 HTML：`prototype/009-3-unread-ui.js` 的 `window.EvaUnreadUI` 统一处理零值、`99+`、转义与可访问名称。React 用 `EvaUnreadBadge`，原生个人栏用 `badgeHTML`。
- 汇总层级：折叠时显示其中有未读的会话数；展开后由可见子会话显示数字，父级只提示未展示的未读会话，避免同一批未读在相邻层级重复出现。叶子会话显示未读消息数。
- 外观：`prototype/017-im-shell.css` 的 `[data-eva-unread]` 是唯一尺寸、字体、形状和颜色来源。未读提示统一为数字徽标。选中与静音状态也在这里定义。
- 页面 CSS 可以设置位置、间距、悬停时与操作按钮互换；不得重新定义徽标的背景、文字色、尺寸、字体或圆角。新增入口不应加容器名单才能显示正确样式。
- 项目内部的任务列表、详情、页签和切换菜单复用公共未读徽标；打开任务详情后，由任务数据仓清除该任务的未读状态。我的项目首页维持现行布局，本轮不提交首页未读任务区及项目行徽标。

新增未读入口时，先接入公共组件，再核对宽窄导航、选中、静音、暗色、零值和 `99+`。`tests/unread-component-contract.test.mjs` 随 `npm test` 运行，防止已接入的入口重新出现私有外观。视觉验收仍要检查实际计算样式，构建成功不能替代截图和交互检查。
