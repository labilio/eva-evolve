# 消息 · AI 发言显示开关 产品设计说明

## 1. 背景与问题

团队 IM（一级菜单「消息」的关注 / 最近）里，人在群聊中与 AI 会混排发言。当用户只想快速浏览**同事的回复**时，AI 的分身、数字员工、项目管家消息会形成噪音：

- 项目管家会主动同步进展并 @所有人，单次可能连续多条；
- 讨论中 AI 的确认、补充会打断人类对话的阅读节奏；
- 用户不想逐条跳过，也不想真的删除或屏蔽任何内容。

因此需要一个**只在阅读层生效、可随时还原**的显隐开关，而不是改变数据、权限或他人可见性。

## 2. 设计目标

| 目标 | 说明 |
| --- | --- |
| 快速降噪 | 一键只看人的发言，隐藏全部 AI 回复 |
| 可还原 | 再点一次立即恢复全部消息，不丢任何数据 |
| 认知成本低 | 图标语义来自已有的全局 AI 标，不引入新符号体系 |
| 状态可预期 | 每个会话独立记忆，刷新后仍保持；跨会话互不干扰 |
| 零副作用 | 不影响搜索、引用、中栏摘要、未读与权限 |

## 3. 范围边界

- **入口唯一**：仅出现在一级菜单「消息」的会话内容区顶栏。
- **不出现**：个人「Eva 同学」、我的 Agent（AI 小队 / 个人助理 / 数字员工面板）、项目 Space 内嵌会话、通讯录与任何复用 `ChannelsView` 的其他入口。
- **不做**：不新增设置项、不改变 `Ta` 数据、不删除消息、不修改他人可见性、不写入服务端。

## 4. 交互设计

### 4.1 位置

会话内容区顶栏右侧操作区，位于「进入项目」分隔线之后、「查找聊天内容（放大镜）」之前，即**放大镜左侧**。

```
[进入项目 × 项目名] | [AI 开关] [🔍 查找] [聊天任务] [子区] [⋯]
```

### 4.2 两种状态

| 状态 | 含义 | 图标 | Tooltip | `aria-pressed` |
| --- | --- | --- | --- | --- |
| 默认（开） | 展示 AI 发言，即全部消息 | 全局 AI 标（紫色小方标 `AI`） | 隐藏 AI 回复 | false |
| 禁用（关） | 不展示 AI 回复，仅人的回复 | AI 标 + 左下→右上禁用斜线 | 显示 AI 回复 | true |

说明：

- 使用**动作式文案**（点击后会发生的动作），而不是状态式描述，降低理解成本。
- 提示统一用 Semi Tooltip，不用浏览器原生 `title`，避免双份提示。
- 禁用态**不置灰**，保持 AI 标原有紫色，只用斜线表达「不再展示」，与「AI 身份」语义解耦。
- 点击切换时若处于多选态，先退出多选，避免选中项被隐藏后计数与视图不一致。

### 4.3 记忆粒度

按**当前会话**记忆：

- 群聊父群与每个子区各自独立（以运行时 `va` 为准）；
- 「A 群隐藏、B 群显示」互不影响；
- 本地持久化，刷新与重新进入后保持。

## 5. 状态与数据设计

### 5.1 唯一数据源

复用既有会话偏好存储 `evaMemberStore.chatPreferences(va, actorId)` / `setChatPreferences(...)`，新增字段 `hideAi`。

- 不新增第二份全局变量、DOM class 或 `window` 状态；
- 读取随 `evaMemberRevision`（`useSyncExternalStore`）驱动重渲染；
- 写入经 `setChatPreferences` 的字段白名单校验。

### 5.2 派生而非改写

`Ta`（`visibleMessages` 结果）保持**全量不变**，供搜索、引用与定位使用；仅在**消息流渲染处**派生「隐藏 AI 后」的数组：

```
evaHideAi = 开关可见 && chatPreferences(va, actorId).hideAi === true
evaStreamMessages = evaHideAi ? 过滤掉 AI 与多余分隔条后的 Ta : Ta
```

### 5.3 AI 判定口径

统一按身份标记，不按名称猜测：

```
sender.ai === true || sender.identityAppearance 存在
```

- `sender.ai`：项目管家、数字员工等；
- `identityAppearance`：AI 分身（clone）等仅带身份外观的 AI。

系统消息（入群提示、子区创建通知）与时间分隔条保留。

## 6. 过滤边界（用户明确决定）

| 面 | 是否受开关影响 | 原因 |
| --- | --- | --- |
| 消息流渲染 | ✅ 受影响 | 这是唯一目的 |
| 查找聊天内容（搜索面板、结果、定位） | ❌ 不受影响 | 搜索仍是全量数据；定位时把全量索引映射到过滤后索引 |
| 引用 / 回复块 | ❌ 不受影响 | 属于消息内容，不做二次裁剪 |
| 中栏列表摘要、未读、提及 | ❌ 不受影响 | 列表数据源与消息流分离，改动不波及导航态 |
| 数据本体、他人可见性、权限 | ❌ 不受影响 | 纯渲染层开关 |

分隔条处理：过滤后若出现相邻或孤立的时间分隔条，折叠多余项，避免出现只有时间、没有消息的空段。

## 7. 视觉与主题规范

- **AI 标**：直接调用全局 `window.EvaAIIdentity.badge`，不手写 SVG / Unicode；尺寸与圆角由公共样式决定，业务不覆盖比例。
- **默认态**：按钮无底色、无阴影（修复了 `<button>` 默认底色），仅 hover / 选中时显示顶栏统一的 `op:hover` 灰底。
- **禁用斜线**：水平线 `rotate(-45deg)` 得到左下→右上「/」方向；不使用阴影描边。
- **暗色**：斜线取次级文字语义色，沿用 `:root[data-theme="dark"]` 适配，不使用写死色值。
- 复用会话头顶栏既有 `.op` 几何（32×32、圆角 8），不新造控件形态。

## 8. 实现映射

| 关注点 | 位置 |
| --- | --- |
| 顶栏按钮、状态变量、消息流过滤、搜索定位映射 | `prototype/009-5-patch-im.js` |
| 会话偏好字段 `hideAi` 白名单 | `prototype/009-2-membership.js` |
| 按钮几何、默认无底色 / 无阴影、斜线 | `prototype/055-conversation-search.css` |
| 暗色斜线 | `prototype/057-gds-dark-tokens.css` |

架构一致性：

- 复用统一 IM 内核 `ChannelsView`，未复制消息区、未新增监听器；
- 一级导航选中态仍由路由推导，开关不触碰导航状态；
- 仅经 `window.__evaPatch` 注册补丁，构建产物唯一，锚点缺失即构建失败。

## 9. 验收清单

1. 「消息」打开含项目管家的群：AI 标默认显示，点按后 AI 回复消失、再点恢复。
2. 切换后不残留连续 / 孤立时间分隔条。
3. 同群与各子区分别记忆；A 群隐藏不影响 B 群；刷新后保持。
4. 关注 / 最近往返切换后状态与滚动不串。
5. 查找聊天内容结果条数不变，定位到人消息命中正确；引用块与中栏摘要未变。
6. 我的 Agent、项目 Space 内嵌会话、数字员工面板**无**此按钮。
7. 暗色模式下 AI 标与斜线对比度正常；默认态无底色、无阴影。
8. 全部图标按钮提示为 Semi Tooltip（进入项目、AI 开关、查找、聊天任务、子区、聊天信息）。

## 10. 明确不做（Non-goals）

- 不做“仅看某类 AI / 某人”的细粒度筛选；
- 不做“必须 @ 才回应”等 AI 行为设置（另有群聊规则，与此开关无关）;
- 不改变消息写入、以 hidden 隐藏、软删除或影响他人;
- 不把该开关扩展到我的 Agent 或项目 Space，除非后续单独评审。
