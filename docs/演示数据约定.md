# 演示数据约定

根据用户要求，今后所有需要预置内容和人员的功能，统一在现有 **供应链运营协同** 项目（协作项目 ID：`prod`；任务看板项目 ID：`p-supply`）中实现演示场景。本约定指导原型实施，不修改客户原始需求文档。

## 内容与人员

- 人类、分身、负责人、管理员及普通成员复用现有身份 ID；按场景补齐角色和关系，不重复创建同名人员。
- 成员直接添加及退出等流程需要初始状态时，在该项目下准备符合规则的演示关系，不预置待审批或待接受记录。
- 群聊采用“大群 → 可选子区”；全员群由项目成员派生，普通群和子区与项目保持明确关联。
- 消息、任务、文件、来源与共享版本围绕同一供应链场景组织，使评审者可以直接走通流程。
- 涉及助理、数字员工等能力时，可在该项目场景中展示其业务关联，但不得因此将其设为项目成员；成员身份规则仍以现行产品方案为准。

## 数据维护

| 数据 | 维护位置 |
| --- | --- |
| 项目、任务、人员及归属 | `prototype/009-2-data-supply.js` |
| 文件及云盘示例 | `prototype/009-1-data-drive.js` |
| 团队消息、AI 身份及会话示例 | `prototype/009-3-data-im.js` |

各模块通过稳定 ID 关联；预置初始数据与运行时状态控制器保持单一数据来源，不能在视图打开时拼出另一套项目或人员。已持久化的本地数据需要升级时，提供明确迁移或定向初始化方式，不静默清空用户演示操作。

预置数据必须遵守分身归属、成员添加、管理权限和文件可见范围。不得为了方便演示而让未加入的成员读取群历史。

## 验收与例外

新增功能的操作说明与 Edge 浏览器验收默认从“项目 → 供应链运营协同”开始，并准备必要的初始人员、内容和关系。评审者无需先创建另一个测试项目才能看到功能。

创建项目、跨项目转存或权限隔离等行为可使用临时项目验证；自动化单元测试仍可使用隔离夹具。这些数据不作为默认演示内容，也不向正常新建项目自动灌入供应链样例。

此前“成员流程验证”等临时项目仅代表历史测试记录；后续预置内容和正式演示路径均以“供应链运营协同”为准。

## 团队文件功能设计补充演示

用户明确指定在现有 `drive-design` 项目补充文件协作讨论与任务，作为默认置顶项目之一。本例外复用现有项目和人员，不新增默认项目。包含文件体验设计、文件功能开发、文件验收与反馈三个群及两个子区，关联 DRIVE-1 至 DRIVE-9 任务。已有成员数据采用一次性增量初始化，保留用户消息、编辑与删除；供应链仍是其他新功能的默认演示项目。

## EVA Official Space 用户交流演示

用户明确要求在现有 `official` 项目演示用户与开发团队使用 AI 解决反馈。新增“用户使用反馈与开发交流”群与三个子区，复用王宜林、林晓、何静、周远及王宜林的云端分身；先建立项目和群成员关系，再展示消息，不将用户示例身份复制成新账号。

- 上传失败：用户描述 → @王宜林的云端分身整理富文本排查步骤与 Markdown 文件 → 开发者确认 → @项目管理专员登记 EVA-101。
- 分享权限：用户提问 → @王宜林的云端分身说明权限边界并提供 CSV 验收矩阵 → EVA-102 复核任务。
- 会议行动项：用户提问 → @王宜林的云端分身提供 Markdown 模板 → 人工确认 → EVA-103 文档改进任务。

任务在 `009-2` 维护，消息在 `009-3` 维护，真实示例文件及下载映射在 `009-1` 维护。演示任务卡引用实际 Official 任务 ID；状态仅代表预置场景，不宣称真实 AI 执行或产品修复已上线。普通 AI 的回复与文件均承接明确 @ 请求。

成员及消息采用一次性增量初始化，不覆盖已有群消息，不在用户删除示例群后重新创建。默认置顶全部四个预置项目，Official 演示可从关注或项目目录进入。

## 预置项目任务阶段覆盖

用户要求四个现有预置项目均具备完整任务阶段。供应链运营协同 12 项（8 项顶层任务与 4 项多层子任务）、团队文件功能设计 9 项、Official 5 项、客户联合交付 5 项，均覆盖 todo、in_progress、in_review、done。2026-09-14 待规划合并为待办，原 backlog 任务保留并迁移到 todo；除供应链项目按子任务设计新增的 4 项演示任务外，其余项目任务总数不变。任务内容贴合各项目，ID、编号和 workspace_id 隔离。新建空项目不自动填充演示任务。专项检查为 `tests/demo-project-task-stages.test.mjs`。

## 各项目自动化场景

2026-09-08 用户明确要求为全部现有项目补充自动化及历史 Mock 数据，作为供应链默认约定的本次例外。prod、drive-design、official、lab 各新增三条贴合业务的自动化、每条两次运行记录；保留团队文件原有两条自动化。运行记录包含成功摘要或失败原因，可打开同项目关联任务。页面明确标注演示数据，不接入调度、不执行外部调用、不自动向群发消息。按用户要求，本次不运行测试或浏览器验收，仅构建后供用户本地测试。
