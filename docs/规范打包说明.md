# Eva 产品规范打包

## 分发形式

分发一个 `eva-product-rules` 技能包。它也是普通 Markdown 文档包：不用 Codex 的研发可直接阅读 `references/index.md`，Codex 根据 SKILL.md 按任务选择规范。

```text
eva-product-rules/
├── SKILL.md
├── agents/openai.yaml
├── references/
│   ├── index.md
│   ├── common/      四份通用：图标、身份展示、布局、配色
│   └── menus/       六份专项：Eva 同学、我的 AI、消息、项目、通讯录、数字员工市场
└── sources.json     来源文件与内容摘要，用于核对更新
```

包内不带待确认条目、文件库待审方案、旧规范全文、原型源码、AGENTS、构建发布纪律、演示数据或本机路径。未收录的业务不代表被禁止，也不代表已经授权。

## 唯一维护来源

- 产品正文维护在 [通用规范与专项目录](./开发规范总览.md)。目录含内部工作状态；导出时只保留已定规则。
- 技能入口与展示信息维护在 `tools/product-rules-skill/`。
- 打包清单、链接重写与排除规则维护在 `tools/package-product-rules.mjs`。
- 不手工修改包内 references 或本机安装副本；重新打包生成，避免多份正文各自变化。

## 生成与验证

在仓库根目录运行：

```bash
node tools/package-product-rules.mjs
```

输出 ZIP 位于 `artifacts/product-rules/`。脚本仅按明确清单打包，重写包内链接，拒绝断链、本机路径及未清理的待确认内容；同时解压核对实际归档字节。JSON 输出包含临时验证目录和 ZIP 摘要。

使用 skill-creator 的 `scripts/quick_validate.py` 对输出的验证目录检查技能格式。格式检查不等于产品实现或完整业务验收。

## 交给技术同学

直接发送 ZIP。普通阅读从 `references/index.md` 开始；Codex 用户将 ZIP 内完整的 `eva-product-rules` 文件夹放到自己配置的技能目录（通常为 `~/.codex/skills/`），保持目录结构，然后使用 `$eva-product-rules`。

发送 ZIP 不等于已安装；只复制 SKILL.md 也不够，references 必须一起保留。首次使用可把下面的话连同包一起交给同事的 Codex：

> 请解压这个 Eva 产品规范包，读取 eva-product-rules/SKILL.md，并按其中的相对路径读取相关 references。先列出本次开发实际参考的规范，再按这些规则完成任务。若尚未安装为技能，本次直接从解压目录读取。

安装后可用以下请求检查是否找到规则：

> 使用 $eva-product-rules，说明我的消息中项目、大群、子区的关系，以及关注和最近在范围、排序、归属展示上的区别。列出实际读取的规范文件。

应能定位到 `references/menus/messages.md`；涉及成员资格继续读取 `projects.md`，涉及头像或附属面板读取 common 中的身份与布局规范。无需打开原型仓库的历史文档。

本包不依赖原型仓库和外部连接器。新规则确认后修改源文档并重新打包；通过 sources.json 中的摘要判断内容变化，不用历史测试结果推定当前版本。
