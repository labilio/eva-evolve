# 转发面板规范（2026-09-20 用户确认版）

适用范围：消息页右键「转发／合并转发」打开的转发目标面板 `.eva-fp-modal`。
实现位置：`prototype/009-5-patch-im.js`（`EvaForwardMessagesDialog`）、`prototype/061-forward-picker.css`；
「创建群聊并发送」复用 `prototype/009-2-members-ui.js` 的 `CreateGroup`。

## 信息结构

- 取消原先的「最近／我的 Agent／项目／联系人」四 Tab 与竖分隔线，不保留任何 Tab 残留。
- 未输入查询时只显示一个分组「最近」，且不显示分组标题以外的任何分组；左栏是唯一列表。
- 输入查询后才出现分组，顺序固定为：**关注 → 联系人 → 我的 AI → 群聊与子区**（无内容的分组不渲染）。
  - 「关注」与消息页「关注」完全同源（同一 `conversationFollowed` 数据），组内沿用关注列表排序。
  - 「我的 AI」按公共身份体系列出本人可转发的分身、本地助理与数字员工；AI 身份名称旁使用公共 AI 标。
  - 「群聊与子区」列出群与子区，子区行显示「项目 / 父群」上下文。
- 「最近」必须包含：大群、人类私聊，以及**全部 AI 单聊**（分身、本地助理、数字员工的身份行与其会话、AI 团队群）。
  AI 单聊在消息页会被过滤，转发目录自行并入同一份最近列表。

## 目标选择

- 左栏默认只列大群，**不列子区**；子区一律通过右侧群卡片的「发送至」下拉多选。
- 群卡片是「身份行 + 按需展开的发送至」：默认只勾选本群（`self`，选项与摘要文案均为「本群」），卡片只占一行；
  点轻量展开按钮 `.eva-fp-row-toggle` 才显示下拉，无子区的群不塞占位数据。
  当选择结果不是「仅本群」时强制显示该行，避免选择结果被隐藏。
- 下拉选项 = 本群 + 该群全部活跃子区 + 底部「新建子区」。
  子区选项在名称前带全站统一的子区图标（Lucide `corner-down-right`，与中栏「子区」同源），「本群」不加图标；
  图标只作层级标记、随语义 token 着色，不新增颜色或尺寸变体。
- 搜索命中子区时，右栏父群卡片自动展开并预勾该子区（仍可再改选本群）。
- 搜索覆盖全部群的子区，包括消息数据源里的演示群。

## 新建子区

- 群卡片下拉底部提供「新建子区」，就地展开命名输入行（Enter 确定、Esc 取消、另有确定／取消按钮）。
- 创建即真实落库，与群内「新建子区」使用同一合同：项目群走成员库 `store.createThread`，
  AI 团队群走 `window.EvaMyAITeamGroup.createThread`；名称上限分别为 30／100 字符。
- 新建成功后自动勾选并计入已选数量；取消整个转发面板不回收已建的子区。
- 演示数据里不存在于成员库的群沿用群内入口的同一限制，不额外造数据或放宽校验。

## 创建群聊

- 搜索框右侧常显「新建群聊」入口：图标 + 文字的**低频三级按钮**（透明底、无边框、次级文字色，悬停才有浅底），
  与搜索框同行等高（32px，间距 8px），不得填主色、加边框或挤压搜索框主位。
- 复用既有新建群聊页面（成员选择器模板 A），弹窗标题为「创建群聊并发送」，页脚按钮为「创建并发送」。
- 新建群**不归属项目**；创建成功后不关闭转发面板，新群自动加入右栏并默认勾选本群。
  其他入口（群聊管理、项目建群）沿用默认标题「新建群聊」与按钮「创建群聊」。
- 该弹窗层叠在转发面板之上（`.eva-forward-host` 的 `z-index` 高于 Semi 默认 1000，故弹窗通过 `zIndex` 抬高）。

## 保持不变的既有行为

- 底部预览（文本／合并记录／文件）、留言、发送链路与多选规则。
- 点面板内容区空白、点遮罩、Escape 分层（先关「创建群聊并发送」弹窗或「发送至」下拉／命名行，再关面板）与关闭按钮。
- 灰色蒙版范围、系统标题栏不被遮挡、头像／AI 标／项目色的公共合同。
- 输入提示继续由 Octo `ChatComposer.buildPlaceholder` 统一生成，不由本面板另写文案。

