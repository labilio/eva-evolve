# 通讯录身份卡

身份卡沿用 Octo-Web ProfileDetailShell 的头像、信息区及操作区结构，通过 Semi Modal 和 Eva 公共身份组件适配。通讯录每位真人及所属分身优先横排在同一行，部门为同行次级信息，短竖线区分真人和分身。搜索、人类与 AI 的独立资料入口继续保留。

| 身份 | 信息与操作 |
| --- | --- |
| 人类 | 头像、姓名；其他人可发消息，自己不提供给自己发消息 |
| 云端分身 | AI 标、类型、简介（有数据才展示）、可点击的所属人；所属人可在同一弹窗查看并返回 |
| 本人的已有云端分身 | 进入现有我的 AI 会话 |
| 其他人的分身 | 展示群中 @ 协作说明，不因查看资料授予私人对话权限 |
| 数字员工 | 职责、公共／个人／项目归属；已添加到我的 AI 且当前账号可用时进入已有会话；不虚构个人主人 |
| Eva 项目管理专员 | 职责、当前可访问的服务项目、进入项目；无私聊操作 |

不增加部门、岗位、Octo 号、备注、好友关系、在线状态推测。公共头像比例和 AI 标保持既有合同。群成员与项目成员仍保留原有管理入口；查看资料不重建消息流或输入框。

## 数据与状态

- `009-3-contact-identities.js` 按稳定 ID 投影身份和允许的操作，不依据显示名称猜测身份。
- `009-3-identity-card.js` 提供各入口共用的卡片和头像适配。卡片负责所属人返回状态；路由负责跳转。
- 通讯录使用原生 React Route，原 DOM 注册桥已移除。
- 人类私聊的会话索引、消息和按账号隔离的草稿存放在成员业务 store，按双方账号 ID 复用会话。切换演示账号会重置内部会话组件；不合并上一个账号的临时私聊缓存。
- 弹窗使用标题栏下方的专用 Portal 宿主，宿主持续挂载，关闭时卸载 Modal。无需修改路由调度或操作 DOM 绕过 React。

## 2026-09-08 紧凑横排（现行）

用户明确否定姓名、部门、数量、分身四层纵排：一行能展示的信息必须横排，以提高浏览效率。此决定覆盖前述纵向主从方案。

每行约 65px：真人头像＋姓名＋次级部门，接短竖线与紧凑排列的分身。删除独立分身数量标题及纵向缩进；分身按内容宽度排列，不拉伸成稀疏等宽列。空间不足才在分身区域内换行。多分身仍支持超过 6 个原组内展开／收起，数量体现在展开入口，完整数量保留在组的无障碍名称中。搜索、资料卡、头像和 AI 标合同继续有效。

Edge 1200×800 验证 1／2／3 个分身与真人在同一行、行高不超过 66px；900×800 验证多分身按需换行、12 个分身展开收起、搜索折叠命中项、资料卡与路由往返。截图沿用本地 `artifacts/clone-owner/contacts-redesign.png`。

## 2026-09-09 单分身与窗口自适应（现行）

本节覆盖此前所有多分身数量、展开和折叠规则。每人零个或一个分身；显示「xxx的 AI 分身」及既有 Eva Logo，名称和头像不可修改。沿用「联系人 / TA 的 AI 分身」两列表头、独立资料卡和搜索；无分身显示「未创建」，移除「共 x 个」和多分身控件。具体身份规则见《分身主人展示规则》。

- 根据通讯录内容容器宽度适配，不根据显示器物理分辨率或 DOM 状态分支。
- 两列使用 2:3 弹性比例，取消 1040px 列表上限和 220px 分身项上限；宽屏不放大头像、字号或行高。
- 内容宽度小于 1000px，左右内边距缩至现有 16px token。
- 内容宽度小于 640px，搜索框置于标题下一行，部门移至真人姓名下方；仍保持左右身份对应，不出现横向页面滚动。
- 文字过长截断并保留完整 title，AI 标不可收缩。列表独立纵向滚动，表头吸顶；系统标题栏保持唯一可见。
- 搜索和资料卡状态仍由通讯录 React 组件持有，切换账号时重置。布局直接由 CSS 容器查询推导，无新增 UI 状态或监听器。
