# 通讯录身份卡

身份卡沿用 Octo-Web ProfileDetailShell 的头像、信息区及操作区结构，通过 Semi Modal 和 Eva 公共身份组件适配。通讯录每位真人及所属分身优先横排在同一行，部门为同行次级信息，短竖线区分真人和分身。搜索、联系人与 AI 的独立资料入口继续保留。

| 身份 | 信息与操作 |
| --- | --- |
| 联系人 | 头像、姓名、类型「联系人」、部门；其他人可发消息，自己不提供给自己发消息；本人可更换头像 |
| 云端分身 | AI 标、类型、简介（有数据才展示）、可点击的所属人；所属人可在同一弹窗查看并返回 |
| 本人的已有云端分身 | 进入现有我的 AI 会话；主人可更换头像 |
| 其他人的分身 | 展示群中 @ 协作说明，不因查看资料授予私人对话权限 |
| 数字员工 | 职责、公共／个人／项目归属；已添加到我的 AI 且当前账号可用时进入已有会话；不虚构个人主人 |

不增加 Octo 号、备注、好友关系、在线状态推测；联系人的「部门」按正式版「集团/中心/中台/组」全路径展示，沿用企业微信名片的信息层级：**最末级组织做大字主值、上层链路做小字灰字副行并完整换行**，不截断、不用省略号、不挂悬停提示，多少层级都放得下；不拆成部门、岗位两行。公共头像比例和 AI 标保持既有合同。群成员与项目成员仍保留原有管理入口；查看资料不重建消息流或输入框。

## 数据与状态

- `009-3-contact-identities.js` 按稳定 ID 投影身份和允许的操作，不依据显示名称猜测身份。
- `009-3-identity-card.js` 提供各入口共用的卡片和头像适配。卡片负责所属人返回状态；路由负责跳转。
- 通讯录使用原生 React Route，原 DOM 注册桥已移除。
- 联系人私聊的会话索引、消息和按账号隔离的草稿存放在成员业务 store，按双方账号 ID 复用会话。切换演示账号会重置内部会话组件；不合并上一个账号的临时私聊缓存。
- 弹窗使用标题栏下方的专用 Portal 宿主，宿主持续挂载，关闭时卸载 Modal。无需修改路由调度或操作 DOM 绕过 React。

## 2026-09-20 身份头像可更换

用户要求人类本人、分身主人和个人助理主人可以更换头像，入口是身份资料卡；数字员工不参与。本轮只开放头像，姓名仍不可编辑。该决定覆盖下方资料卡「不增加资料编辑」的旧表述，仅限头像。

- 卡片头像提供「更换头像」入口：常态只显示头像本身（不因弹窗自动聚焦而显示），鼠标悬停或键盘聚焦时整个圆形头像浮出半透明灰色蒙版与居中相机。本人、分身与个人助理的资料卡点击头像选图后都进入同一个圆形裁切编辑器确认（见下条），保存后回到身份页。不提供预设头像。
- 统一圆形裁切编辑器（本人／分身／个人助理资料卡、侧栏底部账号菜单「更换头像」与群头像共用同一实现与数据源），为单一头部结构：头部居中标题「更换头像」（右上关闭按钮是唯一关闭控件）；中部 112 px 圆形舞台。账号菜单入口常态悬停/聚焦时浮出相机与「点击更换」，提示「点击头像上传图片，不超过 5 MB」，点击选择文件后进入圆形裁剪；资料卡与群头像入口选图后直接进入圆形裁剪（群头像由弹窗标题「群头像」承担标题，编辑器不再渲染自己的头部）。圆形裁剪含画布 + 缩放滑块，可缩放、拖拽，导出 512×512 PNG；裁剪页页脚提供「取消 / 保存」：账号菜单入口点保存写回并关闭资料卡，资料卡入口点保存写回并回到资料卡、群头像入口点保存写回群设置，取消放弃本次裁剪。常态无页脚、无「恢复默认」；不再渲染第二个关闭控件、返回按钮、第二个标题、重复说明或独立的「返回资料」页脚。
- 本人头像另在侧栏底部账号菜单提供「更换头像」入口，点击直接打开该编辑器（`startAvatarEditing`），不复制编辑器或数据源、不改资料卡权限；分身与个人助理从各自身份资料卡点击头像进入同一圆形裁切编辑器。账号菜单保留「设置」「退出登录」。资料卡 Portal 宿主固定挂到 `document.body`，从侧栏打开时不会被内容区层叠遮挡。
- 头像仍是各身份的单一数据源：人类写成员档案 `avatar`，分身在主人档案下写分身记录 `avatar`，个人助理写 `EvaAITeam` 的 `configuration.avatar`；全部经 `EvaAIIdentity.avatar` 渲染，通讯录、资料卡、会话消息、我的 AI 身份行同步刷新。分身与个人助理的主图与主人头像相互独立：未自定义时均为单张圆形 Eva Logo，主人更换头像不再带动分身或助理；历史数据把 Logo 存为自定义主图时按未自定义处理，仍渲染默认 Eva Logo。
